# 内容变更与治理标准

本标准把“简单功能保持简单，高风险边界必须可追溯”作为默认原则。

## 权限

- `/me/*` 路由只允许当前会话用户访问自己的资源；前端传入的 `user_id` 不能改变主体。
- 管理端使用明确的 `OWN` / `ALL` capability。资源所有权以直接拥有的父资源为准（例如置顶评论的权限归卡片所有者）。
- 共享分类数据（标签、主题）不能因为一个用户的删除操作影响其他用户的公开内容；存在跨用户引用时返回冲突，由管理员执行受控治理。

## 可见性与计数

- 公共子资源读取必须先校验父资源仍然公开、未删除、未受限。
- 审核中的内容不得进入公开列表或公开计数；只有审核通过才增加计数。
- 删除、隐藏、恢复等状态变更必须与计数和派生关系在同一事务内更新，或进入明确的修复队列。

## 审计与通知

- 普通编辑、置顶、取消置顶采用结构化静默审计，不强制填写自然语言理由。
- 审核、封禁、权限、凭据和批量破坏性操作必须保留操作者、目标、前后状态和受控理由码。
- 通知由服务端领域事件触发；客户端不得伪造系统通知、解析提及或自行拼接通知分页。

## 迁移

- 迁移必须可重复、可分批、可观测。失败状态由调度器停止，重试需要显式运维动作。
- Contract/删除旧字段必须经过兼容窗口和回滚验证；未经批准不得直接删除旧表或旧列。
