# 管理端原生组件统一记录

## 目标与边界

以现有 Vuetify 为基准统一同类组件，不新增 UI 库、不改变品牌、导航分类、业务 API、权限规则或站点配置值。此次重点是资源列表、配置表单、配置对象卡片，以及工作台和运行状态页的常驻容器。

## 已落地规则

| 类型 | 统一实现 |
| --- | --- |
| 常驻卡片 | 原生 `flat + border`，白底、轻描边、默认圆角；不叠加可见阴影 |
| 菜单与对话框 | 原生 `elevated`，不继承常驻卡片的边框 |
| 配置字段 | `outlined / comfortable`，保留校验、说明、密钥保护和未保存提示 |
| 列表查询 | 同一工具区放搜索、辅助动作和“视图设置”；筛选控件使用 `compact` |
| 批量操作 | 选中后才显示，包含数量、动作选择、应用和取消选择；权限仍由原 guard 校验 |
| 视图设置 | 单一菜单包含已保存视图、保存、列选择和恢复默认；保留管理员隔离与完整恢复逻辑 |
| 配置目录 | 渠道、驱动、主题使用一致的标题／说明／底部动作结构；状态用标签表达，不给整张卡片染色 |
| 窄屏表格 | 数据区域允许横向滚动，页面不溢出；空态提示和动作保持在可见宽度内 |

默认值位于 `apps/admin/nuxt.config.ts`，列表结构由 `AdminResourceTableShell` 和 `AdminTableViewControls` 维护，配置分区复用 `AdminConfigSection`。没有为每种业务卡片新增包装组件。

## 修正的具体问题

- 标签、卡片、评论、用户、角色、权限目录和文件列表不再各自排布一套搜索与批量工具栏。
- 创建角色和处理过期上传不再依赖先选中一行；只调整入口位置，不自动执行操作。
- 存储与验证目录取消“外层边框再套内层卡片”，基础设置表单保留一层内容卡片。
- 消息、存储、验证、主题卡片不再混用整卡 tonal、border、flat 和不同动作尺寸。
- 移除页头／配置动作上的统一强制高度，回到原生按钮尺寸。
- 分页已有“每页行数”标签，选项只保留数值，避免重复“/页”导致原生选择框截断。
- 隔离 E2E 使用独立临时 Nuxt 生成目录，不抢占用户正在使用的实时开发服务锁。

- `npm run check` 通过；Vue 页面与共享组件模板解析无错误。
- `npm run build:admin` 通过。Windows 沙箱下依赖追踪遇到目录链接权限限制，授权后使用同一构建命令完成验证，没有部署。
- 桌面 1440px、窄屏 390px 实屏检查已覆盖列表、存储目录、运行状态及保存视图弹窗。
- 管理端角色／路由／无障碍／组件回归首次运行 88 项，83 项通过；4 项组件测试受样式热更新和零尺寸阴影断言影响，1 项角色导航测试被开发重载中断。
- 最终独立重跑 21 项全部通过：登录准备、9 类页面 × 2 个宽度、保存视图恢复与浮层外观、社区运营权限导航。首次失败用例全部包含在最终重跑中；最终代码没有未解决的测试失败。
- 已核实实时前端 3000 和 PHP 后端 6001 返回 HTTP 200；E2E 只使用 3100／6101 与一次性数据库，运行结束自动清理。

既有业务数据、站点配置、密钥和后台服务均保持原状。详情诊断等特殊内容仍保留自己的信息结构，未将所有页面强行改造成卡片网格。
