## 迁移提交

1. 增加特征测试，不改行为。
2. 提取稳定契约或上下文对象。
3. 迁移一个完整用例及其调用者。
4. 删除旧实现和临时适配。
5. 更新架构检查与文档。

## 完成检查

- [ ] 原行为验证通过
- [ ] 无新反向依赖
- [ ] 无双轨实现
- [ ] Controller 未直接访问 Model
- [ ] Application 未读取 Request 或引用 Infrastructure
- [ ] Service 所需身份和能力由调用者显式传入
- [ ] 公开路由未假设 `AuthContext` 必然存在
- [ ] 错误与日志语义一致
- [ ] 自动检查覆盖新边界
- [ ] 回退路径明确

## 交给普通业务 Agent 时

任务描述必须给出以下信息，不能只写“参考现有模块”：

1. 一个明确的 Route/API 入口和预期响应。
2. 允许修改的文件或目录，以及不可改变的公共契约。
3. 需要复用的 Application 用例、Port 或 `AuthContext` 字段。
4. 至少一条行为测试和一条真实请求验收方式。
5. 必须执行的根检查与模块检查。

Auth 是后端第一个完成的样板。业务 Agent 应复制它的依赖方向和验证方式，而不是复制
Auth 的目录名称或把非认证业务放入 `application/Auth`。
