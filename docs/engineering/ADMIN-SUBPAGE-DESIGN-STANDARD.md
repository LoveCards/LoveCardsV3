# 管理端子页面与子任务设计规范

> 状态：2026-11-21 按单记录与入口来源补充 A 类基线；本规范覆盖管理端的次级页面和子任务表面，现有页面尚未逐项迁移。
>
> 适用范围：`apps/admin/pages/apps` 中从管理页进入的详情、配置、专题和分区视图，以及由这些页面发起的创建、编辑、测试、确认弹窗。规范路由与中文名称仍以 [导航规范](ADMIN-NAVIGATION-CONVENTION-2026-11-07.md) 为准；一级页面骨架以 [布局规范](ADMIN-LAYOUT-SYSTEM.md) 为准；表格内部以 [表格交互规范](ADMIN-TABLE-INTERACTION-STANDARD.md) 为准；资源详情字段和编辑细节以 [详情与编辑规范](ADMIN-DETAIL-EDIT-DESIGN-STANDARD.md) 为准；颜色和组件外观以 [UI 风格锁定](ADMIN-UI-STYLE-LOCK.md) 为准。

## 1. 什么是子页面

子页面是从一个已确定的管理任务继续深入的**次级任务表面**，不由 URL 层级单独决定。它可以是可分享的独立路由、父页中的标签视图、资源详情弹窗，或单次创建／测试／确认弹窗。资源记录先按入口来源选择独立页或弹窗；其他子任务再按稳定地址、完整上下文和独立阅读需要选择容器。不因表单较长就复制一张独立页。

| 类型 | 适用任务 | 容器与行为 | 不适用的做法 |
| --- | --- | --- | --- |
| A 单记录详情／编辑 | 非主列表引用与直达；主列表行内编辑、处理或必要只读查看 | 独立页是记录的稳定管理地址且可授权编辑；主列表弹窗直接进入同一详情主体的编辑／处理范围 | 页面和弹窗各做一套表单；整张 Nuxt page 嵌弹窗；把记录页做成无关数据总览 |
| B 对象配置 | 主题、发送渠道、存储渠道、验证驱动等可直接访问的配置 | 独立 960px 配置页，说明当前对象与生效范围，按保存范围组织字段 | 在列表弹窗堆完整配置页；用多层卡片包围动态字段 |
| C 专题／安全任务 | 用户 Session、升级、通信或事件诊断等需要完整上下文的用例 | 独立页或所属父页专题区；状态先于命令，操作与诊断分开 | 把高风险流程塞进窄弹窗，或把命令伪装成普通字段保存 |
| D 父页内分区 | 同一对象的策略、驱动目录、事件视图、文件视图 | `v-tabs` 或明确分区，沿用父页标题与容器，不为每个 Tab 再造页头 | 仅为视觉分组创建新路由；重复标题、刷新和保存区 |
| E 短任务弹窗 | 创建、测试、上传、危险确认、筛选和视图设置 | 一次只处理一个明确任务，标题、说明、正文、单组动作 | 用确认弹窗承载完整详情；叠两层可操作弹窗 |

**容器选择顺序：** 先判定入口来源：对象所属主列表的编辑／处理保持列表上下文并用弹窗；非主列表的对象引用、书签和跨模块跳转进入独立路由。其余同一页面内相互关联的视图使用 Tab；仅确认或短输入使用小弹窗。用户从独立页与列表弹窗看到同一资源事实与权限结果。URL、返回和未保存保护依旧遵守当前路由与表格规范。

## 2. 所有子页面共用的视觉骨架

```text
独立路由：面包屑 → 唯一页面标题／用途 → 对象身份或当前状态
          → 本页主要任务 → 关联信息 → 历史／诊断

父页 Tab：父页标题／用途 → 一排真实视图 Tab → 当前 Tab 的主要任务
           → 当前 Tab 的局部反馈／诊断（不重复父页标题）

短任务弹窗：任务标题／关闭 → 必需说明与输入 → 错误反馈
              → 取消／唯一主动作
```

- **一个任务一个视觉重心。** 首屏把对象、当前状态和主要任务放在一起；技术标识、旧结果、扩展选项与诊断放后部。普通区块用标题、留白和细分隔线组织；同一任务内容范围只有一层主表面，不出现“页面卡片 → 分区卡片 → 字段卡片”的套娃。
- **保留既有尺度。** 资源详情和专题页沿用 1040px，配置页沿用 960px，列表仍是流式容器；统一 24px 主区块间距、16px 常规区块内间距。弹窗尺寸按任务复杂度取现有详情规范的档位；短确认和测试弹窗按内容取紧凑宽度，不能为了统一变成 1040px。
- **标题和文案按职责分层。** 独立页只有一个 `h1`；Tab 面板和弹窗主体不再造同级大标题。区块标题说明“这组内容是什么”，帮助文本说明影响或约束；不靠连续 `v-alert` 解释正常流程。普通值、可点链接、按钮和命令在外观上可辨。
- **字段和操作各有位置。** 只读事实平面展示，授权字段才变成输入控件；一个保存范围只有一个主提交区。刷新属于正在查看的数据范围；创建、上传和测试是任务动作；审核、封禁、撤销和恢复是受状态与 capability 约束的命令，必须有真实 SDK/API 对应。
- **保持双主题和窄屏一致。** 使用 Vuetify 主题 token，不写页面专有白底／深底；暗色与浅色的顺序、密度和动作层级相同。桌面 1440／960px、窄屏 600／390px 和 200% 缩放均需核对滚动、标题、字段、保存与焦点，不因窄屏换成另一套业务流程。

## 3. 五类页面的具体基线

### A. 资源详情与编辑

10 类资源的单记录边界、字段顺序、单一内容表面、原位编辑、独立保存范围、三档弹窗宽度和逐资源验收，以[详情与编辑规范](ADMIN-DETAIL-EDIT-DESIGN-STANDARD.md)为准。只读权限、审计和处理任务的必要“查看”仍保留；可编辑主列表行不额外制造无用的“查看”。非主列表引用进入目标记录的独立页并可按权限编辑，不把本列表身份字段做成大按钮。

### B. 对象配置子页

适用于主题参数、站外发送渠道、存储渠道、验证驱动，以及同类可直达配置。页头给对象的可读名称、所属目录和当前状态，次行以一句话说明影响范围；内部按“主要参数 → 安全／密钥 → 测试或依赖 → 高级诊断”排序。动态 schema 字段由服务端契约决定，不为对齐视觉重排有依赖关系的字段或改动提交语义。常用短字段桌面两列，长说明、地址、密钥帮助和测试结果独占一行；窄屏单列。Secret 保持既有受控读写规则，留空／遮罩语义就近说明。

配置子页的审查样板：

```text
站外发送 / 邮件渠道                       [已启用]
管理发送渠道参数；测试使用已保存配置。
────────────────────────────────────────────
渠道参数
名称                 发件地址
[输入]               [输入]
连接安全
服务器地址           密钥（受控遮罩）
[输入]               [保留现值 / 重新设置]
────────────────────────────────────────────
测试与结果（独立任务）          [测试发信]
配置保存范围                    [保存渠道配置]
```

`AdminConfigSection` 和 `AdminConfigSaveBar` 仍是配置页的共享边界：一个保存范围一个保存区，页头不重复保存；只读时不留空动作区。测试只读取已保存配置时，测试入口与脏状态说明必须一致。失败靠近对应字段／测试区，保存成功后以服务端结果更新当前状态。站点、Redis 和策略等非动态配置页也遵守此节的表面、字段、保存与反馈规则；具体页面骨架仍以布局规范的配置页章节为准。

### C. 专题、安全与运维子任务

用户账号安全页先显示账号身份、保护状态与有效 Session，再呈现撤销入口和会话表；批量撤销与单条撤销按各自影响确认，不因统一按钮外观弱化 root／高权限目标保护。升级页先显示当前版本和升级计划状态，再给上传、继续、批准收缩或恢复的真实命令；每一步的等待、失败和恢复记录须可辨。事件管理、通信与运行诊断先显示当前状态／时间范围，再展示能力、队列、依赖或错误；无需编辑的诊断区不出现保存栏。专题内的小表仍遵守表格规范，不能为“详情感”改成卡片堆叠。账号安全等专题的审查样板是“身份与保护状态 → 当前可处理对象 → 命令 → 历史／诊断”；命令可以紧贴当前对象，但确认层必须说明作用范围，不能把受保护对象显示成可执行。

### D. 父页中的分区视图

站点策略、事件管理、存储／验证目录、文件视图等已经使用 Tab 的页面，父页负责唯一标题、面包屑与总任务；Tab 只表示**同一父任务下的真实视图或保存范围**，不用作装饰性分类。Tab 标题短且可预期，选中态按主题 token，内容从同一左边界开始；切换后刷新、结果、空态和错误只针对当前视图。含草稿的 Tab 切换必须遵守未保存决策。多个独立保存范围各自标明对象和脏状态，不让一个全局按钮暗示可以保存全部。内容过多但不构成独立任务时可用 `v-expansion-panels` 收起高级诊断；外部引用所需的内容必须有稳定路由，不能仅藏在无 URL 的 Tab 中。

### E. 创建、测试、确认和工具弹窗

创建标签／角色等短表单以“对象类型 + 创建”为标题，必要字段在前，错误就近，底部仅“取消／创建”。测试发信、存储或验证的弹窗明确使用已保存还是草稿配置，结果留在当前任务内；上传升级包明确文件要求和即时副作用。危险确认只负责对象、动作、影响和确认，不承载可编辑详情；危险色只用于确认阶段。筛选与视图设置是列表工具弹窗，其输入草稿、应用／取消与 URL 规则仍按表格规范执行。密钥显隐及未保存离开确认使用现有共享组件，不再出现逐页自制的警告对话框。

## 5. 实施和人工审查门槛

迁移按垂直切片进行：先固定一个页面的旧入口、数据、权限、保存与失败样例，再同时处理其独立页、嵌入视图或弹窗；验收后移除旧双轨。先用卡片与用户验证 A，用一个发送／存储驱动验证 B，用账号安全验证 C，再推广到同类页面；D、E 仅在实际父页和弹窗中收束，不新建通用业务引擎。保留原 SDK、状态机、通知和审计边界。

人工审查必须同时看：页面与弹窗的任务层级是否一致；第一屏能否识别对象和当前任务；是否只有一层主要表面；可读字段、关联链接、普通按钮与危险命令是否可区分；保存范围与取消副作用是否准确；加载／空态／错误是否真实；暗色、窄屏、缩放、焦点、滚动与脏状态是否可用。代码检查按 `AGENTS.md` 执行；截图人工审查不能由构建代替。未检查的子页面不得标记为完成迁移。

## 6. 迁移进度与审查记录（2026-11-19）

- A 类：10 类资源的独立详情与列表弹窗共用详情主体；本轮统一事实字段、分区边界、弹窗宽度与关闭入口。卡片、评论、用户、标签、角色、文件、举报、权限、审计和处理任务均已纳入代码审查；原有权限、命令和保存流程保留。
- B 类：站点访问和内容规则的配置区连接为单一表面；四个动态配置子页移除保存栏前的重复分隔线。保存范围、密钥语义和测试只读已保存配置的约束保持不变。
- C–E 类：账号安全事实区、事件状态 Tab、站点策略 Tab、角色与标签创建、测试发信及升级上传的标题、说明和动作层级已收束；专题命令、URL 与未保存状态仍按各自用例处理。
- 自动验证：`npm run build:admin` 通过；管理端只读模拟 API 的卡片／评论 11 项回归通过，配置／详情 28 项中 27 项首次通过，审计空态断言改为检查主内容后单项通过。`npm run check` 受云端 PHP 8.5 弃用提示和缺少 `mime_content_type()` 影响，后端基线失败。
- 人工审查仍须核对浅色／暗色、桌面／窄屏、200% 缩放、编辑态、弹窗滚动与焦点；自动构建和模拟 API 回归不替代视觉签收。

## 8. 单记录双形态全量复审与施工方案（2026-11-22）

本节是第 4 节覆盖账本的执行记录，不另建页面类型或第二份视觉规范。审查范围为 `apps/admin/pages/apps` 的 66 个路由文件、与其相连的详情主体及 Dialog。37 个实际页面中，10 个资源列表对应 10 个 A 类单记录详情；其余 17 个实际页面属于 B–D 或父页。29 个旧路由只验证单向重定向、参数和返回，不制作另一套详情。短任务弹窗按 E 类审查。此处“已具备”只表示代码结构存在，不等于视觉和交互已经人工签收。

| 举报 | `ReportDetailContent` + `ReportDetailDialog` / `community/reports/[id]` | 状态处理与追加备注是两个独立提交范围 | 两种任务切换显式处理草稿；举报目标、举报人、负责人跳转与关闭使用同一决策 |

### 8.1 一致的行为裁决

1. **入口与主体。** 主列表的编辑、单条处理和必要只读查看在列表弹窗完成，保持筛选、页码、滚动与 URL；非主列表引用、跨资源跳转和直达使用独立路由。两种容器挂载同一模块主体，独立页可按权限编辑，弹窗不嵌 Nuxt page。无权或状态不允许时只显示真实可读事实。
2. **草稿与命令。** 普通字段草稿和立即生效的命令分开。命令在字段编辑态可触达；点击后展示影响及“草稿仍需单独保存”，执行后只刷新与命令有关的服务端事实，保留草稿和弹窗。正在提交、上传或执行命令时可暂时锁定冲突操作，结束后恢复。不能因 `dirty` 或编辑模式而静默隐藏、禁用独立命令。两个有草稿的保存范围互斥时，切换入口仍可发现，点击后由保存、放弃、继续编辑的明确决策处理；不暗中丢弃，也不为同时编辑两个范围建立双轨状态。
3. **保存结果。** 从主列表以编辑入口打开的弹窗，普通保存成功且重读服务端事实后关闭，并刷新原列表和回焦触发行；失败保留弹窗、草稿和就近错误。独立页保存后保持当前记录地址并回到阅读态。立即生效的命令和举报处理、备注、任务重试执行后保持当前容器，展示最新状态与反馈，除非目标已被删除且不可继续阅读。当前卡片普通保存关闭而其他资源多保持弹窗，是待统一的实现差异；改动前逐项固定现有行为测试。
4. **离开与跨资源导航。** 弹窗的关闭按钮、Esc、遮罩、切换记录、正文关联链接及底栏导航都经过同一草稿决策；独立页的站内跳转、返回和刷新也受保护。路由守卫由持有草稿状态的详情主体或弹窗容器承担，`AdminResourceLink` 只负责目标与权限，不承载业务草稿状态。确认离开后才导航；取消保持原弹窗与输入、焦点。新标签页、浏览器卸载及嵌套确认须分别核对，不能只测关闭按钮。
5. **浮层和视觉。** 列表弹窗默认不常驻“打开完整页面”底栏；只有经实际跨任务需求证明的次级入口才保留，并且经过草稿保护。对象编号只在容器标题或主体身份区出现一次。页面和弹窗各只有一层主表面；详情区用留白或分隔线，不套多层卡片。页面只增加面包屑、返回与稳定 URL；弹窗只增加紧凑标题、关闭、滚动和焦点管理。只读字段、关联链接、编辑控件、立即生效命令必须可辨，浅色与暗色使用同一 Vuetify token 层级。

### 8.2 同类问题的适用边界

- B 类四个动态配置页、站点与 Redis 配置以及站点策略的保存范围、测试与刷新，按已保存配置和草稿配置的真实契约审查；脏状态导致测试或刷新不可用时，必须就近说明原因和恢复路径。这类页面使用独立配置页，不因含表单就增加主列表详情弹窗。
- C 类账号安全、升级、通信与事件诊断保留专题流程；命令的确认、权限和状态连续性按专题审查，不强制套 A 类字段编辑模式。
- D 类父页 Tab 切换检查未保存草稿、当前视图刷新和局部反馈，不复制页头、全局保存或稳定地址。E 类创建、上传、测试、危险确认、筛选与视图设置继续是单任务弹窗，不扩成单记录独立页。
- 用户前端 `apps/default-theme` 与管理端是不同产品表面；本节不改其路由或弹窗。新增管理端资源先按“单记录稳定地址 + 主列表任务弹窗”条件归类，进入本账本后再施工。
