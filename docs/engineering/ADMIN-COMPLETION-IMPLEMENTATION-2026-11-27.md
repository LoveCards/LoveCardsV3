# 管理端能力补全实施清单

> 2026-11-27。基于云端 dev `35c114c2` 复审后的实施范围。此文件只管理切片、决策和验收证据；视觉规则继续引用既有规范，不建立第二套设计体系。

## 目标与范围

补齐现有管理任务中的查询、诊断和导航断点，不按后端表或模块机械建立菜单。新增一个“系统 → 站内通知”入口；现有升级、文件、举报、事件和主题页面继续承担各自职责。不增加一级菜单、业务模块、全局 Store、通用详情引擎、请求封装层或前端依赖。

## Direction contract

THESIS：管理员从摘要和任务准确找到记录与诊断，页面以对象、状态和下一步为重点。
OWN-WORLD：沿用 LoveCards 的 Vuetify 原生组件、Indigo 主色与中性表面；浅色和深色共用信息层级。
STORY：识别记录 → 核对当前事实 → 进入受权的关联对象或命令；查询本身不改变用户状态。
FIRST VIEWPORT：页头与刷新在既定位置，筛选与结果位于一份表格壳；诊断先给状态，技术字段置后；一个任务只有一层主要表面。
FORM：seed: none (pinned)。用户要求“确保遵守开发规范，然后 ui 风格”等，并已确认现有详情／弹窗和表格基线，沿用该体系。
FINISH：unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## 复审修正

- 通知 `DATETIME` 由既有后端路径以本地 `date()` 保存，不能把无时区历史值统称 UTC。筛选和显示按保存原值；开始含、结束不含；不在本次迁移历史时间。
- `communications.read` 继续代表运维元数据；新 `notifications.read@global` 只允许逐条通知元数据查询，不自动授予既有非 root 角色，不包含正文和隐私偏好。
- 文件渠道精确筛选、举报待处理状态组及事件 ID 定位必须先进入正式请求 schema，不能只改前端 URL 或以类型断言绕过契约。
- 升级计划属于 C 类专题，复用现有单计划 API 和持久状态机，不建立另一个升级模块。计划查询 `?plan=` 支持刷新与引用，命令保持一份实现。
- 主题上传和删除虽有 API，但开放新增 UI 前须补审计与文件副作用结果。数据库事务不能声称回滚文件系统：先记录操作意图，审计不可用则不执行；完成审计失败必须明确副作用可能已发生，提示刷新核对，不静默重试。主题文件与绑定写入共用一个模块锁，数据库操作持锁至提交；Application 依赖锁契约，不直接依赖文件系统实现。
- 升级恢复允许“指针已还原、健康未确认”后的继续恢复；可续跑的 checkpoint 不得被前端的自造状态机锁死。执行不确定与历史计划保持只读。
- 原通知聚合使用无查询条件的 ThinkORM `find()` 会返回空值，导致总数、未读、接收人数假零；现改为真实聚合结果，旧接口形状与授权保持兼容。
- 站外发送历史需要新记录、脱敏、保留期限和清理协议，另行分期；私信撤回、任意私信浏览、全站公告和私人草稿／收藏／轨迹明细不在本次实现范围。

## UI 与交互约束

- 列表复用 `AdminResourceTableShell`。表头横排、字段横向列式，ID 默认隐藏；固定排序的接口不放假排序按钮；没有全文搜索契约就不放全文搜索框。
- 行尾“查看”中性 text 打开只读弹窗，详情按 ID 重新读取；跨对象引用进入稳定独立路由。独立页和弹窗用同一模块详情主体，壳只负责返回、标题、尺寸、关闭、焦点与滚动。
- 只读资源不造编辑态、保存或批量写操作。元数据不冒充正文；用户名不可得时使用“用户 #ID”，不逐行请求用户详情或假造名称。
- 通知查询无副作用，不更新 read_at、不发送通知、不写业务数据。关联对象仍独立判权，缺权显示纯文字。来源事件无直接持久关联时明确不可追溯，不解析 dedupe_key 猜关联。
- 原生表面、菜单、输入、确认和无障碍控件，沿用现有主题 token；不新增样式引擎、统一渲染 schema 或自制浮层。
- 首次失败不显示假零；同条件刷新失败可保留旧值且标明，筛选变化清除旧结果；并发只接受最新响应。URL 管已生效查询，视图偏好按管理员隔离，重置不删除已存视图。
