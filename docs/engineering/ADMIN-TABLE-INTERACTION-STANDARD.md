# 管理端列表与表格交互规范

> 状态：2026-11-18 目标规范已定稿，云端 dev 已完成首轮迁移；人工审查与隔离环境全量 E2E 尚待完成。本文持续作为验收口径，不能把代码合入或构建成功视为视觉与行为验收完成。
>
> 范围：`apps/admin` 的资源列表、详情内嵌表、运行诊断表和可编辑策略表。页面宽度与区块顺序遵守 [页面布局规范](ADMIN-LAYOUT-SYSTEM.md)，颜色与 Vuetify 原生外观遵守 [UI 风格锁定](ADMIN-UI-STYLE-LOCK.md)，API 与权限边界遵守 [管理端架构](ADMIN-ARCHITECTURE.md)。本文负责表格内部的信息、导航和操作语义；与旧的 IA 草案、UI 审查记录或表格查询建议冲突时，以本文为准。

## 1. 目标与不变量

管理员扫一行时，先识别对象和状态，再在行尾找到下一步。**字段负责阅读，操作负责行动**。查看当前记录、跳到关联对象、修改当前记录、执行危险动作必须有不同且可预期的入口。

- 不因统一 UI 增加无效搜索、筛选、排序、批量操作、保存视图或详情页。控件必须对应真实 API、当前权限及明确任务。
- 不改变后端业务语义、权限范围或通知/审计规则；前端隐藏操作不是授权校验。
- 资源列表在整个页面只保留一处结果数、一处检索区和一个表格表面。不同业务可选择不同筛选字段，但位置、层级和反馈一致。
- 表格身份列不承担隐蔽导航；整行默认不可点击。不得靠 ID、颜色或图标猜测入口。
- 详情路由是可直接打开和刷新的页面；弹窗是一次局部查看或操作的呈现方式。两者不得因复用而建立两份数据与权限规则。
- 浅色、深色使用同一信息层级、交互和状态含义；不得为夜间模式另造表格布局。

## 2. 表格类型

| 类型 | 适用场景 | 容器与分页 | 行内入口 |
| --- | --- | --- | --- |
| 资源列表 | 用户、卡片、评论、标签、文件、角色、权限、举报、审计、处理任务 | `AdminPageContainer fluid` 内一个 `AdminResourceTableShell`；后端分页按真实契约 | 行尾一个明确文字主操作；其余动作进入“更多”菜单 |
| 局部只读表 | Session、升级计划、队列分布、运行依赖、处理器目录 | 所属详情/运行区块内原生 `v-data-table`；小数据量可无分页 | 有后续页面才给明确文字入口；纯诊断表不造“详情” |
| 可编辑策略表 | 通知与主动提示策略 | 所属配置区块内原生表格；少量规则可无分页 | 原位开关或字段只负责编辑；统一保存区负责提交，危险变更另确认 |

事件事实的展开列表是“主对象＋关联处理任务”的层级视图，不强行改成扁平表格。它的筛选、总数、展开语义和任务链接仍按本规范的可读性、单一入口及 URL 规则验收。主题与渠道目录等卡片目录不伪装成表格。

## 3. 资源列表的固定阅读顺序

```text
页面标题、用途说明                                  [页级主动作]
可选上下文摘要
┌─────────────────────────────────────────────────────────────┐
│ 搜索 / 常用筛选 / 查询             结果数  [视图设置（按需）] │
│ 已生效条件（仅有条件时）                 [清除/恢复条件] │
│ 已选 N 项与批量动作（仅选中且有相应权限时）                 │
├─────────────────────────────────────────────────────────────┤
│ 资源身份       核心业务字段      状态      时间      操作   │
│ 对象摘要       辅助说明          明确文案  统一格式  查看详情 │
├─────────────────────────────────────────────────────────────┤
│ 每页行数                                           分页     │
└─────────────────────────────────────────────────────────────┘
```

页级动作如创建、上传和刷新放页头；10 个资源列表均有同一位置、带文字和刷新图标的“刷新”，保持 `outlined` 次级语义，不能因为页面没有创建动作就升为主按钮，也不能再在表格工具区重复放第二个刷新。刷新只重读当前已生效查询和当前页；初次加载失败的“重试”属于错误反馈，不代替常驻刷新。局部表只刷新自身时，入口放所属区块标题侧；配置表存在未保存修改时保留入口、禁用并说明原因，不得默默丢弃修改。事件管理的运行状态、事件明细和注册能力分别刷新自身数据，标签切换后入口与当前可见内容一致。搜索与最常用的一两个筛选在工具区；多字段、低频筛选可以在同一区的折叠区或明确命名的弹窗内，审计允许两行。结果数在工具区靠操作侧显示，加载或请求失败时不得把旧结果默认为零。已生效条件应可读、可逐项清除；清除查询条件回到第一页且不清列偏好。

排序只有服务端支持的列才显示表头排序；若另有“搜索与排序”弹窗，它与表头必须读写同一状态。当前排序方式需要可见，例如表头方向或条件摘要；不能把一个隐藏排序留在 URL 而页面毫无提示。分页、每页行数、搜索、筛选和排序进入 URL；列设置按需启用，保存视图只在复合查询或重复工作流确有价值时启用，二者不能捆绑出现。偏好按当前管理员隔离，管理员身份未确定前不写浏览器持久化。没有相应能力时省略控件，不放禁用的假入口。处理任务可保留高频状态切换，审计可保留多字段查询，但它们仍在同一表格壳内。

现有资源列表已经提供的命名视图及浏览器内偏好在迁移时保留，不静默删除用户数据；是否给新增列表开放“保存视图”由该页任务决定。保存和应用视图只接受页面声明的搜索、筛选、排序、每页行数和列键；`page`、`inspect`、返回来源及其他临时参数不进入视图。读取旧视图时先过滤未知键和值，不能把旧存储中的任意 query 原样写回路由。

文本搜索保留输入草稿，按 Enter 或明确的“查询”按钮才提交；清空已提交关键词立即重新查询。常用单项筛选和表头排序在选择后立即生效；多字段筛选面板统一由“应用”提交，关闭面板不改变已生效条件。任何已提交的查询条件或每页行数变化都回到第一页，翻页保持条件。URL 只反映已生效条件，输入草稿和临时行选择不写入 URL；更新查询使用路由替换，打开详情使用正常导航，避免每次输入都堆出浏览器历史。

每个列表声明自己的默认查询基线，区分搜索/筛选、排序、每页行数和列偏好。只有已生效的搜索或筛选偏离基线时才显示筛选重置入口：无默认过滤条件时用“清除筛选”回到无条件列表；有默认过滤条件时用“恢复默认筛选”回到可见的默认状态，例如处理任务的通知队列与失败视图。两者不改变排序、列偏好和每页行数。“恢复默认视图”才同时恢复默认查询基线、列偏好和每页行数，不删除已保存视图；已保存视图应用时从第一页开始，不以整页重新加载实现。

| 请求场景 | 行、结果数和操作 | 反馈 |
| --- | --- | --- |
| 首次加载或已生效查询、页码变化 | 清除上次查询的行和临时选择；结果数暂不显示；行操作不可用 | 表格内显示加载状态，成功后才显示本次结果或空态 |
| 当前查询刷新 | 保留本次查询的行供阅读，临时禁止写入类行操作与批量操作；“查看详情”可用且重新读取当前对象；旧结果数标明为“上次结果” | 显示“更新中”；成功后更新行与结果数 |
| 当前查询刷新失败 | 保留上次成功结果供只读排查，继续禁止写入类操作；旧结果数仍标明为“上次结果” | 显示错误与重试；首次加载失败只显示错误，不显示零结果 |

并发请求只接受最新已生效查询的响应；状态、行和结果数必须同时切换，不能让旧请求覆盖新条件。服务端最终仍独立验证每项操作的权限与状态。

## 4. 列与字段的显示规则

默认列从左到右为：资源身份、支撑判断的业务字段、状态、时间、操作。一般保留 5–8 个核心列，简单目录可以更少；不为凑列数加入无意义字段。可选诊断列仍服从字段格式；ID、IP、request/correlation ID、原始 payload 和内部版本优先放详情诊断区或列设置，不占用默认阅读顺序。没有独立资源身份的审计记录，以“动作＋操作者”作为主信息。

| 字段语义 | 列表显示 | 细节与空值 |
| --- | --- | --- |
| 身份 | 名称、用户名、文件名或内容摘要为主；编号为弱化辅助文字 | 长内容最多两行，全文在详情；没有名称时用“资源类型 #编号” |
| 关联资源 | “用户 #编号”“卡片 #编号”等可读文字 | 默认不渲染成 `v-btn`；跨资源跳转放详情中的明确链接；确需列表直达时显示“查看用户”等命名链接并标明它离开当前记录 |
| 状态 | 明确中文状态词，成功/正常可用中性文字，需注意/失败用语义芯片 | 同一状态在同一业务域复用一份映射和一种组件；颜色与图标只是辅助；未知值显示“未知状态”，不能猜测为正常 |
| 时间 | 可确认格式的时间统一显示 `YYYY-MM-DD HH:mm`；需要秒的审计/诊断才显示秒 | API 明确时区且站点时区可得时才转换；无时区的标准日期时间只调整显示格式，不改变年月日和时分。格式未知时显示服务端原值并提示“时间格式未知”。只有时区语义明确时才给 `<time>` 的 `datetime` 写机器可读时间；空值为“—” |
| 数量/金额外数值 | 按数值对齐，带单位或含义 | 不用芯片装饰普通数字；空值与零必须区别 |
| 长文本/错误 | 可读摘要，按词或标点断行；必要时截断并给完整详情 | 不让长码撑破页面，也不将业务正文压成不可读的窄列 |
| 技术标识 | 等宽或次级文字，支持复制时给明确复制操作 | 不用彩色芯片伪装状态；敏感字段遵守脱敏与权限契约 |

单元格空值统一为“—”，但“未配置”“未执行”“不适用”“读取失败”各有不同业务含义时须分别写明。搜索命中高亮只标示匹配片段，不改变链接、状态或权限语义。

## 5. 点击、详情与操作的边界

### 5.1 行尾操作

- 每个有详情或局部查看能力的资源列表在最后一列提供**一个带文字的主入口**：完整页面用“查看详情”，只有局部面板用“查看”或“编辑”；如果目前只有文件引用等专题页，准确写“查看引用”。主入口必须指向当前行的对象或其明确命名的专题，不能用“查看详情”跳到关联用户或另一类对象。
- 行尾可再有一个“更多”菜单，收纳低频编辑、审核、账号安全、删除等；菜单项用动作全称。单行多个并排图标、行尾只有图标、身份与操作列重复“查看详情”，均不作为默认样式。
- 列表的 ID、身份文字和整行默认不触发详情。若保留可点击身份作为已建立的工作流，必须同时存在行尾文字入口、目的地一致，并在页面迁移记录中说明；完成迁移后只保留一个主要入口。
- 危险动作在菜单/次级入口触发确认，最终确认框说明目标、影响和可恢复性；不把普通列表行渲染成红色动作墙。不可执行动作按 capability 与目标状态独立隐藏或说明原因。

行尾主入口统一使用共享的轻量文字外观：无常驻描边、实底或药丸形状，使用主题 `primary` 文本、统一的字号与字重；悬停和键盘焦点必须可辨，点击区域不能只覆盖字形。前往详情或专题的入口保留链接语义，打开局部面板或执行动作的入口保留按钮语义，二者外观一致；不得为了统一外观把导航伪装为按钮，或把写操作做成超链接。每行最多一个常驻文字入口和一个“更多”菜单；“更多”图标须有明确可访问名称和提示。行尾列按实际入口与菜单预留宽度，不能依靠缩小字号或文字折行压进窄列。页头按钮、搜索按钮和行尾主入口不是同一种视觉层级。

### 5.2 完整详情页与弹窗

| 意图 | 默认承载 | 原因 |
| --- | --- | --- |
| 阅读完整对象、证据、历史、关联和诊断 | 独立详情路由 | 可分享、刷新、返回、建立面包屑和容纳复杂信息 |
| 修改有限字段、审核或调整状态、追加备注 | 当前列表或详情上的 `v-dialog` | 保留上下文，操作范围和保存结果明确 |
| 删除、撤销、永久清理或其他高风险一步操作 | `AdminDangerActionDialog` 或同等显式确认 | 审阅资源和后果后才提交 |
| 需要多步骤、长时间编辑或跨多个子资源的流程 | 独立页面 | 避免深弹窗、内部滚动和丢失上下文 |

“查看详情”不得自动进入编辑态；详情页的“编辑”再打开编辑弹窗。弹窗可承载从详情页抽出的**内容组件**，但不直接嵌整张带 `AdminPageHeader`、布局、路由 middleware 的页面，也不嵌同源 iframe。页面壳、弹窗壳分别负责导航和焦点；对象读取、字段规则与权限判断只保留一份。复杂卡片编辑可用宽且可滚动的对话框，窄屏全屏；标签这种少字段对象可以仅有局部面板，不为整齐而新增空洞详情页。

路由弹窗（从列表打开同一详情 URL 时保留列表背景，直接访问 URL 则显示完整页面）是**可选的专项模式**，不作为全局表格规则。只有任务确实需要“同一详情 URL 同时具备弹窗和完整页”时才采用；必须先验证刷新、前进后退、关闭目标、列表筛选/滚动保持、权限、焦点与未保存修改。关闭应返回来源列表；没有有效来源时回到规范列表地址。不得直接调用 `history.back()` 假设前一页一定是列表。普通编辑弹窗可以保持列表 URL；需要深链时使用明确的编辑状态，不把 `inspect` 同时解释成查看和编辑。

### 5.3 已有地址与状态迁移

卡片、评论、标签的 `/.../:id` 当前只是跳到列表 `?inspect=id` 的兼容入口。卡片和评论建立真正详情页后，规范 URL 为 `/.../:id`；旧 `?inspect=id` 转到对应详情，原列表筛选/分页作为返回上下文保留，不混入详情查询参数，并有可删除的迁移期。不得让页面与弹窗长期各自维护一套内容规则。地址变更时同步导航契约、`AdminResourceLink`、面包屑及 E2E。用户、角色、举报、审计和处理任务已有详情页，保留其稳定 URL。

编辑弹窗关闭、保存失败或权限不足时保留当前列表查询；保存成功更新当前行或刷新当前查询并给出反馈。未保存修改时，关闭、返回、刷新和路由跳转要有同一离开保护。对话框恢复焦点到触发按钮；嵌套确认不得使焦点丢失或让背景列表可操作。

从列表打开详情时，把当前内部列表地址写入这次导航的路由 history state；有经校验的同标签页来源历史时，详情的“返回列表”使用浏览器返回，由路由恢复已生效查询、页码和滚动位置。刷新后如来源历史不可恢复，可使用已校验的来源列表地址恢复查询与页码，滚动回顶部；直接打开详情或来源丢失时回规范列表首页。旧 `?inspect=id` 跳转前从原 URL 去掉 `inspect`，把剩余有效列表查询作为来源地址。来源只能是对应资源的管理端列表路由，不接受外部 URL；不另建全局返回状态库，也不把来源参数混入详情 URL。列表操作成功后若当前行不再属于筛选结果，应从本次结果移除并更新总数，不保留一个状态与筛选条件矛盾的行。

## 6. 响应式与可访问性

- 断点以视口 CSS 宽度为准。≥600px 使用横向列式表格，所有列标题保持单行、横向字序；列宽由字段角色和当前可见列决定，宽表只在表格容器内横向滚动。不得沿用不同页面各自的“自动在 1280px 变纵向”默认，也不得用固定 720px 最小宽度让 8 列挤成竖排字。排序图标与标题必须同处可读的表头单元格；设置 `nowrap` 时仍须给该列足够最小宽度，不靠视觉溢出遮盖相邻列。
- <600px 复用 Vuetify 数据表原生的“字段名＋值”移动行和移动排序控件，统一设置 `mobile-breakpoint` 为 600；只读局部表和可编辑策略表遵守相同断点。身份与状态优先阅读，操作仍在每条记录末尾；其余可见字段保持可访问，批量选择不能占据身份阅读位置。没有服务端排序能力的表不展示空的排序选择器；不能由各页面复制一套移动表格或另造卡片列表。
- 字段宽度建议：身份/正文摘要至少 240/320px，状态约 100–120px，时间约 170–190px，操作按文字与菜单实际宽度预留；长技术码采用可折行或省略加完整说明。可见列变化后重新计算总宽，不用单个全站 `min-width` 硬塞所有表。
- 表头保持横向文字，不使用竖排字形；窄列先保证中文词组可读，再让表格内部滚动。行高可随摘要合理增长，但同类状态、时间和操作对齐。
- 键盘能到达查询、排序、详情和菜单；焦点明显；链接、按钮与纯文字语义一致。图标按钮必须有可访问名称和提示；只有颜色不同或仅靠悬停出现的动作不可接受。
- 核对 1440px、960px、600px、390px、等效 200% 缩放、浅色和深色。不得出现页面级横向溢出、表头逐字竖排、操作被裁切、弹窗不可关闭或缩放后无法读到字段值。

## 7. 当前页面的目标归类与迁移边界

| 页面/区块 | 类型 | 当前主要差异 | 目标入口与保留能力 |
| --- | --- | --- | --- |
| 用户 | 资源列表 | 用户名跳详情，行尾编辑或查看 | 行尾“查看详情”；编辑与删除留弹窗，账号安全留详情子页 |
| 卡片、评论 | 资源列表 | ID 与操作都开编辑/审核面板，`/:id` 回跳列表 | 内容摘要保持身份；建立完整只读详情页，行尾“查看详情”，编辑/审核仍弹窗；旧深链迁移 |
| 标签 | 资源列表 | 名称与操作重复开面板 | 行尾“编辑”或“查看”；名称为文字，保留轻量弹窗及深链兼容 |
| 文件 | 资源列表 | 文件名跳“引用”而非文件详情，行尾多个图标 | 文件名为身份文字；行尾明确“查看引用”或“编辑”，其余进菜单；不把引用页冒称详情 |
| 角色 | 资源列表 | 名称跳详情，行尾三个图标含红色删除 | 行尾“查看详情”；编辑、分配权限、删除按频率和风险分层 |
| 权限目录 | 资源列表 | 能力标识自身是唯一入口 | 增加行尾“查看详情”，能力标识改为可读文字；只读不造编辑 |
| 举报 | 资源列表 | 编号、举报人、目标均为按钮，缺少行尾操作 | 三列以文字识别；行尾“查看详情”进入举报页；举报人和目标链接放详情页；状态更新和备注仍用弹窗 |
| 审计 | 资源列表 | 图标是唯一详情入口 | 行尾文字“查看详情”；动作与资源字段以阅读为主，跨资源链接按需要明确命名 |
| 处理任务 | 资源列表 | 业务事件与行尾重复跳同一任务 | 保留行尾“查看详情”，事件名为可读文字；状态切换与队列筛选保留 |
| Session、升级计划、队列/依赖/处理器目录 | 局部只读表 | 视觉密度及断点各异 | 统一字段格式、横向/纵向断点；只展示真实可执行操作 |
| 通知与主动提示策略 | 可编辑策略表 | 自有移动布局与表格断点不同 | 保留开关、审阅与保存语义；与通用断点和字段层级对齐 |

此表是迁移清单，不表示新增后端接口已经具备。若完整详情缺少必要数据，先核对现有 SDK 与 API，再决定是否增加只读契约；不能用列表中的截断字段伪造完整详情。

## 8. 实施顺序与验收门禁

1. **先固化页面样板**：以举报列表＋详情、一个卡片/评论列表及一个可编辑策略表为样本，验证三种表格类型、身份/状态/时间/操作列、移动排序和表单焦点。先在真实数据与权限下验证，再推广。
2. **收束共享层**：逐页使用 Vuetify 原生移动能力验证断点；全部 17 个承载数据表的文件复核后，再把 600px 提升为 `VDataTable` 和 `VDataTableServer` 的全局默认值并移除过渡性逐页设置。`AdminResourceTableShell` 只显示页面传入的结果数及其新鲜度，表格正文继续用既有 `AdminAsyncState` 表达加载、错误和空态。共享视图控件只管理列偏好与用户显式保存的视图，不直接发 API、不调用 `window.location.replace`、不自行清空业务查询；页面负责校验并应用视图条件。业务状态映射仍留模块。避免再建立一套表格引擎或复制查询状态仓库。
3. **逐域迁移**：治理与审计、内容与用户、系统与诊断；每次只提交一个可验证的页面切片，同步该页入口、旧深链、URL 查询、权限、空态和 E2E。共享规则先以现有组件的增量能力服务样板，全部迁移后删除旧分支，不保留长期双轨。
4. **复核并删除旧路径**：移除不再使用的 `inspect` 回跳、重复按钮、固定表格最小宽度和冗余样式；有外部书签依赖的旧地址只保留单向重定向，并在迁移记录中写明删除条件。

| 责任位置 | 本次设计边界 | 首个可验证切片 |
| --- | --- | --- |
| Vuetify 默认值与表格共享样式 | 完成逐页验证后，将 `VDataTable`、`VDataTableServer` 的移动断点统一为 600px；只在共享层处理无排序表的空移动排序头与表格内部溢出，不复制各页表格模板 | 举报和处理任务在 390px、600px、960px 下均可读、可操作；其他表格无回归 |
| `AdminResourceTableShell` | 独立显示页面传入的唯一结果数及“更新中/上次结果”标识，不依赖列偏好键；`AdminAsyncState` 继续负责正文状态，表格壳不读取业务 API | 切换举报筛选与刷新失败时，结果数和行状态一致 |
| `AdminTableViewControls` | 列设置与命名视图分别按需开启；只管理当前管理员的持久化偏好并发出应用/重置意图。页面按自身查询白名单校验并提交视图条件，不能通过整页重载应用视图；已有保存视图不丢失 | 不保存视图的列表仍能显示结果数；保存视图切换不整页重载 |
| 页面查询与返回上下文 | 页面维护各自 API 查询映射和默认基线；共享一个仅用于同资源列表来源校验的路由辅助逻辑，不建跨模块查询仓库 | 举报详情返回原页；旧卡片 `inspect` 地址能到新详情并正确返回 |
| 字段格式 | 共享时间与空值的纯显示规则；业务状态映射留在所属模块，不建立全站状态枚举 | 同类字段在举报、卡片、处理任务中含义和格式一致 |

**影响范围快照（2026-11-18）**：10 个资源列表页面、7 个局部/策略表所在文件、`AdminResourceTableShell`、`AdminTableViewControls`、Vuetify 默认值、资源链接与卡片/评论详情路由，以及相应 E2E 和视觉验收。卡片/评论的 `getManaged` 已存在，首批只读详情以现有 SDK 契约为边界；若确需新增证据或历史字段，单独审查后端 Resource、capability 与通知/审计语义，不能为统一外观顺手扩展 API。本方案不改变业务状态机、通知投递、管理菜单、夜间主题 token 或后端队列。现有其他功能分支不纳入本次 UI 迁移。

每个列表至少审查：默认核心列数量适合任务且可读；结果数只有一处且不会把旧数冒充新数；搜索/筛选/排序真实生效并可从 URL 恢复；默认过滤的恢复语义清楚；窄屏仍可按真实服务端能力排序；行尾主入口目的地明确；身份和关联字段不会伪装按钮；同类状态/时间格式一致；只读角色与不可执行目标不出现假操作；加载、空数据、无匹配、错误分别可辨且旧行不可误操作；390px 与 200% 缩放能完成查看和操作；浏览器返回/刷新及弹窗未保存保护有效。自动化覆盖交互与契约，截图人工审查信息层级。文档阶段仅校验规范一致性，不能把未运行的页面 E2E 写成通过。

路由弹窗专项模式的技术依据：[Vue Router：带独立 URL 的弹窗](https://router.vuejs.org/guide/advanced/router-view-route)、[Nuxt 4：`NuxtPage` 的 `route` 属性](https://nuxt.com/docs/4.x/api/components/nuxt-page)；这些 API 只说明可实现性，不免除本节的实际验收。

## 10. 表格视觉收束清单

2026-11-18 按实际 `<v-data-table>`／`<v-data-table-server>` 使用点普查，共 17 张表；事件明细的展开列表另按同一操作与刷新语义检查。设计复核不能只抽查举报页，也不能把构建通过视为美观通过。

| 表格范围 | 实际使用点 | 审查重点 |
| --- | --- | --- |
| 资源列表（10） | 用户、卡片、评论、标签、文件、角色、权限、举报、审计、处理任务 | 页头唯一刷新；表头横向；身份为文字；行尾单个轻量文字主入口与按需显示的“更多” |
| 局部与诊断表（5） | Session、升级计划、队列分布、通信依赖、处理器目录 | 所属区块刷新范围明确；无详情时不造假入口；真实操作仍可被键盘和触控访问 |
| 可编辑策略表（2） | 通知策略、主动提示策略 | 开关与统一保存区保持原行为；未保存修改时刷新禁用并说明；长说明不挤压表头 |
| 展开列表（非表格） | 事件明细及关联处理任务 | 当前条件刷新保留上次结果并标注新鲜度；条件切换清除旧结果；任务链接目的地明确 |

视觉验收以 [图 1](assets/admin-ui-reference/01-workbench.png) 的克制、平面和紧凑层级为准：行尾主入口只占一处文字重心，更多菜单图标为次级；页头刷新与表格工具区分层；表头保持一行且有足够呼吸空间。每张表分别在 1440、960、600、390px 和等效 200% 缩放下检查浅色、深色、键盘焦点、长文本、空态与加载/刷新失败。宽表只允许表格内部横向滚动；截图人工审查文字密度、留白、对齐和视觉重心，不能仅以“无溢出”通过。

实现依据：Vuetify 3 的 [Data table](https://vuetifyjs.com/components/data-tables/) 支持列级宽度和表头配置，[按钮变体](https://vuetifyjs.com/components/buttons/) 提供语义层级；[Carbon 数据表规范](https://v10.carbondesignsystem.com/components/data-table/usage/) 将全局工具、行内操作和分页放在不同层级。外部规范只提供组件能力与交互参考，最终外观以本仓库图 1 和上述规则为准。
