# 管理端列表与表格交互规范

> 状态：2026-11-19 已在云端 dev 实施资源双形态详情、关联文本链接、表格宽度响应操作列，以及关联资源的可读名称。本轮收束所有数据表为横向列式展示，并统一默认列与列表动作文案；验证记录以本次提交说明为准。
>
> 范围：`apps/admin` 的资源列表、详情内嵌表、运行诊断表和可编辑策略表。页面宽度与区块顺序遵守 [页面布局规范](ADMIN-LAYOUT-SYSTEM.md)，颜色与 Vuetify 原生外观遵守 [UI 风格锁定](ADMIN-UI-STYLE-LOCK.md)，API 与权限边界遵守 [管理端架构](ADMIN-ARCHITECTURE.md)。本文负责表格内部的信息、导航和操作语义；与旧的 IA 草案、UI 审查记录或表格查询建议冲突时，以本文为准。

## 1. 目标与不变量

管理员扫一行时，先识别对象和状态，再在行尾找到下一步。字段负责阅读，操作负责行动。操作包含查看、进入编辑态和资源命令；封禁、隐藏、审核、置顶、恢复、重试、删除等不能被“编辑/删除”概括。

- 不因统一 UI 增加无效搜索、筛选、排序、批量操作、保存视图或详情页。入口必须对应真实 SDK/API、当前权限、目标状态及明确任务。
- 不改变后端状态机、权限、通知和审计语义；前端隐藏或禁用操作不是授权校验。涉及状态转换先按 [通知规范](NOTIFICATIONS.md) 判定，通知只能由后端统一发布。
- 资源列表只保留一处结果数、一处检索区和一个表格表面。身份列和整行默认是阅读内容，不承担隐蔽导航。
- 当前行的查看、编辑态和资源命令在列表上下文内完成；关联到另一资源的明确语义链接进入其稳定详情路由。单条命令与批量命令按实际契约分别声明，不假设批量 API 天然提供同义的单条动作。
- 可被引用资源的独立页与列表弹窗承载同一份**模块内详情主体**。主体按权限和状态呈现查看态、字段编辑态或专题处理态；页面壳负责路由，弹窗壳负责焦点、尺寸和关闭。不得复制读取、表单与保存规则，也不得把整张 Nuxt 页面嵌入弹窗。
- 浅色、深色使用同一信息层级、交互和状态含义；夜间模式不另造布局。

## 2. 表格类型

| 类型 | 适用场景 | 容器与分页 | 行内入口 |
| --- | --- | --- | --- |
| 资源列表 | 用户、卡片、评论、标签、文件、角色、权限、举报、审计、处理任务 | `AdminPageContainer fluid` 内一个 `AdminResourceTableShell`；后端分页按真实契约 | 行尾显示当前行的弹窗操作；可用宽度不足时依优先级收入“更多” |
| 局部只读表 | Session、升级计划、队列分布、运行依赖、处理器目录 | 所属详情/运行区块内原生 `v-data-table`；小数据量可无分页 | 有后续页面才给明确文字入口；纯诊断表不造“详情” |
| 可编辑策略表 | 通知与主动提示策略 | 所属配置区块内原生表格；少量规则可无分页 | 原位开关或字段只负责编辑；统一保存区负责提交，危险变更另确认 |

事件事实的展开列表是“主对象＋关联处理任务”的层级视图，不强行改成扁平表格。它的筛选、总数、展开语义和任务链接仍按本规范的可读性、单一入口及 URL 规则验收。主题与渠道目录等卡片目录不伪装成表格。

## 3. 资源列表的固定阅读顺序

```text
页面标题、用途说明                                  [页级主动作]
可选上下文摘要
┌─────────────────────────────────────────────────────────────┐
│ 搜索 / 常用筛选 / 查询             结果数  [视图设置（按需）] │
│ 已生效条件（仅有条件时）                 [清除/恢复条件] │
│ 已选 N 项与批量动作（仅选中且有相应权限时）                 │
├─────────────────────────────────────────────────────────────┤
│ 资源身份       核心业务字段      状态      时间      操作   │
│ 名称或摘要     独立字段          明确文案  统一格式  查看  ⋯ │
├─────────────────────────────────────────────────────────────┤
│ 每页行数                                           分页     │
└─────────────────────────────────────────────────────────────┘
```

页级动作如创建、上传和刷新放页头；10 个资源列表均有同一位置、带文字和刷新图标的“刷新”，保持 `outlined` 次级语义，不能因为页面没有创建动作就升为主按钮，也不能再在表格工具区重复放第二个刷新。刷新只重读当前已生效查询和当前页；初次加载失败的“重试”属于错误反馈，不代替常驻刷新。局部表只刷新自身时，入口放所属区块标题侧；配置表存在未保存修改时保留入口、禁用并说明原因，不得默默丢弃修改。事件管理的运行状态、事件明细和注册能力分别刷新自身数据，标签切换后入口与当前可见内容一致。搜索与最常用的一两个筛选在工具区；多字段、低频筛选可以在同一区的折叠区或明确命名的弹窗内，审计允许两行。结果数在工具区靠操作侧显示，加载或请求失败时不得把旧结果默认为零。已生效条件应可读、可逐项清除；清除查询条件回到第一页且不清列偏好。

排序只有服务端支持的列才显示表头排序；若另有“搜索与排序”弹窗，它与表头必须读写同一状态。当前排序方式需要可见，例如表头方向或条件摘要；不能把一个隐藏排序留在 URL 而页面毫无提示。分页、每页行数、搜索、筛选和排序进入 URL；列设置按需启用，保存视图只在复合查询或重复工作流确有价值时启用，二者不能捆绑出现。偏好按当前管理员隔离，管理员身份未确定前不写浏览器持久化。没有相应能力时省略控件，不放禁用的假入口。处理任务可保留高频状态切换，审计可保留多字段查询，但它们仍在同一表格壳内。

现有资源列表已经提供的命名视图及浏览器内偏好在迁移时保留，不静默删除用户数据；是否给新增列表开放“保存视图”由该页任务决定。保存和应用视图只接受页面声明的搜索、筛选、排序、每页行数和列键；`page`、`inspect`、返回来源及其他临时参数不进入视图。读取旧视图时先过滤未知键和值，不能把旧存储中的任意 query 原样写回路由。

文本搜索保留输入草稿，按 Enter 或明确的“查询”按钮才提交；清空已提交关键词立即重新查询。常用单项筛选和表头排序在选择后立即生效；多字段筛选面板统一由“应用”提交，关闭面板不改变已生效条件。任何已提交的查询条件或每页行数变化都回到第一页，翻页保持条件。URL 只反映已生效条件，输入草稿和临时行选择不写入 URL；更新查询使用路由替换，列表弹窗不改 URL，跨资源详情链接使用正常导航，避免每次输入都堆出浏览器历史。

每个列表声明自己的默认查询基线，区分搜索/筛选、排序、每页行数和列偏好。只有已生效的搜索或筛选偏离基线时才显示筛选重置入口：无默认过滤条件时用“清除筛选”回到无条件列表；有默认过滤条件时用“恢复默认筛选”回到可见的默认状态，例如处理任务的通知队列与失败视图。两者不改变排序、列偏好和每页行数。“恢复默认视图”才同时恢复默认查询基线、列偏好和每页行数，不删除已保存视图；已保存视图应用时从第一页开始，不以整页重新加载实现。

| 请求场景 | 行、结果数和操作 | 反馈 |
| --- | --- | --- |
| 首次加载或已生效查询、页码变化 | 清除上次查询的行和临时选择；结果数暂不显示；行操作不可用 | 表格内显示加载状态，成功后才显示本次结果或空态 |
| 当前查询刷新 | 保留本次查询的行供阅读，临时禁止写入类行操作与批量操作；当前行的只读查看弹窗可用且重新读取当前对象；旧结果数标明为“上次结果” | 显示“更新中”；成功后更新行与结果数 |
| 当前查询刷新失败 | 保留上次成功结果供只读排查，继续禁止写入类操作；旧结果数仍标明为“上次结果” | 显示错误与重试；首次加载失败只显示错误，不显示零结果 |

并发请求只接受最新已生效查询的响应；状态、行和结果数必须同时切换，不能让旧请求覆盖新条件。服务端最终仍独立验证每项操作的权限与状态。

## 4. 列与字段的显示规则

全部可选列的顺序从左到右为：ID（若存在）、资源身份、支撑判断的业务字段、状态、时间、操作；ID 默认隐藏。默认可见列一般保留 5–8 个核心列，简单目录可以更少；不为凑列数加入无意义字段。IP、request/correlation ID、原始 payload 和内部版本优先放详情诊断区或列设置。审计记录将“动作”和“操作者”分别设列。

| 字段语义 | 列表显示 | 细节与空值 |
| --- | --- | --- |
| 身份 | 名称、用户名、文件名或内容摘要单独成列 | 长内容可在本单元格内合理折行，全文在详情；没有名称时用“资源类型 #编号” |
| 关联资源 | 优先“名称 #编号”，缺名称时“资源类型 #编号” | 默认在当前资源的页面或弹窗详情中给指向关联对象独立页的语义链接；列表有明确高频跨资源任务时，可在纯文字旁另放“查看作者”等命名链接，不把整项字段伪装成按钮 |

| 状态 | 明确中文状态词，成功/正常可用中性文字，需注意/失败用语义芯片 | 同一状态在同一业务域复用一份映射和一种组件；颜色与图标只是辅助；未知值显示“未知状态”，不能猜测为正常 |
| 时间 | 可确认格式的时间统一显示 `YYYY-MM-DD HH:mm`；需要秒的审计/诊断才显示秒 | API 明确时区且站点时区可得时才转换；无时区的标准日期时间只调整显示格式，不改变年月日和时分。格式未知时显示服务端原值并提示“时间格式未知”。只有时区语义明确时才给 `<time>` 的 `datetime` 写机器可读时间；空值为“—” |
| 数量/金额外数值 | 按数值对齐，带单位或含义 | 不用芯片装饰普通数字；空值与零必须区别 |
| 长文本/错误 | 可读摘要，按词或标点断行；必要时截断并给完整详情 | 不让长码撑破页面，也不将业务正文压成不可读的窄列 |
| 技术标识 | 等宽或次级文字，支持复制时给明确复制操作 | 不用彩色芯片伪装状态；敏感字段遵守脱敏与权限契约 |

一个单元格只表达一个字段语义，不在内容下叠放作者、在文件名下叠放 MIME、在动作下叠放操作者，或在状态下叠放错误代码。所需信息设独立列；窄屏通过表格内部横向滚动读取，不改为上下堆叠的移动卡片行。

关联身份字段优先显示“名称 #ID”（如“用户：用户名 #123”“标签：标签名 #45”）；缺名称时显示“用户 #123”等明确回退。字段标题写资源名，不暴露 `user_id` 等存储字段名；排序、搜索和 URL key 可继续使用既有契约，不为展示改公共键名。先复用当前列表响应已有的名称；仅有 ID 时优先评估后端列表读取阶段的批量关联摘要，禁止每行调用用户搜索或详情 API、跨页拼凑不受权限保护的全局缓存。

单元格空值统一为“—”，但“未配置”“未执行”“不适用”“读取失败”各有不同业务含义时须分别写明。搜索命中高亮只标示匹配片段，不改变链接、状态或权限语义。

## 5. 点击、详情与操作的边界

### 5.1 行尾操作与资源命令

操作按**作用对象和行为**建模，而非按“编辑/删除”两项固定模板建模：

| 类别 | 例子 | 入口与执行 |
| --- | --- | --- |
| 查看与导航 | 查看本行；查看作者、举报人或目标 | 本行“查看”打开详情弹窗；关联资源使用明确命名的链接进入对方独立页。查看不产生写入。 |
| 字段编辑 | 卡片正文、标签名称、用户资料 | 详情主体从查看态切为编辑态，同位置展示可写字段和保存/取消；只读事实不伪装为禁用输入框。 |
| 资源命令 | 通过审核、封禁/解封、隐藏/恢复、置顶/取消置顶、恢复文件、重试任务 | 依据单条对象状态与 capability 显示准确动词，可在行尾、详情的操作区或专题处理区触发；有影响或不可逆时先确认。命令不混入普通字段草稿。 |
| 批量命令 | 批量封禁、隐藏、审核、恢复、删除 | 仅在有选中项且全部目标可执行时出现在选中工具区；展示目标数、混合状态处理规则、影响和结果。它不占单行操作列。 |

列表中的通用动作统一用短文案“查看”“编辑”“删除”，省略当前行对象名；弹窗标题、确认内容及跨资源链接仍明确对象。审核、封禁、隐藏、恢复、置顶、重试、永久删除等资源命令保留能区分状态和后果的动词，不套用通用动作名。

每个模块维护自己的动作声明与排序：动作标识、准确文案、作用范围（单条/批量）、所需 capability、目标状态条件、确认/保存范围、执行函数。共享操作列只负责按钮外观、容量和溢出菜单；不注册全局业务动作、不调用 SDK、不代替服务端鉴权。行尾优先“查看”与当前列表的高频可执行命令；编辑入口按任务频率排序，其余命令进入“更多”或详情操作区。宽度足够时外露本表**已声明适合行尾**的动作，不要求把所有批量命令、低频专题或危险命令塞进一行。只有一项动作不显示空菜单，没有可执行动作则显示非交互占位。

当前行按钮统一为低饱和 `tonal` 首项及中性色 `text` 次项；统一圆角、字重、间距和焦点，不用裸超链、彩色图标排或实底主色。危险色留给最终确认。桌面点击区至少 32px，移动及等效放大至少 44px；动作文案不折行。“更多”有可访问名称，菜单项与外露按钮使用同一文案，不因折叠改变动作名称。

权限、目标保护、状态、新鲜度逐项判定。刷新失败后的旧行只允许重新读取的查看；编辑与所有写入命令禁用。触发动作时仍以详情或后端最新状态复核。对于批量接口的单 ID 调用，只有契约和效果明确等同于单条命令且经测试覆盖时才能复用；不得只因 `ids` 接受数组就自动生成单条入口。批量混合状态不得标成含糊的“切换”：确认层应说明每类目标会发生什么、哪些会跳过；成功、跳过和失败数量按服务端结果显示，不能用一次成功提示掩盖部分失败。

### 5.2 根据表格可用宽度显示操作

操作显隐由**表格内容可用宽度**和当前可见列决定，不以整个窗口、硬编码的 960/1280px 断点或每行文本长度决定。各视口均使用横向列式表格；移动端宽度不改变行结构。

1. 页面给操作稳定的优先级和完整文案。最窄可用状态保留一个当前行的常用操作及按需出现的“更多”；能容纳时保留两个常用操作；只有在身份、状态、时间等可见列仍达到各自最小可读宽度，且操作列完整容纳本表已声明且适合行尾的全部单条动作时才全部外露。不能为多露一个按钮把表头挤成竖排字或让动作被裁切。
2. 每张表先确定一份外露动作容量，再按每行权限和状态过滤并按优先级填充；“更多”只收纳本行未外露的动作。宽度收缩时反向收入，菜单与外露区不重复，操作顺序、文案和确认方式不变。某行仅有一项动作时外露该动作，不显示空菜单；没有动作时显示非交互占位。最窄状态也保持操作列单行，表格仅在自身滚动容器内横向滚动。
3. 每张表只观察一次滚动视口宽度，以选择列、当前可见列声明的最小可读宽度、已声明动作的保守宽度和间距计算档位；不逐行测量、观察或按每行文本决定断点。列设置、侧栏、浏览器缩放和容器尺寸变化时重算；档位之间留出余量，操作列宽按该档位固定，防止显隐反复触发 ResizeObserver。实际能力仍逐行过滤，不伪造按钮；宽屏动作过多时继续使用“更多”并允许表格内部滚动，不能为了全显牺牲字段可读性。
4. 行尾保持右对齐、单行、同一垂直基线；图标不是文字的替代。宽屏全显时，删除、恢复、重试等仍使用原有确认和权限规则；密集资源列表的视觉重心仍是对象和状态，而不是一排按钮。升级计划、Session 等局部表只在确有多个动作时复用此规则，纯诊断表不补操作列。

### 5.3 一份详情主体，两种容器

| 入口 | 容器 | 行为 |
| --- | --- | --- |
| 列表中查看、编辑或处理当前行 | 当前列表上的 `v-dialog`；窄屏可全屏 | 保持查询 URL、页码与滚动。按 ID 读取同一详情主体；编辑直接进入该主体的编辑态，处理直接进入该主体的专题处理态。 |
| 关联资源、书签、刷新或直接访问 | 对象自己的独立 `/:id` 详情页 | 稳定可分享地址。呈现同一详情主体及必要专题；页头或主体操作区可切换到授权编辑/处理态。 |
| 删除、撤销、永久清理等高风险一步命令 | 明确确认层 | 说明对象、影响、可恢复性和实际动作；避免两个主要弹窗同时可交互。 |
| 跨资源、多步骤且弹窗无法完整审阅的任务 | 明确命名的独立流程页 | 单独论证，不把普通查看或编辑暗中改成跳转。 |

每个可编辑资源在**模块内**拥有一份详情内容与状态逻辑：同一对象读取、字段呈现、权限判断、草稿、验证、保存和刷新。查看态使用文本、媒体、状态和证据；点击“编辑”后，仅实际可写字段原位变成输入控件，其他事实和审计信息保持只读。保存成功重读当前对象并通知外壳刷新列表；失败留在编辑态并保留草稿及错误。页面壳只负责路由、面包屑、返回和页面宽度；弹窗壳只负责焦点、关闭和滚动。不能直接把含路由参数、middleware、页头和页面布局的 Nuxt page 放进弹窗，也不建全局字段渲染引擎。

简单字段可在同一编辑范围保存；复杂操作在详情主体内设独立的专题区块和保存范围。卡片媒体上传、用户头像、角色授权、文件公开/审核状态等存在副作用、独立 API 或部分成功风险，不能假装与普通字段一键保存、取消即回滚。举报原因、证据与处理记录只读，状态处理与追加备注是各自明确的命令/处理态；审计与权限目录完全只读。账号安全、Session 撤销、文件引用和任务重试保留各自权限、确认或专题流程。同一内容组件可由页面与弹窗复用，但不要求所有资源长成同一套字段。

弹窗显示对象身份、状态、关闭入口和动作区；长证据或表单可滚动，390px 与等效 200% 缩放时不遮挡关闭/保存。只读态没有草稿；编辑/处理态的关闭、Esc、遮罩、切对象和路由离开共用脏状态决策。保存前不得默默丢弃草稿；保存后焦点回到触发入口。弹窗内的关联对象链接按权限导航到对方稳定详情页，导航前同样检查未保存内容。

### 5.4 关联资源链接和旧地址

`AdminResourceLink` 只用于**从当前对象前往另一对象**，目标始终是该对象的独立详情路由；权限不足、类型未知或对象 ID 缺失时显示非交互文字。链接文字必须指明目标，例如“用户 #12”及其上下文标题；链接用语义锚点和常驻可识别的下划线/方向提示，不再渲染成带大图标、内边距和按钮背景的 `v-btn`。列表身份字段不借此变成隐蔽操作；评论列表的作者等确有高频跨资源管理任务的辅助字段，可在作者文字旁另给“查看作者”链接，链接目的地在视觉和可访问名称中明确。举报人/目标默认在举报详情中链接，避免重现三列都像按钮的噪声。卡片作者、审计操作者/目标、文件引用和事件处理任务也按任务频率与权限逐项核对。

卡片与评论已有真正的 `/:id` 页面；其历史 `?inspect=id` 仍按既有单向迁移到详情页，不能复活成第二个编辑地址。标签的 `/:id` 目前反向跳到列表 `?inspect=id`，须改为真正详情页；历史 `?inspect=id` 暂保留打开列表弹窗，并在站内引用、书签和 E2E 迁移后删除。文件目前只有 `/:id/usage` 专题页，须建立包含文件元数据与引用区的 `/:id` 详情页；已有 `/usage` 地址在迁移期可单向转到详情页引用区，`AdminResourceLink` 的文件/媒体目标改为 `/:id`。用户、角色、权限、举报、审计和处理任务的稳定详情地址保留。地址变更须同步导航契约、面包屑、权限和 E2E，不能用列表截断字段伪造详情。

列表弹窗保持列表 URL，临时打开对象 ID 和编辑草稿不进入已保存视图；需要可分享地址时给“打开完整页面”链接到 `/:id`，并先通过脏状态决策。跨资源引用导航时在本次 history state 留下经校验的站内管理端来源；详情页的“返回来源”仅在上一条历史确为该来源时回退以恢复查询、页码及浏览器可恢复的滚动，否则显式导航该来源。面包屑仍指向目标资源的规范列表；直接打开、新标签页或来源失效时“返回列表”回目标资源规范列表。来源不能是外部 URL，也不能绕开路由权限，不另建全局返回状态库。现有 `adminListSource` 只接受同资源列表，跨资源来源需新增最小校验入口，不得直接放宽它的旧调用约束。列表操作成功后若当前行不再属于筛选结果，应重新读取当前查询并采用服务端总数，不在前端猜测总数。

## 6. 响应式与可访问性

- 所有视口宽度均使用横向列式表格。Vuetify 数据表的移动卡片行断点关闭；列标题保持单行、横向字序，字段互不叠放。宽表只在表格容器内横向滚动，页面本身不产生横向溢出。排序图标与标题同处可读的表头单元格。
- Vuetify 原生的排序、分页范围、每页行数和无数据提示统一使用简体中文语言包；页面不得逐一覆盖翻译文案。
- 字段宽度建议：身份/正文摘要至少 240/320px，状态约 100–120px，时间约 170–190px，操作按文字与菜单实际宽度预留；长技术码采用可折行或省略加完整说明。可见列变化后重新计算总宽，不用单个全站 `min-width` 硬塞所有表。
- 表头保持横向文字，不使用竖排字形；窄列先保证中文词组可读，再让表格内部滚动。行高可随摘要合理增长，但同类状态、时间和操作对齐。
- 行操作的展开依据表格自身宽度预算；在相同 960px 视口下，侧栏、列设置或嵌入容器改变了表格宽度，也必须得到相应的操作布局。不得只用视口媒体查询决定“更多”的显隐。窄屏操作列保留一个常用按钮及按需出现的菜单；操作列仍保持单行。
- 键盘能到达查询、排序、当前行弹窗操作、跨资源链接和菜单；焦点明显；链接、按钮与纯文字语义一致。图标按钮必须有可访问名称和提示；只有颜色不同或仅靠悬停出现的动作不可接受。
- 核对 1440px、960px、600px、390px、等效 200% 缩放、浅色和深色，并增加同视口不同表格容器宽度、列显隐和权限组合。不得出现页面级横向溢出、表头逐字竖排、操作被裁切、弹窗不可关闭或缩放后无法读到字段值。

## 7. 当前页面的目标归类与迁移边界

下表列的是已核对代码中的**动作族与目标入口**，不是把所有动作强制放到行尾。各行仅显示真实契约、权限和当前状态允许的动作；批量区独立按选择范围计算。复用详情主体前必须核对完整读取字段和写入结果。

| 资源 | 详情主体与单条入口 | 已存在的批量命令或专题动作 | 约束 |
| --- | --- | --- | --- |
| 用户 | 查看；资料编辑态；账号安全专题；删除确认 | 封禁/解封、冻结/解冻、审核状态切换 | root/未知角色目标保护贯穿单条与批量；头像上传和角色分配独立保存范围；安全专题保持授权子页。 |
| 卡片 | 查看；正文等字段编辑态；审核、置顶等资源命令；删除确认 | 置顶切换、封禁切换、隐藏切换、通过审核、删除 | 单向审核不能标作“取消审核”；媒体上传副作用与草稿分别处理；列表与详情使用同一内容主体。 |
| 评论 | 查看；内容编辑态；审核、置顶/取消置顶、删除 | 封禁切换、隐藏切换、通过审核、删除 | 置顶仅对符合条件的顶层正常评论开放；单向审核不得暗示可撤销。 |

| 文件 | 查看元数据与受权引用；状态专题；恢复、移入回收站、永久删除 | 审核通过、封禁、切换公开、移入回收站、恢复、永久删除（按视图） | 引用需独立 capability；审核与公开是不同命令，可能部分成功；删除与恢复保持状态和确认约束。 |
| 角色 | 查看；基础字段编辑态；授权专题；删除 | 删除自定义角色 | 系统角色及 root 保护不变；授权单独保存，未知分类不可写。 |
| 权限目录 | 只读查看 | 无 | 服务端定义，不制造编辑和批量入口。 |
| 举报 | 查看证据和历史；处理态更新状态、追加备注 | 无已核对批量契约 | 状态变更与备注是独立命令；处理结论按业务规则收集；举报人和目标链接到各自详情。 |
| 审计 | 只读查看 | 无 | 脱敏和引用权限保持服务端边界。 |
| 处理任务 | 查看结果与错误；符合状态时确认重试 | 无 | 重试是独立命令，不是“编辑任务”；事件事实引用进入稳定详情页。 |

具体副作用必须写进确认与验收：用户批量状态翻转会撤销会话并触发既有通知；卡片/评论审核为单向通过，相关治理动作可能清理置顶；标签审核可双向翻转；文件审核/封禁为定向设置、公开状态为翻转，永久删除还受引用和异步清理约束。展示层不得从统一的 `status` 字段推断这些行为。

Session 撤销、升级计划推进/批准/恢复属于局部表的专门命令，不虚构资源详情页；多动作时可复用宽度收放。通知和主动提示策略仍原位编辑并统一保存。队列、依赖、处理器目录纯诊断；主题与渠道目录不是表格。

**代码核查索引（2026-11-19）**：10 个资源列表位于 `pages/apps/users/index.vue`、`pages/apps/content/{cards,comments,tags}/index.vue`、`pages/apps/settings/storage/files/index.vue`、`pages/apps/access/{roles,permissions}/index.vue`、`pages/apps/community/reports/index.vue`、`pages/apps/operations/{audit,deliveries}/index.vue`。批量命令见用户、卡片、评论、标签、文件、角色列表的 `BaseTableBatchOptions` 与对应 SDK 调用；单条动作、确认和权限需同时核对详情页与模块组件。上述路径相对 `apps/admin/`，表格现状不是目标设计。

## 8. 设计复审：复杂度与熵增边界

| 选择 | 代价判断 | 最终约束 |
| --- | --- | --- |
| 页面与弹窗各自读取、各造表单 | 权限、草稿与保存随资源数双份维护 | 模块内一份详情主体与编辑逻辑；页面/弹窗只作容器，业务专题按真实保存范围拆分。 |
| 把整张 Nuxt 页面嵌弹窗或建设全局详情引擎 | 路由、焦点、响应式及业务分支耦合 | 复用资源内容组件，不复用页面壳；不按 schema 自动生成所有资源。 |
| 把审核、封禁等命令当普通字段编辑 | 状态机、确认、通知及部分成功语义丢失 | 字段草稿与资源命令分离；模块内声明单条/批量范围并按实际契约复用。 |
| 将所有批量动作复制到每行或让宽屏无限外露 | 行尾喧宾夺主，且部分命令没有等价单条语义 | 行尾只声明适合当前任务的单条动作；批量动作留在选中区；可读列宽优先，溢出进入“更多”。 |
| 每行测量动作或建立全局动作注册表 | 布局反馈和业务耦合随行数增长 | 每表一次容器观察，业务动作留在模块，呈现层只算容量。 |
| 全局返回状态和复制列表查询 | 来源失效及权限变化难收敛 | 经校验 history state 与规范列表兜底；URL 是列表查询的唯一来源。 |

新抽象必须消除页面与弹窗真实重复的读取、字段、权限或保存逻辑。迁移一个资源时移除它的旧双轨入口；只读资源不造编辑器，纯诊断表不造操作列。保留 SDK、capability、后端状态机和审计边界。

## 9. 实施顺序与验收门禁

1. **校正已上线样板**：先以卡片验证同一详情主体在独立页和列表弹窗的查看/编辑切换、媒体副作用和审核/置顶命令；现有用户“只读查看弹窗＋另开编辑弹窗”改为同一主体，保留 root 目标保护。旧实现提交保留历史，最终代码移除双轨。
2. **复核动作契约**：逐资源列出单条与批量 SDK 方法、capability、状态条件、确认、通知和结果；不因批量接口存在就生成单条入口。行尾优先级依据实际任务，不固定成“查看→编辑→删除”。
3. **逐资源迁移**：评论、标签、举报、角色、文件、审计、任务按第 7 节各做一个垂直切片；只读资源复用查看主体，复杂专题保留独立保存范围。标签/文件先建立稳定详情页再切换关联链接。旧 `?inspect` 与 `/usage` 保留必要单向兼容并记录删除条件。
4. **收束共享呈现**：`AdminResourceTableShell` 与行操作组件只负责宽度档位、按钮/菜单、可访问性；模块负责动作权限和执行。每表观察一次容器，不逐行测量。宽度足够时逐项外露适合行尾的动作，字段可读性优先。
5. **验收与清理**：逐页核对 URL、权限、状态、新鲜度、混合批量结果、未保存保护、部分成功、键盘焦点、390px/200% 缩放与浅/深色。运行 `npm run check`、`npm run build:admin` 和隔离管理端 E2E；人工截图审查仍须单独完成，不能由构建替代。共享 dev 数据库不运行写入 E2E。

目标影响范围为 10 个资源列表、各自详情页/模块组件、表格行操作呈现、关联资源链接、相关 E2E 与截图审查。5 个局部/诊断表只核对实际命令；2 个策略表不因本方案重写。任何新增 API 字段、状态转换或通知行为另行审查。完成标准是页面与弹窗同一资源事实/编辑规则、动作覆盖实际业务命令且无伪入口、旧双轨移除、检查通过并可供人工审查。

2026-11-18 按实际 `<v-data-table>`／`<v-data-table-server>` 使用点普查，共 17 张表；事件明细的展开列表另按同一操作与刷新语义检查。设计复核不能只抽查举报页，也不能把构建通过视为美观通过。

| 表格范围 | 实际使用点 | 审查重点 |
| --- | --- | --- |
| 资源列表（10） | 用户、卡片、评论、标签、文件、角色、权限、举报、审计、处理任务 | 页头唯一刷新；所有宽度表头横向、字段独立成列；ID 可选且默认隐藏；当前行操作打开弹窗；宽度容纳时逐项外露，空间不足才出现“更多” |
| 局部与诊断表（5） | Session、升级计划、队列分布、通信依赖、处理器目录 | 所属区块刷新范围明确；无详情时不造假入口；升级/Session 的真实多动作可按表格宽度收放 |
| 可编辑策略表（2） | 通知策略、主动提示策略 | 开关与统一保存区保持原行为；未保存修改时刷新禁用并说明；长说明不挤压表头 |
| 展开列表（非表格） | 事件明细及关联处理任务 | 当前条件刷新保留上次结果并标注新鲜度；条件切换清除旧结果；任务链接目的地明确 |

视觉验收以 [图 1](assets/admin-ui-reference/01-workbench.png) 的克制、平面和紧凑层级为准：行尾首个按钮有清楚的轻量形状，其他动作和“更多”逐级降低强调；关联链接不伪装成按钮；页头刷新与表格工具区分层；表头保持一行且有足够呼吸空间。每张表分别在 1440、960、600、390px 和等效 200% 缩放下检查浅色、深色、键盘焦点、长文本、空态与加载/刷新失败，并在相同视口改变表格容器宽度、列设置和权限。宽表只允许表格内部横向滚动；截图人工审查文字密度、留白、对齐和视觉重心，不能仅以“无溢出”通过。

实现依据：Vuetify 3 的 [Data table](https://vuetifyjs.com/components/data-tables/) 支持列级宽度和表头配置，[按钮变体](https://vuetifyjs.com/components/buttons/) 提供语义层级，[Dialog](https://next.vuetifyjs.com/en/components/dialogs/) 提供滚动内容与不同宽度的呈现能力；[W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)要求弹窗管理焦点和背景交互。外部规范只提供组件能力与交互参考，最终外观以本仓库图 1 和上述规则为准。
