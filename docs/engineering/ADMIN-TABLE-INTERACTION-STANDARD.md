# 管理端列表与表格交互规范

> 状态：2026-11-19 按实际代码完成入口与操作列复审，双形态详情和宽度响应操作列为待实施目标。2026-11-18 的云端 dev 迁移是历史基线，不能作为本次目标已完成的证据；人工审查与隔离环境全量 E2E 尚待完成。
>
> 范围：`apps/admin` 的资源列表、详情内嵌表、运行诊断表和可编辑策略表。页面宽度与区块顺序遵守 [页面布局规范](ADMIN-LAYOUT-SYSTEM.md)，颜色与 Vuetify 原生外观遵守 [UI 风格锁定](ADMIN-UI-STYLE-LOCK.md)，API 与权限边界遵守 [管理端架构](ADMIN-ARCHITECTURE.md)。本文负责表格内部的信息、导航和操作语义；与旧的 IA 草案、UI 审查记录或表格查询建议冲突时，以本文为准。

## 1. 目标与不变量

管理员扫一行时，先识别对象和状态，再在行尾找到下一步。**字段负责阅读，操作负责行动**。查看当前记录、跳到关联对象、修改当前记录、执行危险动作必须有不同且可预期的入口。

- 不因统一 UI 增加无效搜索、筛选、排序、批量操作、保存视图或详情页。控件必须对应真实 API、当前权限及明确任务。
- 不改变后端业务语义、权限范围或通知/审计规则；前端隐藏操作不是授权校验。
- 资源列表在整个页面只保留一处结果数、一处检索区和一个表格表面。不同业务可选择不同筛选字段，但位置、层级和反馈一致。
- 表格身份列不承担隐蔽导航；整行默认不可点击。不得靠 ID、颜色或图标猜测入口。列表里的“查看”“编辑”“审核”等针对**当前行**的入口打开弹窗；只有明确前往**另一资源**的引用链接才导航。
- 每种可被引用的资源有可直接打开和刷新的详情路由；列表操作使用同一资源的弹窗形态。页面和弹窗共用事实内容、编辑规则与权限判断，不建立两份数据与业务流程。
- 浅色、深色使用同一信息层级、交互和状态含义；不得为夜间模式另造表格布局。

## 2. 表格类型

| 类型 | 适用场景 | 容器与分页 | 行内入口 |
| --- | --- | --- | --- |
| 资源列表 | 用户、卡片、评论、标签、文件、角色、权限、举报、审计、处理任务 | `AdminPageContainer fluid` 内一个 `AdminResourceTableShell`；后端分页按真实契约 | 行尾显示当前行的弹窗操作；可用宽度不足时依优先级收入“更多” |
| 局部只读表 | Session、升级计划、队列分布、运行依赖、处理器目录 | 所属详情/运行区块内原生 `v-data-table`；小数据量可无分页 | 有后续页面才给明确文字入口；纯诊断表不造“详情” |
| 可编辑策略表 | 通知与主动提示策略 | 所属配置区块内原生表格；少量规则可无分页 | 原位开关或字段只负责编辑；统一保存区负责提交，危险变更另确认 |

事件事实的展开列表是“主对象＋关联处理任务”的层级视图，不强行改成扁平表格。它的筛选、总数、展开语义和任务链接仍按本规范的可读性、单一入口及 URL 规则验收。主题与渠道目录等卡片目录不伪装成表格。

## 3. 资源列表的固定阅读顺序

```text
页面标题、用途说明                                  [页级主动作]
可选上下文摘要
┌─────────────────────────────────────────────────────────────┐
│ 搜索 / 常用筛选 / 查询             结果数  [视图设置（按需）] │
│ 已生效条件（仅有条件时）                 [清除/恢复条件] │
│ 已选 N 项与批量动作（仅选中且有相应权限时）                 │
├─────────────────────────────────────────────────────────────┤
│ 资源身份       核心业务字段      状态      时间      操作   │
│ 对象摘要       辅助说明          明确文案  统一格式  查看  ⋯ │
├─────────────────────────────────────────────────────────────┤
│ 每页行数                                           分页     │
└─────────────────────────────────────────────────────────────┘
```

页级动作如创建、上传和刷新放页头；10 个资源列表均有同一位置、带文字和刷新图标的“刷新”，保持 `outlined` 次级语义，不能因为页面没有创建动作就升为主按钮，也不能再在表格工具区重复放第二个刷新。刷新只重读当前已生效查询和当前页；初次加载失败的“重试”属于错误反馈，不代替常驻刷新。局部表只刷新自身时，入口放所属区块标题侧；配置表存在未保存修改时保留入口、禁用并说明原因，不得默默丢弃修改。事件管理的运行状态、事件明细和注册能力分别刷新自身数据，标签切换后入口与当前可见内容一致。搜索与最常用的一两个筛选在工具区；多字段、低频筛选可以在同一区的折叠区或明确命名的弹窗内，审计允许两行。结果数在工具区靠操作侧显示，加载或请求失败时不得把旧结果默认为零。已生效条件应可读、可逐项清除；清除查询条件回到第一页且不清列偏好。

排序只有服务端支持的列才显示表头排序；若另有“搜索与排序”弹窗，它与表头必须读写同一状态。当前排序方式需要可见，例如表头方向或条件摘要；不能把一个隐藏排序留在 URL 而页面毫无提示。分页、每页行数、搜索、筛选和排序进入 URL；列设置按需启用，保存视图只在复合查询或重复工作流确有价值时启用，二者不能捆绑出现。偏好按当前管理员隔离，管理员身份未确定前不写浏览器持久化。没有相应能力时省略控件，不放禁用的假入口。处理任务可保留高频状态切换，审计可保留多字段查询，但它们仍在同一表格壳内。

现有资源列表已经提供的命名视图及浏览器内偏好在迁移时保留，不静默删除用户数据；是否给新增列表开放“保存视图”由该页任务决定。保存和应用视图只接受页面声明的搜索、筛选、排序、每页行数和列键；`page`、`inspect`、返回来源及其他临时参数不进入视图。读取旧视图时先过滤未知键和值，不能把旧存储中的任意 query 原样写回路由。

文本搜索保留输入草稿，按 Enter 或明确的“查询”按钮才提交；清空已提交关键词立即重新查询。常用单项筛选和表头排序在选择后立即生效；多字段筛选面板统一由“应用”提交，关闭面板不改变已生效条件。任何已提交的查询条件或每页行数变化都回到第一页，翻页保持条件。URL 只反映已生效条件，输入草稿和临时行选择不写入 URL；更新查询使用路由替换，列表弹窗不改 URL，跨资源详情链接使用正常导航，避免每次输入都堆出浏览器历史。

每个列表声明自己的默认查询基线，区分搜索/筛选、排序、每页行数和列偏好。只有已生效的搜索或筛选偏离基线时才显示筛选重置入口：无默认过滤条件时用“清除筛选”回到无条件列表；有默认过滤条件时用“恢复默认筛选”回到可见的默认状态，例如处理任务的通知队列与失败视图。两者不改变排序、列偏好和每页行数。“恢复默认视图”才同时恢复默认查询基线、列偏好和每页行数，不删除已保存视图；已保存视图应用时从第一页开始，不以整页重新加载实现。

| 请求场景 | 行、结果数和操作 | 反馈 |
| --- | --- | --- |
| 首次加载或已生效查询、页码变化 | 清除上次查询的行和临时选择；结果数暂不显示；行操作不可用 | 表格内显示加载状态，成功后才显示本次结果或空态 |
| 当前查询刷新 | 保留本次查询的行供阅读，临时禁止写入类行操作与批量操作；当前行的只读查看弹窗可用且重新读取当前对象；旧结果数标明为“上次结果” | 显示“更新中”；成功后更新行与结果数 |
| 当前查询刷新失败 | 保留上次成功结果供只读排查，继续禁止写入类操作；旧结果数仍标明为“上次结果” | 显示错误与重试；首次加载失败只显示错误，不显示零结果 |

并发请求只接受最新已生效查询的响应；状态、行和结果数必须同时切换，不能让旧请求覆盖新条件。服务端最终仍独立验证每项操作的权限与状态。

## 4. 列与字段的显示规则

默认列从左到右为：资源身份、支撑判断的业务字段、状态、时间、操作。一般保留 5–8 个核心列，简单目录可以更少；不为凑列数加入无意义字段。可选诊断列仍服从字段格式；ID、IP、request/correlation ID、原始 payload 和内部版本优先放详情诊断区或列设置，不占用默认阅读顺序。没有独立资源身份的审计记录，以“动作＋操作者”作为主信息。

| 字段语义 | 列表显示 | 细节与空值 |
| --- | --- | --- |
| 身份 | 名称、用户名、文件名或内容摘要为主；编号为弱化辅助文字 | 长内容最多两行，全文在详情；没有名称时用“资源类型 #编号” |
| 关联资源 | “用户 #编号”“卡片 #编号”等可读文字 | 默认在当前资源的页面或弹窗详情中给指向关联对象独立页的语义链接；列表有明确高频跨资源任务时，可在纯文字旁另放“查看作者”等命名链接，不把整项字段伪装成按钮 |
| 状态 | 明确中文状态词，成功/正常可用中性文字，需注意/失败用语义芯片 | 同一状态在同一业务域复用一份映射和一种组件；颜色与图标只是辅助；未知值显示“未知状态”，不能猜测为正常 |
| 时间 | 可确认格式的时间统一显示 `YYYY-MM-DD HH:mm`；需要秒的审计/诊断才显示秒 | API 明确时区且站点时区可得时才转换；无时区的标准日期时间只调整显示格式，不改变年月日和时分。格式未知时显示服务端原值并提示“时间格式未知”。只有时区语义明确时才给 `<time>` 的 `datetime` 写机器可读时间；空值为“—” |
| 数量/金额外数值 | 按数值对齐，带单位或含义 | 不用芯片装饰普通数字；空值与零必须区别 |
| 长文本/错误 | 可读摘要，按词或标点断行；必要时截断并给完整详情 | 不让长码撑破页面，也不将业务正文压成不可读的窄列 |
| 技术标识 | 等宽或次级文字，支持复制时给明确复制操作 | 不用彩色芯片伪装状态；敏感字段遵守脱敏与权限契约 |

单元格空值统一为“—”，但“未配置”“未执行”“不适用”“读取失败”各有不同业务含义时须分别写明。搜索命中高亮只标示匹配片段，不改变链接、状态或权限语义。

## 5. 点击、详情与操作的边界

### 5.1 行尾操作

- 当前行的“查看”“编辑”“审核”“更新状态”“删除”等都是**按钮动作**，在原列表上打开该资源的查看/编辑弹窗或确认层；不再用“查看详情”超链作为列表默认入口。列表的 ID、身份文字和整行保持纯阅读。需要导航到关联对象时，在当前对象的详情内容中或确有高频跨资源任务的列表辅助字段旁给明确命名的资源链接，不能把当前行主操作偷换成关联对象跳转。
- 每个资源声明有序的行操作集合，至少区分查看、编辑/审核、其他操作与危险操作。文案写对象和动词，例如“查看用户”“编辑卡片”“更新举报状态”；只有“查看”可能与行内上下文完全无歧义时才省略对象名。仅有一项可执行动作时不显示空的“更多”。权限与目标状态逐项过滤，不能因为操作收进菜单就绕过 capability 或把不可执行项当作可执行项。
- 列表行操作统一使用共享的 Vuetify 按钮外观：首个常用动作是低饱和 `tonal` 小矩形，其他外露动作使用中性色 `text`；统一 4px 圆角、字重、间距与焦点，不使用模拟超链的下划线、裸 `NuxtLink`、实底主色或一排彩色图标。危险动作在列表保持中性，最终确认才使用危险色。桌面点击区至少 32px 高，移动与等效放大时至少 44px；文字不折行、不缩小到难读。“更多”用三个点图标、可访问名称和提示，菜单项仍为完整文字动作。
- 只读查看在当前查询刷新失败时可以保留并标明旧数据；编辑、审核、删除、批量写入在结果不新鲜或加载中禁用。弹窗打开时独立重新读取当前对象，不能把列表摘要当作详情事实。

### 5.2 根据表格可用宽度显示操作

操作显隐由**表格内容可用宽度**和当前可见列决定，不以整个窗口、硬编码的 960/1280px 断点或每行文本长度决定。600px 的表格移动行断点仍按第 6 节执行；它不等于操作列的展开阈值。

1. 页面给操作稳定的优先级和完整文案。最窄可用状态保留一个当前行的常用操作及“更多”；能容纳时保留两个常用操作；只有在身份、状态、时间等可见列仍达到各自最小可读宽度，且操作列完整容纳所有允许的动作时才全部外露。不能为多露一个按钮把表头挤成竖排字或让动作被裁切。
2. “更多”仅收纳本行在当前宽度未外露的动作；从窄到宽只按优先级逐项移出菜单，宽度收缩时反向收入。菜单与外露区不重复同一动作，操作顺序、文案和确认方式不随宽度变化。若该行因权限或状态只有一项动作，外露该动作且不显示空菜单。最窄状态连主动作和菜单都放不下时，操作区占移动行的独立一行，桌面表格仅在自身滚动容器内横向滚动。
3. 宽度预算以表格滚动视口、选择列、当前可见列的最小宽度、操作文字的最大必要宽度和间距计算；列设置、侧栏展开、浏览器缩放、容器尺寸变化时重新计算。对同一张表使用一份布局档位，不能因某行权限不同导致操作列宽或行内位置跳动。实际能力按行过滤，空位不伪造按钮；计算要避免显示/隐藏按钮自身引起的来回抖动。
4. 行尾保持右对齐、单行、同一垂直基线；图标不是文字的替代。宽屏全显时，删除、恢复、重试等仍使用原有确认和权限规则；密集资源列表的视觉重心仍是对象和状态，而不是一排按钮。升级计划、Session 等局部表只在确有多个动作时复用此规则，纯诊断表不补操作列。

### 5.3 双形态详情与编辑

| 来源与意图 | 承载 | 地址与内容 |
| --- | --- | --- |
| 列表中查看、编辑、审核当前行 | 当前列表上的 `v-dialog`；窄屏可全屏 | 保持列表 URL、查询、页码和滚动；打开时按 ID 读取完整对象，可按动作直接进入查看或编辑态 |
| 举报、审计、评论、文件引用等内容中的关联对象；外部书签、刷新和直接访问 | 对象自己的独立 `/:id` 详情页 | 稳定可分享地址，页面默认可读；有权限时能在页内进入编辑态，复杂专题如账号安全保留受限子页 |
| 删除、撤销、永久清理等高风险一步操作 | 明确的确认层 | 说明目标、影响和可恢复性；列表弹窗内优先切换到确认视图，避免堆叠多个活动对话框 |
| 跨多资源、多步骤且弹窗无法完整审阅的流程 | 明确命名的独立流程页 | 需单独论证，不把普通“查看/编辑”悄悄改为页面跳转 |

两种形态采用**同一资源内容与编辑能力**：模块内共享对象读取、字段格式、权限与表单规则，独立详情页和列表弹窗只提供不同外壳、导航和焦点管理。不把整张带 `AdminPageHeader`、middleware 的页面嵌进 `v-dialog`，不嵌 iframe，也不建立全局通用详情引擎。页面默认展示完整内容，点击“编辑”在当前页切换到编辑区；弹窗的“查看”和“编辑”进入同一资源面板的不同初始态，查看态可以在授权后切到编辑态。保存成功同步当前对象并重读/更新来源列表；失败保留表单、错误和来源查询。后端仍独立校验所有写入。账号安全、文件引用、审计证据等有独立权限或专题语义的区块不能因共用外壳而扩大可见范围。

弹窗提供明确标题、对象身份、状态、关闭入口和固定动作区；长证据或表单用可滚动内容，390px 与等效 200% 缩放时全屏且不遮挡关闭/保存。未保存修改时，关闭、Esc、遮罩、切对象和离开路由均走同一离开保护；切到关联资源前先处理脏状态。打开时焦点进入标题或第一项有意义的内容，关闭后回到触发按钮；若原行已不在结果中，回到逻辑上相邻的操作或列表标题。一次只允许一个可交互的主要弹窗，危险确认切换视图或安全地交接焦点。页面直达与浏览器刷新不依赖曾打开列表。焦点与背景不可操作要求遵守 [W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

### 5.4 关联资源链接和旧地址

`AdminResourceLink` 只用于**从当前对象前往另一对象**，目标始终是该对象的独立详情路由；权限不足、类型未知或对象 ID 缺失时显示非交互文字。链接文字必须指明目标，例如“用户 #12”及其上下文标题；链接用语义锚点和常驻可识别的下划线/方向提示，不再渲染成带大图标、内边距和按钮背景的 `v-btn`。列表身份字段不借此变成隐蔽操作；评论列表的作者等确有高频跨资源管理任务的辅助字段，可在作者文字旁另给“查看作者”链接，链接目的地在视觉和可访问名称中明确。举报人/目标默认在举报详情中链接，避免重现三列都像按钮的噪声。卡片作者、审计操作者/目标、文件引用和事件处理任务也按任务频率与权限逐项核对。

卡片与评论已有真正的 `/:id` 页面；其历史 `?inspect=id` 仍按既有单向迁移到详情页，不能复活成第二个编辑地址。标签的 `/:id` 目前反向跳到列表 `?inspect=id`，须改为真正详情页；历史 `?inspect=id` 暂保留打开列表弹窗，并在站内引用、书签和 E2E 迁移后删除。文件目前只有 `/:id/usage` 专题页，须建立包含文件元数据与引用区的 `/:id` 详情页；已有 `/usage` 地址在迁移期可单向转到详情页引用区，`AdminResourceLink` 的文件/媒体目标改为 `/:id`。用户、角色、权限、举报、审计和处理任务的稳定详情地址保留。地址变更须同步导航契约、面包屑、权限和 E2E，不能用列表截断字段伪造详情。

列表弹窗保持列表 URL，临时打开对象 ID 和编辑草稿不进入已保存视图；明确需要可分享的对象地址时给“打开完整页面”链接到 `/:id`，并在离开保护后导航。跨资源跳转把经校验的当前内部来源留在本次 history state；返回时恢复来源查询、页码和可用的滚动位置，直接打开或来源失效时回规范列表地址。来源不能是外部 URL，不另建全局返回状态库。列表操作成功后若当前行不再属于筛选结果，应从本次结果移除并更新总数。

## 6. 响应式与可访问性

- 断点以视口 CSS 宽度为准。≥600px 使用横向列式表格，所有列标题保持单行、横向字序；列宽由字段角色和当前可见列决定，宽表只在表格容器内横向滚动。不得沿用不同页面各自的“自动在 1280px 变纵向”默认，也不得用固定 720px 最小宽度让 8 列挤成竖排字。排序图标与标题必须同处可读的表头单元格；设置 `nowrap` 时仍须给该列足够最小宽度，不靠视觉溢出遮盖相邻列。
- <600px 复用 Vuetify 数据表原生的“字段名＋值”移动行和移动排序控件，统一设置 `mobile-breakpoint` 为 600；字段名仍须单行横排，不得被长值挤成逐字竖排，长内容在值侧折行。只读局部表和可编辑策略表遵守相同断点。身份与状态优先阅读，操作仍在每条记录末尾；其余可见字段保持可访问，批量选择不能占据身份阅读位置。没有服务端排序能力的表不展示空的排序选择器；不能由各页面复制一套移动表格或另造卡片列表。
- Vuetify 原生的移动排序、分页范围、每页行数和无数据提示统一使用简体中文语言包；页面不得逐一覆盖翻译文案。
- 字段宽度建议：身份/正文摘要至少 240/320px，状态约 100–120px，时间约 170–190px，操作按文字与菜单实际宽度预留；长技术码采用可折行或省略加完整说明。可见列变化后重新计算总宽，不用单个全站 `min-width` 硬塞所有表。
- 表头保持横向文字，不使用竖排字形；窄列先保证中文词组可读，再让表格内部滚动。行高可随摘要合理增长，但同类状态、时间和操作对齐。
- 行操作的展开依据表格自身宽度预算；在相同 960px 视口下，侧栏、列设置或嵌入容器改变了表格宽度，也必须得到相应的操作布局。不得只用视口媒体查询决定“更多”的显隐。移动行保留一至两个常用按钮及按需出现的菜单，动作区可以独立成行。
- 键盘能到达查询、排序、当前行弹窗操作、跨资源链接和菜单；焦点明显；链接、按钮与纯文字语义一致。图标按钮必须有可访问名称和提示；只有颜色不同或仅靠悬停出现的动作不可接受。
- 核对 1440px、960px、600px、390px、等效 200% 缩放、浅色和深色，并增加同视口不同表格容器宽度、列显隐和权限组合。不得出现页面级横向溢出、表头逐字竖排、操作被裁切、弹窗不可关闭或缩放后无法读到字段值。

## 8. 实施顺序与验收门禁

1. **先做双形态样板**：以用户（可编辑）、举报（证据＋处理）和审计（只读）验证列表弹窗与独立页共享内容、列表 URL 不变、跨资源引用跳转、关闭焦点、保存失败和权限边界。卡片/评论随后验证内容编辑和旧 `inspect` 迁移。不得先批量替换 10 个“查看详情”链接。
2. **收束行操作层**：建立一份仅负责按钮外观、动作优先级、宽度预算和菜单显隐的共享能力；业务模块声明动作、权限、状态与执行函数。它不读取 SDK、不持有业务数据、不承包搜索/分页。使用表格容器和列宽事实计算档位，固定一张表的列宽；避免十页复制 `ResizeObserver`、菜单逻辑或再造表格引擎。首个切片在同视口不同容器宽度下证明一项、两项、全显三种状态。
3. **逐资源迁移**：按第 7 节清单，每次一个垂直切片完成列表弹窗、详情页编辑、关联链接、权限、旧地址和 E2E；新旧查看/编辑逻辑不得长期并行。标签和文件需要先建立真正资源详情，才能切换关联链接。保留已有的 600px 表格断点、查询 URL、结果新鲜度与夜间 token。
4. **复核兼容与清理**：对 `?inspect`、文件 `/usage`、旧 `AdminResourceLink` 目标及原行尾链接分别记录站内调用方、外部书签风险和删除条件；只保留必要的单向兼容入口。移除重复表单、无用菜单与页面级操作列宽度覆盖。

当时的人工审查仍须复核浅色模式、200% 缩放、各资源的权限组合、弹窗焦点与未保存离开保护。旧 `?inspect` 单向重定向由管理端维护者负责；确认外部书签、测试与站内引用都已迁往 `/:id` 后，在单独的兼容清理变更中删除。2026-11-19 的新增目标另按第 8 节验收，不能沿用本节的通过记录。

## 10. 表格视觉收束清单

2026-11-18 按实际 `<v-data-table>`／`<v-data-table-server>` 使用点普查，共 17 张表；事件明细的展开列表另按同一操作与刷新语义检查。设计复核不能只抽查举报页，也不能把构建通过视为美观通过。

| 表格范围 | 实际使用点 | 审查重点 |
| --- | --- | --- |
| 资源列表（10） | 用户、卡片、评论、标签、文件、角色、权限、举报、审计、处理任务 | 页头唯一刷新；表头横向；身份为文字；当前行操作打开弹窗；宽度容纳时逐项外露，空间不足才出现“更多” |
| 局部与诊断表（5） | Session、升级计划、队列分布、通信依赖、处理器目录 | 所属区块刷新范围明确；无详情时不造假入口；升级/Session 的真实多动作可按表格宽度收放 |
| 可编辑策略表（2） | 通知策略、主动提示策略 | 开关与统一保存区保持原行为；未保存修改时刷新禁用并说明；长说明不挤压表头 |
| 展开列表（非表格） | 事件明细及关联处理任务 | 当前条件刷新保留上次结果并标注新鲜度；条件切换清除旧结果；任务链接目的地明确 |

视觉验收以 [图 1](assets/admin-ui-reference/01-workbench.png) 的克制、平面和紧凑层级为准：行尾首个按钮有清楚的轻量形状，其他动作和“更多”逐级降低强调；关联链接不伪装成按钮；页头刷新与表格工具区分层；表头保持一行且有足够呼吸空间。每张表分别在 1440、960、600、390px 和等效 200% 缩放下检查浅色、深色、键盘焦点、长文本、空态与加载/刷新失败，并在相同视口改变表格容器宽度、列设置和权限。宽表只允许表格内部横向滚动；截图人工审查文字密度、留白、对齐和视觉重心，不能仅以“无溢出”通过。

实现依据：Vuetify 3 的 [Data table](https://vuetifyjs.com/components/data-tables/) 支持列级宽度和表头配置，[按钮变体](https://vuetifyjs.com/components/buttons/) 提供语义层级，[Dialog](https://next.vuetifyjs.com/en/components/dialogs/) 提供滚动内容与不同宽度的呈现能力；[W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)要求弹窗管理焦点和背景交互。外部规范只提供组件能力与交互参考，最终外观以本仓库图 1 和上述规则为准。
