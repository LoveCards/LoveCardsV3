# 管理端 UI 风格锁定（图 1 基线）

> 状态：已确认，施工阶段必须遵守
>
> 确认日期：2026-08-23
>
> 唯一视觉基线：[01-workbench.png](assets/admin-ui-reference/01-workbench.png)

## 1. 决策摘要

图 1 作为 LoveCards 管理端的唯一外壳和视觉风格基线。它表达的是“长时间工作的可信控制台”，不是营销页面，也不是深色监控大屏。

### 图 1 决定的内容

- 白色顶部应用栏。
- 白色/冷灰侧栏，当前菜单用 Indigo 背景或浅 Indigo 选中面表达。
- Indigo 只承担品牌、当前选择、链接和主要动作，不做大面积装饰。
- 白色任务表面、浅灰分区和细分隔线。
- 页面以标题、表格、详情分区和时间线为主，不用重复的装饰卡片。
- 状态用文字 + 图标 + 语义色表达；颜色不能单独承担语义。
- 紧凑但可读的桌面工作密度，中文文案优先。

### 其他参考图的优先级

`02-card-list.png`、`03-report-detail.png`、`04-channel-config.png` 只用于参考列表、详情、审计和配置的结构。它们生成时可能出现蓝色顶栏、不同菜单名称或额外入口，这些视觉和导航差异全部以图 1 与信息架构文档为准，不得照搬。

## 2. 场景与视觉性格

**场景句：** 内容运营、安全审核和系统运维人员在明亮的桌面办公环境中连续处理高密度任务，需要快速判断状态、影响和下一步动作。

**视觉性格：** 可信、克制、清晰、高效；熟悉的工具感优先于个性化装饰。

**色彩策略：** Restrained。Indigo 是唯一品牌强调色，语义色只表达状态。

## 3. Token 基线

以下 token 是施工时的默认值；如需调整，必须先更新本文件和 `apps/admin/DESIGN.md`，不能在单个页面临时覆盖。

| Token | 值 | 用途 |
| --- | --- | --- |
| `primary` | `#3F51B5` | 顶部品牌、当前导航、主按钮、可操作链接 |
| `primary-strong` | `#303F9F` | hover/pressed/高对比操作 |
| `primary-soft` | `#E8EAF6` | 当前项背景、轻量提示、选中标签 |
| `surface` | `#FFFFFF` | 页面和主要内容表面 |
| `surface-muted` | `#F5F5F5` | 侧栏分区、工具栏、次级面板 |
| `divider` | `#E0E0E0` | 表格、表单和区块分隔 |
| `ink` | `#212121` | 标题、正文和数据 |
| `ink-muted` | `#5F6368` | 辅助说明、时间和次级信息 |
| `success` | `#43A047` | 成功、正常、已完成 |
| `warning` | `#FF9800` | 待处理、注意、即将过期 |
| `error` | `#F44336` | 失败、危险、阻断 |
| `info` | `#2196F3` | 信息、同步、降级说明 |

几何和密度：

| Token | 默认值 |
| --- | --- |
| `topbar-height` | `64px` |
| `sidebar-width` | `264px`（可收缩到 `72px`） |
| `content-max-width` | `1280px`，超宽屏保持可读边距 |
| `radius-sm` | `4px`，按钮/输入 |
| `radius-md` | `8px`，常驻区块 |
| `radius-lg` | `12px`，复杂详情分区上限 |
| `space-unit` | `4px` |
| `control-height` | `40px`，密集表格可用 `36px` |
| `transition` | `150–250ms`，只表达状态变化 |

字体继续使用 `Roboto, system-ui, sans-serif`，不引入展示字体；标题字号固定，不使用随视口缩放的 `clamp()`。

## 4. 应用壳规范

### 4.1 顶部应用栏

- 背景白色，底部一条细分隔线。
- 左侧为菜单控制、LoveCards 品牌字标和环境徽标。
- 中间允许全局搜索/命令入口，但不能抢过当前页面标题。
- 右侧依次为通知、帮助、角色/账号菜单。
- 生产环境显示明确环境徽标；本地和测试环境不得伪装成生产。

### 4.2 侧栏

- 默认浅色，不使用整条高饱和 Indigo 背景。
- 一级域使用图标 + 中文名称；有子项时显示展开状态。
- 当前域通过浅 Indigo 选中面、Indigo 图标和文本共同表达。
- 当前页面的二级项保持可见；详情页自动展开父域。
- 没有 capability 的域、分组和徽标都不渲染。
- 窄屏切换为临时抽屉；收缩后仍保留可访问名称和 tooltip。

### 4.3 主内容区

- 页面背景为白色或极浅冷灰，内容表面不依赖阴影分层。
- 页面标题只出现一次，下面紧跟用途说明和面包屑。
- 桌面端采用 12 列布局；列表优先全宽，详情和配置按 8/4 或 7/5 分栏。
- 不使用固定 `82%` 之类的页面宽度；容器由 max-width、边距和断点决定。

## 5. 组件风格

### 按钮

- 一页只保留一个主要 Indigo 实底动作。
- 次要动作使用 outlined/text，危险动作在确认阶段才使用红色。
- 文案优先，图标作为辅助；图标按钮必须有 tooltip 和 `aria-label`。
- loading、disabled、success 和 error 状态必须可见且不会重复提交。

### 表格

- 表头使用浅灰背景或细分隔线，不使用厚重阴影。
- 关键列：资源身份、状态、操作者/作者、时间、下一步动作。
- ID、IP、correlation id、原始 payload 等放详情的诊断区。
- 行操作使用文字或带明确名称的菜单；批量操作按动作 capability 单独过滤。
- 选择、分页、筛选和排序状态可通过 URL 恢复。

### 区块与卡片

- 常驻区块使用平面表面 + 单一边界；不做“卡片套卡片”。
- 统计区块只服务于待办判断，禁止装饰性大数字墙。
- 表单分为基础、业务、高级三层；高级内容默认折叠。
- 时间线、状态芯片、错误提示和空态复用同一套组件。

### 状态芯片

- 文案必须直接说明状态，例如“待审核”“已隐藏”“投递失败”。
- 图标和颜色辅助文字，不以颜色作为唯一依据。
- 状态颜色不用于装饰模块或非语义标签。

## 6. 页面模板视觉要求

| 模板 | 图 1 风格下的固定结构 |
| --- | --- |
| 工作台 | 标题 → 待办列表 → 健康摘要 → 最近变更；不使用英雄指标区 |
| 资源列表 | 标题/主动作 → 上下文摘要 → 筛选工具栏 → 高密度表格 → 分页 |
| 资源详情 | 面包屑 → 身份/状态/主动作 → 证据或核心信息 → Tabs → 审计时间线 |
| 配置详情 | 面包屑 → 配置身份 → 基础/安全/高级分区 → 测试结果 → 固定保存栏 |
| 危险操作 | 资源、影响范围、原因、可恢复性、审计提示和明确确认动作 |

## 7. 可访问性和响应式锁定

- 正文与背景达到 WCAG AA 对比度；焦点轮廓始终可见。
- 状态至少由文字和图标/形状中的两种方式表达。
- 所有可操作控件支持键盘访问；抽屉和对话框正确管理焦点。
- 窄屏保持页面标题、筛选和主动作可见；表格允许横向滚动，不强行压缩到不可读。
- `prefers-reduced-motion: reduce` 下不播放装饰动画。
- 生成图片不作为无障碍或响应式验收依据，代码必须单独验证。

## 8. 禁止偏离

施工中不得引入以下风格偏差：

- 深色全屏后台、整条高饱和蓝色侧栏或渐变背景作为默认主题。
- 玻璃拟态、渐变文字、装饰性图表、重复大数字指标。
- 32px 以上的大圆角、厚重阴影、彩色侧边条。
- 每个页面一套不同的表格、按钮、状态芯片或确认对话框。
- 将技术字段直接平铺在主表格，或用无文字图标隐藏关键动作。

## 9. 施工验收门槛

第一批页面完成后，必须逐项对照图 1 和本文件检查：

1. 顶栏、浅色侧栏、当前项和主内容层级一致。
2. 主色只用于导航选择、主要动作和可操作链接。
3. 表格、表单、详情、时间线和危险操作使用统一组件语法。
4. loading、empty、error、403、degraded 和 dirty 状态都有可见设计。
5. 桌面和窄屏都保持可读，键盘和减少动态效果可用。

任何需要改变外壳颜色、字体、圆角或密度的请求，都必须先更新本风格锁定文件，再进入代码修改。
