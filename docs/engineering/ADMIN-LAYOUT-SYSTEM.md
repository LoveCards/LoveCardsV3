# 管理端页面布局规范

> 适用范围：`apps/admin` 的规范路由；菜单名称和归属仍以 `ADMIN-NAVIGATION-CONVENTION-2026-11-07.md` 为准，颜色与原生组件规则仍以 `ADMIN-UI-STYLE-LOCK.md` 为准。列表内部的列、字段、断点、入口和弹窗边界以 [列表与表格交互规范](ADMIN-TABLE-INTERACTION-STANDARD.md) 为准。 子页面的类型、容器与覆盖范围以[子页面设计规范](ADMIN-SUBPAGE-DESIGN-STANDARD.md)为准。

## 目标

管理员在不同页面间切换时，标题、主任务、辅助信息和操作区应出现在可预期的位置。统一的是页面骨架和信息层级，业务字段、权限及后端行为仍由各页面决定。图 1 工作台是外壳视觉基线；其他参考图只补充内容结构，不覆盖现行菜单、配色或权限。

## 共用外壳

- `layouts/default.vue` 负责顶栏、侧栏、主内容 gutter 和移动抽屉；页面不得再建立第二套布局。
- 每个规范页面用 `AdminPageHeader` 承载面包屑、唯一 `h1`、用途说明和页级操作。标题与内容必须处于同一个 `AdminPageContainer` 宽度体系内。
- 内容边距由外壳统一提供。页面只用 Vuetify 间距类表达局部层级，不设置百分比页面宽度或逐页硬编码内容 gutter。
- 桌面端列表使用 `AdminPageContainer fluid`；工作台使用 1280px 阅读宽度；资源详情与系统运行页使用 1040px；配置表单与驱动详情使用 960px。窄屏均自动占满可用宽度。
- 主区块间距以 24px 为准，标题与紧接内容为 24px，区块内使用 16px。独立反馈与其所属区块放在一起，不再用孤立的提示卡打断页面。

## 四种页面骨架

### 工作台

2026-11-27 确认基线：先显示“我的待办”，桌面端待办入口为双列，整行可导航，数量为零仍保留“查看”入口；仅呈现当前账号获授权且可访问的任务。业务概览和运行状态在下方左右并排，各自保持自然高度；当前异常横跨两列。窄屏不超过 680px 时按待办、当前异常、业务概览、运行状态排序，DOM 与视觉阅读顺序一致。职责入口、通知统计、最近变更和产品公告收进末尾的原生折叠区，展开后才请求辅助统计与审计；职责默认三个入口，按需展开其余。

- 数据只来自现有 SDK 的 dashboard 和 operations runtime 接口。没有接口的 CPU、内存、磁盘及历史异常趋势暂不展示，不用演示数据补齐生产页面。
- 业务汇总只展示响应中存在的获授权指标；总量采用等大数字和同一基线。指标选择切换单条“每日新增”趋势，默认展示后端提供的最近六天（截至昨日），不添加接口未支持的时间切换或环比。图表使用主题 primary、零基线、整数友好刻度、直线和可展开的数据表；缺失值不补零，不跨缺失点连接，不播放图表动画。
- 运行状态同时说明消费模式、消费健康、通信模式和通信健康。状态不可用或切换中不得标成正常；待处理大于零本身不是异常。仅展示接口提供的队列数量、等待时长、租约和 Worker 信息，通信检查时间与客户端读取时间分开标注。
- 当前异常按问题类型汇总，数量单位为“类”；来源为消费异常、通信异常、死信和过期租约。全部队列死信数量必须导航到 `deliveries?queue=all&view=dead`，不能落到默认通知队列。明细入口另按 `communications.read` 判定，不能因持有 `operations.read` 暴露越权链接。已有运行摘要权限时，死信不再重复放入待办。
- 业务与运行状态并行读取、独立失败、独立重试。首次失败不展示伪造零值；刷新失败保留上一份成功快照和读取时间并明确标注旧数据，不能宣称当前正常。顶部只在快照存在异常时显示关注提示，健康提示留在运行状态内。

### 资源列表

顺序固定为页头、可选上下文摘要、一个 `AdminResourceTableShell`。搜索、状态筛选、结果数和视图设置位于表格壳工具区；表格内显示加载、错误和空态。批量动作仅在选中后出现。所有数据表在任何视口均保持横向列式；宽表在自身容器内横向滚动，页面本身不横向溢出。单元格不把不同字段上下叠放。具有专用业务筛选的列表可以使用 `toolbar` 槽，但不能在表格上下重复放结果数和筛选条。状态、筛选、排序和分页仍须遵守 URL 与权限契约。

### 资源详情

独立详情页是被引用对象的单记录管理地址，按页头、记录身份与当前状态、核心字段或证据、关联信息、历史与诊断组织；具备权限时可在原位编辑该记录。详情主体使用单一主表面，区块以统一标题、留白或细分隔线组织；同一页面相邻区块间距为 20–24px。具体字段、编辑和弹窗视觉以[详情与编辑视觉规范](ADMIN-DETAIL-EDIT-DESIGN-STANDARD.md)为准。证据、快照或审计详情可在区块内部使用双栏，但移动端必须回到单栏。请求标识、原始诊断字段等不应抢在资源身份之前。详情主体在独立页与列表弹窗中复用；查看态的可写字段可就地切换为编辑控件，资源命令另列操作区。危险动作仍由独立 capability 和确认对话框约束。

### 配置与系统运行页

配置页先说明当前对象与影响，再展示主要设置；测试、依赖和高级诊断位于其后。单一表单使用居中的 960px 内容宽度，不保留没有内容的 4 列空白。字段组可在表单内部双列，窄屏回到单列。保存范围通过 `AdminConfigSaveBar` 明示；桌面端保存区在滚动时保持可见，窄屏保存区位于表单末尾，避免遮挡字段。只读账号没有可执行操作时不显示空保存区。若页面有独立的“概况”和“诊断”信息，系统运行页使用 1040px 宽度，先给当前状态，再给修改入口与高级诊断。动态驱动字段按服务端 schema 渲染，不能为了视觉整齐更改提交语义。

## 已知例外与优先级

- 旧 URL alias 仅重定向，不承载第二套页面；不按旧页面结构验收。
- 处理任务列表沿用通知投递旧 URL，缺省仍筛选通知队列；它可以保留专用状态切换，但筛选位于共享表格壳内。
- 审计列表有多字段检索，允许两行筛选工具区；其结果表仍使用列表骨架。
- 小型诊断表、主题和渠道目录不强制套服务端列表分页。目录卡片仍遵守中性描边、相同标题和底部动作层级。
- 内容主导的卡片、评论列表保留正文优先。对象所属主列表的编辑、处理和必要只读查看在列表弹窗中挂载同一资源详情主体；非主列表引用及直接访问进入独立详情页并挂载同一主体。字段编辑与审核、封禁、隐藏、置顶等资源命令分开呈现。两种形态的内容范围和操作列的宽度响应按[列表与表格交互规范](ADMIN-TABLE-INTERACTION-STANDARD.md)实施；列表宽度和工具区位置仍遵守本规范。

## 变更验收

新增或调整管理页时，先按页面类型选骨架，再核对：桌面 1440px、窄屏 390px、等效 200% 缩放；标题与内容左边界、主次区块顺序、页面横向溢出、表格内部滚动、保存区遮挡、只读角色与失败状态。`check:architecture`、类型检查和现有 E2E 检查组件与行为；截图需要人工核对信息层级、留白和视觉重心，不能只以“无溢出”作为设计通过。
