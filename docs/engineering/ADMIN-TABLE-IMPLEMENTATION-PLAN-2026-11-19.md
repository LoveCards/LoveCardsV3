# 管理端表格交互更新实施方案（2026-11-19）

> 状态：设计方案，页面尚未按本方案改造。行为目标以 [列表与表格交互规范](ADMIN-TABLE-INTERACTION-STANDARD.md) 为准；本文件只确定当前代码基线、迁移顺序、实现边界和验收证据，不另立视觉或业务规则。

## 1. 基线与成功标准

当前 10 个资源列表使用 `AdminResourceTableShell`，身份字段已回到阅读语义。云端 dev 的用户样板仍是只读查看弹窗加独立编辑弹窗；卡片、评论等未完成的本地草稿也沿用旧模式。卡片与评论详情页另外打开编辑弹窗，标签详情反向跳列表 `?inspect`，文件只有 `/usage` 专题。批量区已有封禁、隐藏、审核、置顶、恢复、删除等真实命令，旧行尾方案却以查看/编辑/删除为模板，必须先校正动作语义。卡片列表响应已有 `username` 与 `user_id`，但可选列仍标为“用户ID”并只显示编号；标签关联已有本页目录映射。先用现有数据呈现“名称 #ID”，保持原字段 key 与查询契约。

完成时应能验证：同一资源详情主体在路由页与列表弹窗中读取和呈现一致；查看态可切入授权字段编辑态或专题处理态；列表操作不改变查询 URL；关联资源进入稳定详情路由；单条与批量命令按真实 API、权限和状态展示；表格自身宽度决定一项、两项或可容纳的行尾动作；混合批量结果、部分成功和上传副作用如实反馈。浅/深色、键盘、390px 和 200% 缩放均须可用。

本次不改变 SDK/API 字段、后端状态机、capability、通知、审计或事件队列。若现有契约不足，先独立核对与审查。涉及用户权益和内容审核的状态转换按 [通知规范](NOTIFICATIONS.md) 判断，前端不发布通知。

## 2. 最小实现边界

| 位置 | 增量责任 | 边界 |
| --- | --- | --- |
| 模块内 `*DetailContent` | 按 ID 读取，持有查看/编辑/处理模式、可写草稿、验证、保存、刷新及模块权限；只读事实始终可读 | 不承载路由页头或弹窗焦点；不做全局字段引擎。 |
| 独立详情页 | 稳定 URL、面包屑、返回、页面宽度，挂载同一详情主体 | 不再打开另一套编辑弹窗。 |
| 列表详情弹窗 | 对象身份、容器、焦点、关闭、滚动和脏状态拦截，挂载同一详情主体，可按入口初始进入编辑/处理态 | 不嵌 Nuxt page，不复制读取和表单。 |
| 模块动作声明 | 对单条/批量分别核对 SDK 命令、capability、状态、确认和结果；按任务频率选择行尾动作 | 不把批量命令自动变成单条命令，不把状态命令混入字段保存。 |
| 共享行操作与表格壳 | 每表一次容器宽度观察；按可见列最小宽度、行尾动作预算决定容量，统一按钮与“更多” | 不读取 SDK、不管理业务权限或查询，不逐行测量。 |
| 关联链接与来源导航 | 跨资源语义链接、经校验来源及规范列表兜底 | 不建立全局来源 Store，不让身份列隐藏导航。 |

卡片媒体、用户头像与角色分配、角色授权、文件状态等采用模块内独立保存范围；失败或部分成功只重读实际生效结果，不声称取消上传可回滚。危险资源命令保留确认；举报状态处理与追加备注分开。弹窗/页面共享的脏状态决策覆盖 Esc、遮罩、切对象和离开路由，同一时刻只允许一个主要弹窗可交互。

## 3. 垂直切片顺序

每个切片先固定旧入口、真实 SDK 命令和权限样例，再改同一资源的页面/弹窗/列表；验收后删除该资源旧查看或编辑双轨。共享能力只在真实重复点建立。

| 顺序 | 切片 | 验收重点 |
| --- | --- | --- |
| 1 | 卡片 | 用户指定的样板：正文预览切为可写字段，页面/弹窗共用主体；审核、封禁、隐藏、置顶、删除与字段编辑区分；媒体上传副作用明确。 |
| 2 | 用户 | 修正云端旧样板；资料查看/编辑共用主体，头像、角色和账号安全分范围；root/未知目标保护与批量状态命令不变。 |
| 3 | 评论、标签 | 各自独立切片复用详情主体；评论置顶资格与单向审核、标签状态命令保持真实语义；标签先有稳定详情路由。 |
| 4 | 举报、审计 | 举报证据只读，状态处理与追加备注为主体内明确子态；审计完全只读并保持脱敏。 |
| 5 | 文件、角色、权限 | 文件元数据/引用和状态命令分权限与保存范围；角色基础编辑和授权分范围；权限目录只读。 |
| 6 | 处理任务与局部表 | 重试、Session 撤销、升级计划推进/批准/恢复按专门命令和确认；诊断表不造假动作。 |

每个资源的行尾和选中区需同时审查：单条入口不一定等同批量方法；没有等价 API 时仅在详情/批量区保留现有动作。旧 `?inspect` 和文件 `/usage` 的兼容删除条件在站内引用、E2E 与书签风险审查后记录。

## 4. 每个切片的验证与停止条件

1. 记录旧入口、旧 URL、实际 capability、受保护目标、保存/确认行为；至少保留一条可复现请求或 E2E 样例。
2. 检查当前行操作不导航、关联链接可直达；直接打开详情页与从另一资源跳入均可返回，错误来源不能跳出管理端或绕过权限。
3. 在 1440、960、600、390px 和等效 200% 缩放下核对可见列、长文案、菜单、焦点、弹窗滚动及关闭；同一视口改变表格容器宽度、列设置和权限组合，确认无抖动、重复、裁切或页面级横向溢出。
   卡片和评论的“用户”可选列同时核对有用户名、无用户名及 ID 排序/搜索；卡片标签核对已加载与未知标签，不能出现逐行用户查询。
4. 验证只读、无权、受保护目标、请求失败、刷新中的旧结果、保存失败和脏状态；保存后由服务端重新给出列表行与总数。浅色、深色均进行截图人工审查。
5. 每个代码切片运行 `npm run check`、`npm run build:admin` 和受影响的隔离管理端 E2E。没有隔离数据库或浏览器环境时明确标记未通过，不以共享 dev 数据库执行写入 E2E，也不以构建通过代替人工视觉审查。

最终清理检查：10 个资源列表不再将当前行“查看详情”作为 `NuxtLink`；同一资源页面与弹窗不保留双套读取/编辑流程；跨资源目标不再指向标签 `?inspect` 或文件 `/usage`；行尾与批量命令都有真实契约、权限和状态说明；表格共享层没有业务请求、权限分支或逐行观察器；未完成的人工审查项明确保留为待验收。
