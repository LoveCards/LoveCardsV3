# 管理端表格交互更新实施方案（2026-11-19）

> 状态：设计方案，页面尚未按本方案改造。行为目标以 [列表与表格交互规范](ADMIN-TABLE-INTERACTION-STANDARD.md) 为准；本文件只确定当前代码基线、迁移顺序、实现边界和验收证据，不另立视觉或业务规则。

## 1. 基线与成功标准

当前 10 个资源列表已使用 `AdminResourceTableShell`，身份字段已回到阅读语义，但多数“查看详情”仍由 `AdminTableRowAction` 的 `to` 分支渲染为裸链接并跳页。`AdminResourceLink` 把跨资源引用渲染为带图标的按钮。卡片、评论详情页已能调用现有编辑弹窗；用户、角色详情页缺少编辑入口；标签 `/:id` 反向跳列表 `?inspect`，文件只有 `/:id/usage` 专题页。`adminListSource` 只校验同资源列表来源。各资源的操作菜单与宽度规则仍分散在页面内。

完成时应能逐项验证：10 个列表中当前行“查看/编辑/审核”按权限打开弹窗且不改变列表 URL；跨资源链接进入可刷新、可直接访问的目标详情页；有写权限的详情页调用与列表相同的编辑/审核弹窗；表格在同一视口下随自身宽度和可见列决定统一的 1 项、2 项或可容纳的全显操作档位；表头单行可读，菜单不重复动作；浅色与深色、键盘、390px 和 200% 缩放均可完成任务。只读资源、无权限目标、错误与脏状态须如实呈现。

本次不改变 SDK/API 字段、后端状态机、capability、通知、审计或事件队列。若某弹窗缺少完成任务的事实字段，先核对现有 SDK 与 API，再独立审查契约变化。涉及内容审核和账号状态的任何新增状态转换，按 [通知规范](NOTIFICATIONS.md) 先判定；前端不发布通知。

## 2. 最小实现边界

| 位置 | 增量责任 | 禁止扩张 |
| --- | --- | --- |
| `AdminResourceTableShell` 与共享操作能力 | 每张资源表观察一次内容视口；根据当前 headers 的 `minWidth`、选择列和已声明动作文案预算给出稳定的外露容量；统一按钮、菜单和可访问名称 | 不读取 SDK、不决定业务权限、不逐行创建 `ResizeObserver`，不接管查询和分页 |
| 资源列表页面 | 声明有序动作和当前行允许的动作；打开模块内查看/编辑弹窗；保存后重新读取当前查询和服务端总数 | 不复制编辑表单，不把列表摘要当详情，不在前端猜测结果数 |
| 模块内查看弹窗 | 按 ID 独立读取完成当前任务所需的事实、状态和证据，提供完整页面入口；只在实际重复时抽取模块内内容片段 | 不嵌整页、不复制完整历史或诊断区、不建设全局详情引擎 |
| 独立详情页 | 保持稳定路由、完整信息和专题区块；授权入口复用现有编辑/审核弹窗 | 不新建第二套页内编辑表单；只读资源不伪造编辑入口 |
| `AdminResourceLink` 与来源导航 | 跨资源引用用语义链接；只接受经校验的站内来源，上一条历史匹配时才回退，直接访问回规范列表 | 不建立全局来源 Store，不信任外部 URL，不把业务身份列变成隐藏链接 |

操作容量由表格级声明计算，行内仅按权限和状态过滤并填充可见槽位；只有溢出动作才进入“更多”。预算先满足可见业务列的最小可读宽度；空间不足时使用表格自身横向滚动，不能通过压窄字段换取动作全显。对于没有 `minWidth` 的列，迁移该页时补足与字段角色一致的声明，不建立第二份列宽配置。菜单与按钮共享同一动作定义和执行函数。

编辑弹窗的脏状态保护须覆盖关闭、Esc、遮罩、切换对象与路由离开。只读查看不持有草稿；查看切编辑时先关闭查看层并交接焦点。现有 `useAdminUnsavedChanges` 只处理路由变化，不能直接当作弹窗关闭保护。危险操作继续使用原有确认语义；同一时刻只允许一个主要弹窗可交互。

## 3. 垂直切片顺序

每个切片先固定原行为和 URL/权限样例，再修改该资源，运行受影响 E2E，确认后移除该资源的旧入口。共享能力只在第一个真实使用点建立，后续资源验证其边界；不先批量改 10 页。

| 顺序 | 切片 | 交付与依赖 |
| --- | --- | --- |
| 1 | 用户 | 建立每表操作容量与按钮语义样板；列表查看用户弹窗按 ID 读取，列表/详情页复用 `EditUserDialog`；评论作者等跨资源返回使用经校验的来源。账号安全保留独立授权子页。 |
| 2 | 举报 | 查看弹窗呈现处理所需证据；列表和详情页调用现有状态/备注流程，举报人和目标是明确的跨资源链接。验证权限、证据边界及高风险确认。 |
| 3 | 审计 | 只读样板：列表查看弹窗、完整详情页、操作者与目标链接；不添加编辑器。验证敏感字段和未知资源退化。 |
| 4 | 卡片、评论 | 各自独立切片迁移列表查看入口，复用已有 `EditCardDialog`、`EditCommentDialog`；保持正文优先、审核与置顶资格；旧 `?inspect` 只保留必要的单向迁移。 |
| 5 | 标签 | 建立真正的 `/:id` 详情页后切换关联引用；列表查看与编辑分别使用聚焦查看弹窗和现有 `EditTagDialog`；旧 `?inspect` 暂按明确删除条件兼容。 |
| 6 | 文件 | 建立包含元数据与引用区的 `/:id` 详情页；列表“查看文件/查看引用”在弹窗内完成当前任务，编辑复用 `EditFileDialog`；旧 `/usage` 地址保持单向兼容直至引用与书签核验完成。 |
| 7 | 角色、权限目录 | 角色详情页复用现有编辑与分配权限弹窗，系统角色保护不变；权限目录只读，详情/列表均不提供编辑。 |
| 8 | 处理任务与局部表 | 处理任务查看弹窗与独立诊断页分工，重试保留确认和状态限制；Session、升级计划仅在确有多动作时接入相同操作收放。纯诊断表及两张策略表不新增行操作。 |

第 1–3 个样板验收后再定共享组件最终接口；若出现资源特例，只保留模块内实现并在规范清单注明，不能把特例加进所有列表的通用 API。标签、文件必须先有稳定详情页才能切换 `AdminResourceLink` 的目标。旧 URL 的删除由管理端维护者在站内引用、E2E 与外部书签风险核对后单独提交。

## 4. 每个切片的验证与停止条件

1. 记录旧入口、旧 URL、实际 capability、受保护目标、保存/确认行为；至少保留一条可复现请求或 E2E 样例。
2. 检查当前行操作不导航、关联链接可直达；直接打开详情页与从另一资源跳入均可返回，错误来源不能跳出管理端或绕过权限。
3. 在 1440、960、600、390px 和等效 200% 缩放下核对可见列、长文案、菜单、焦点、弹窗滚动及关闭；同一视口改变表格容器宽度、列设置和权限组合，确认无抖动、重复、裁切或页面级横向溢出。
4. 验证只读、无权、受保护目标、请求失败、刷新中的旧结果、保存失败和脏状态；保存后由服务端重新给出列表行与总数。浅色、深色均进行截图人工审查。
5. 每个代码切片运行 `npm run check`、`npm run build:admin` 和受影响的隔离管理端 E2E。没有隔离数据库或浏览器环境时明确标记未通过，不以共享 dev 数据库执行写入 E2E，也不以构建通过代替人工视觉审查。

最终清理检查：10 个资源列表不再将当前行“查看详情”作为 `NuxtLink`；跨资源目标不再指向标签 `?inspect` 或文件 `/usage`；旧兼容入口的调用方和删除条件有记录；表格操作能力没有业务请求、权限分支或逐行观察器；所有未完成的人工审查项明确保留为待验收。
