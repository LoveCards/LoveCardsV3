# 管理端表格查询交互建议

> 状态：用户管理、卡片、评论、标签、举报处理部分已落实；其余为后续页面调整建议。

## 已落实的共同规则

- 列表只保留一个 `AdminResourceTableShell`：搜索、筛选、视图设置和结果数放在其工具区；表格内显示加载、错误和空态。
- 用户管理的账号状态、角色进入“搜索与排序”弹窗。角色属于关联关系，应使用结构化 `role_id` 精确筛选，不作为 `search_keys` 文本搜索字段。
- 中文枚举名称只在用户明确选择单个枚举搜索字段时转换为接口值。例如选“状态”并输入“正常”，请求发送 `search_value=0`；URL 和输入框仍保留“正常”。多字段搜索不转换，以免数字误搜其他字段。页面传入自身已有的状态选项，公共转换函数不硬编码业务字典。
- 举报处理沿用同一表格壳、视图设置、清除筛选及表格内空态；状态和目标类型仍是专用服务端参数，不伪装成全文搜索。

## 其余表格的取舍

| 页面 | 建议 |
| --- | --- |
| 卡片、评论、标签 | 保持现有搜索框与“搜索与排序”入口；枚举中文转换复用公共函数。只有单字段枚举搜索时转换，保留用户输入原文用于分享 URL。 |
| 角色、权限目录 | 继续使用各自可用的查询字段和共享表格壳；不要把角色 grants 或权限 scope 塞进通用文本搜索。 |
| 审计日志 | 按[专用方案](ADMIN-AUDIT-QUERY-DESIGN-2026-11-08.md)补后端契约，再加筛选控件；不能先做无效 UI。 |
| 通知处理 | 当前“失败/全部/待处理”是高频状态切换，保留为视图选择；视图条与表格壳之间只保留一处结果数。 |
| 升级、运行状态、用户会话 | 小规模诊断表或详情内嵌表可继续使用本地 `v-data-table`，不必为了统一强加服务端分页和复杂筛选。 |

## 后续验收准则

新增筛选必须能在 API 请求中看到对应参数；翻页与刷新保留条件，清除筛选返回第一页。表头排序与弹窗排序只维护一份状态。共享组件只组合 Vuetify 原语，不承载业务枚举或跨页 API 请求。窄屏工具区可以换行，但搜索、筛选和视图设置仍在同一表格表面内。
