# 后台 UI 调查与收敛设计

> 日期：2026-09-14 · 状态：方向已确认，应用壳与标签样板已完成并通过验证。
>
> 本轮交付：全后台信息架构、代表页面线框、交互规则、实施切片和验收标准。
> 不覆盖既有风格锁定，不改业务、权限、数据库、URL 或部署配置。确认后再同步正式基线。

## 1. 判断与证据边界

核心问题是**信息和动作缺少稳定的优先级**：导航层次过多，通用表格工具长期占据注意力，简单对象与复杂运维套用不同页面组织方式。已有共享组件和浅色 Indigo 风格可以继续使用。

本轮读取了导航、应用布局、页面头、面包屑、表格壳、视图控件、配置分区，以及标签、卡片、评论、用户、权限、举报、站点设置、渠道配置、工作台和运行状态等页面源码。完整阅读现行 IA、风格锁定和架构规范。

应用内浏览器连接连续返回 `nodeRepl.fetch request failed`，随后使用仓库现有 Playwright 与本地测试账号完成只读实屏采样。采样覆盖标签、卡片、举报、用户、站点设置、消息渠道、工作台、运行状态及 390×844 标签页；未触发业务写操作。

实屏确认：1440×900 标签页表格前有两层工具，共出现 8 个常驻工具动作，默认表头含 3 个技术 ID；表格从视口 y=347 才开始。全权限侧栏生成 26 个导航/分区行。390×844 下，创建、批量、筛选、搜索和视图控制占据大部分首屏，默认只看到 ID/应用 ID/用户 ID 等前置列。举报页使用另一套筛选和结果结构。以上证据支持本提案的 P1 判断。

### 应保留的基础

- Nuxt + Vuetify、浅色应用壳、现有 Indigo 品牌和常规控件。
- capability 过滤、后端授权、敏感信息最小可见、危险操作确认。
- 已有 URL 查询状态、管理员隔离的保存视图、未保存离开保护、旧地址兼容。
- 简单编辑对话框和复杂详情页的合理差异；统一不等于全部改成抽屉或全部表格化。

## 2. 设计目标与边界

使用场景沿用 PRODUCT：运营人员在桌面持续处理内容、用户与异常，运维人员按需进入专业诊断。视觉方向沿用已确认的白色顶栏、浅色侧栏、Indigo 当前项；本轮不另起品牌探索或生成效果图。

成功标准：打开页面后能明确“我在管理什么、如何找到目标、现在能执行什么”，同类页面的操作位置稳定，低频能力不丢失但不常驻抢占空间。

本轮不做：新 UI 库、换主题、全局命令系统、可拖拽仪表盘、自定义导航、额外角色体系、重写 CRUD 引擎、API/数据库迁移。也不为画面丰富添加接口不存在的统计、趋势、关联数量或筛选。

## 3. 信息架构：一个直达入口＋四个任务组

```text
工作台                     ← 直接打开，不再嵌套“总览”

内容与社区
  卡片
  评论
  标签
  文件管理                 ← 从“系统配置 / 存储”移入
  举报处理
  社区洞察

用户与权限
  用户管理
  账号恢复
  角色管理
  权限目录                 ← 原“权限管理”，明确只读定位

站点设置
  站点与社区规则
  主题外观                 ← 原“主题列表”
  存储配置
  消息渠道
  验证配置

系统运维
  运行状态
  通知投递
  升级与迁移
  审计日志
```

20 个唯一入口全部保留。合并用户与访问控制，是因为它们共同回答“谁在使用、能做什么”；内容与社区维持一个组，避免为了目录对称再增一层。账号恢复仍是独立只读入口，会话仍属于用户详情。

文件管理面向“查找和治理文件”，存储配置面向“文件放在哪里、如何上传”，两者分开。对有相应权限的人，文件页提供“存储配置”次要关联链接；无需在两组重复列文件入口。若实际岗位访谈证明文件管理主要由运维使用，可再评估位置，这不是扩大运营数据权限的理由。

### 导航行为

- 保留当前 264px 桌面侧栏和移动端临时抽屉；首轮不同时改尺寸和层级。
- 工作台始终直达；初次进入只展开当前组。用户可主动展开其他组，当前会话保留选择；路由变化确保目标组展开。
- 一级组保留图标，二级文字项对齐；去掉 `内容管理/社区治理/存储/角色/权限` 等不承载独立页面的分区标题。
- 当前叶子项有浅 Indigo 选中面；详情继承父项选中态。不用整组背景加深表达同一状态。
- 菜单不常驻“高风险页面”警告图标。保留风险元数据，在具体变更和确认处展示风险；只读查询本身不应被渲染成危险动作。
- 组和关联入口分别按原 capability 过滤；不按角色名推断，不因合并导航扩权。
- 不改现有 canonical URL 和 legacy alias。文件 URL 仍可保持 `/apps/settings/storage/files`；新分类由导航元数据表达，不以路径前缀猜域。
- 页头、面包屑、页面搜索结果、关联链接同时更新归属名称；搜索兼容“权限管理”“主题列表”等旧名称。

## 4. 页面骨架：统一规则，保留任务差异

### 4.1 应用壳与页面头

顶栏只保留产品/环境、页面搜索、账号入口。侧栏去掉重复账号块，底部保留返回站点与折叠入口。没有现成功能的通知、帮助、全局搜索不补空按钮。

列表页：一行小号域名作为上下文，下面标题与主动作对齐；不把当前标题再写进面包屑。不需要独立“内容管理”层。

详情页：保留“父列表 → 当前资源”的可返回路径；回列表恢复筛选、分页和滚动上下文。无实际页面的域名只是文字，不伪装链接。

常规资源页描述可省略，或用一句真正解释范围的文案。删除提醒放删除确认；服务端怎样校验权限等开发说明不作为每页副标题。

建议批准后的 token 调整：页面标题 24px/600，分区标题 18px/600，表格与标签 14px，辅助文字 12–13px；常规文字仍可用 16px。保留现有单字体、4px 控件圆角、8px 常驻内容圆角和 4px 间距单位。控件高度统一 40px，独立图标按钮和触屏操作区至少 44px。这些是拟议值，须先更新风格锁定，再由实屏检验，不逐页硬编码。

### 4.2 列表协议

```text
域上下文
页面标题                                         [页面主动作]

搜索目标…              常用业务筛选（有接口才显示）      [视图设置]
生效条件摘要（仅有条件时显示，可逐项清除）
───────────────────────────────────────────────────────────
名称 / 内容 / 账号          业务字段         状态       操作
资源数据……
───────────────────────────────────────────────────────────
共 N 条                                每页行数 / 上下页
```

具体约定：

- 没有创建能力的页面没有创建按钮，也不为凑“一个主动作”将刷新升级为主按钮。
- 默认一条检索工具栏。保存视图、列设置和恢复默认视图收进“视图设置”；已保存视图和管理员隔离键保持兼容。
- 查询条件变化才显示“清除筛选”；它不清除列设置。完整“恢复默认视图”放菜单并说明同时重置哪些内容。
- 选中行后，在同一工具区显示“已选 N 项 / 可执行的批量动作 / 取消选择”。不增加始终可见的“操作选择＋应用”两步。
- 批量动作继续依原契约执行。“封禁/取消”这类切换语义不能简单改名成“全部封禁”；施工前核对真实 API 行为，确认中准确说明，不能通过文案伪造幂等操作。
- 操作列保留一个高频文字操作，例如“编辑”或“查看”，其余进“更多”。危险动作在明确确认阶段强调红色，避免每行一个红垃圾桶。
- 资源身份列可点击，不再让 ID 成为唯一详情入口。不可点击的名称不使用链接色；状态、普通标签不统一包装成同样的 chip。
- 同一种状态用同一语义组件；不同业务状态不强行用同一枚举替换。
- 简单列表不强加可保存视图；复杂列表保留已有能力。共享壳提供可选位置，而非默认渲染所有功能。

### 4.3 标签页：第一批样板

```text
内容与社区
标签                                               [+ 创建标签]

[搜索标签名称……………………………… ×]                    [视图设置 ▾]
────────────────────────────────────────────────────────────
□ 标签名称                   状态         创建时间        操作
□ 日常                       正常         …              编辑  ⋯
□ 校园                       隐藏         …              编辑  ⋯
────────────────────────────────────────────────────────────
共 N 个标签                                     10 条 / 上下页
```

示例名称和状态仅用于结构示意，不是实际查询结果。默认列为名称、状态、创建时间、操作，加选择列。ID、应用 ID、创建用户 ID 留在可选列或编辑面板的“技术信息”。当前接口未提供关联卡片数，不新增该指标。

当前 [Tags SDK](../../packages/sdk/src/generated/resources/tags.ts) 的列表参数没有独立 `status` 筛选；第一批不添加看似可用的状态下拉。现有高级搜索实际是“搜索字段＋排序”，应准确命名为“搜索与排序”，从视图设置进入，原能力保留。

编辑继续使用小型对话框：名称、状态在前，技术信息在后按需展开；取消/保存固定在底部。两三个字段没有必要迁移为全屏详情或全新抽屉系统。保留 `inspect` 深链和现有兼容详情地址。

### 4.4 用户、卡片、评论与举报

- 用户：头像＋用户名＋编号合并为账号身份列；角色用名称呈现，接口只有 ID 时诚实显示 ID，不猜测名称；账号、安全会话和恢复流程保留现有入口边界。
- 卡片：缩略图与内容摘要组成识别区域；状态和时间稳定对齐；点赞/评论数为辅助，完整内容在现有详情/面板查看。
- 评论：正文摘要为主体，所属资源和审核状态辅助定位。保留有权管理员的正文修正能力，不因为旧文档一句“评论不可编辑”删除现有功能。
- 举报：状态筛选直接可见，列表突出举报目标、业务理由、当前状态和创建时间。举报详情是需要证据和处理历史的独立页面；不为了与标签统一而塞入小弹窗。
- 举报详情顺序：身份/状态 → 举报内容和必要上下文 → 可执行处理 → 处理历史。高频判断的信息放同一阅读区域，审计技术字段折叠；只显示现有接口授权返回的上下文。

### 4.5 配置页：业务分区与保存范围对齐

```text
站点设置 / 站点与社区规则
站点与社区规则
[基本信息]  [社区规则]

站点信息        站点名称、地址、标题、介绍
搜索与页脚      关键词、备案、版权（按当前字段分组）

────────────────────────────────────────────────────
基本信息有未保存修改                          [放弃修改] [保存基本信息]
```

- Tabs 仅表示独立任务/保存范围；当前站点页的基本信息与社区规则保留。字段按含义分节，用标题和分隔线，不套多层边框。
- 基础/业务/高级不是机械三段模板。只有确属高级或低频的参数才折叠；有错误或未保存修改的折叠区自动展开并定位。
- 保存栏处于当前内容区底部，长页采用 sticky；预留占位避免遮挡表单。清楚写“保存基本信息/保存社区规则/保存渠道配置”，不出现含糊的“保存全部”。
- 切换保存范围、离开页面、刷新关闭均保留 dirty 保护；当前已有保护不能因重新排版丢失。失败保留输入，不先关闭表单。
- 密钥遵循既有“留空保留现值”语义，说明紧贴字段；不把真实密钥放概览、截图、浏览器持久化或日志。
- 渠道列表优先紧凑列表，展示名称、默认状态、可用状态、配置入口。主题有真实预览图时保留卡片；不要求所有配置都长一样。
- 测试发信仍使用已保存配置；修改未保存时禁用测试并显示原因。测试可能外发消息，调查和视觉验收中不触发，需另获授权。
- “未保存”只保留一处主要状态表达；具体危险变更再说明影响，不重复铺满 warning 提示。

### 4.6 工作台与运行状态

工作台先显示待办，再显示健康摘要，最后最近变更；当前职责收进账号信息或轻量说明。宽屏待办为主列、健康为辅列，窄屏顺序堆叠；只显示现有接口和权限支持的真实数据。社区洞察承担深入聚合，首页不复制整张统计报告。

运行状态面向专业用户，允许比标签页更高的信息密度。将设施、Worker、事件队列分为清晰区块；异常摘要置顶；原因码和 Provider 等技术数据可保留在诊断层。不要用三个额外 KPI 卡片重复表格已有数字。

## 5. 状态与响应式不能被“简化”掉

| 场景 | 统一行为 |
| --- | --- |
| 首次加载 | 保留页头和工具栏位置，内容显示骨架；未知结果数不显示为 0 |
| 无数据 | 说明“尚未创建”；只有可创建且有权限时提供创建入口 |
| 筛选无结果 | 显示条件与“清除筛选”，不误导用户重新创建资源 |
| 刷新失败 | 保留旧内容并标明未更新，错误就地重试；不伪装成功 |
| 部分模块失败 | 工作台其他模块可用；失败模块单独反馈，不全部显示为 0 |
| 只读/403 | 只读页不提供写动作；无页面读取权限则解释并提供可达返回入口 |
| 正在保存 | 防重复提交；结果未知时不提示成功，不丢弃输入 |
| 危险操作 | 指明资源、数量、影响、可恢复性；保留业务结论字段，无通用操作原因 |
| 内容过长 | 名称可换行或摘要截断，详情可查看完整文本；不只靠 hover 获得关键内容 |
| 窄屏/200% 缩放 | 临时侧栏，工具栏换行，主动作保留；表格区域横向滚动，不让整页横向溢出 |
| 键盘操作 | 可见焦点、逻辑顺序、菜单和对话框关闭后回到触发位置；选中结果和保存反馈可被辅助技术感知 |

## 6. 对现有实现的最小落点

| 位置 | 改动范围 | 不做什么 |
| --- | --- | --- |
| `config/navigation.ts` | 组归属、显示名称、搜索旧名称映射；文件详情归属与父项一起调整 | 不修改 grant、API 或 canonical path |
| `layouts/default.vue` | 工作台直达、展开策略、移除 section 行和重复身份块 | 不增加第二套布局或角色硬编码 |
| `AdminPageHeader` / `AdminBreadcrumbs` | 统一上下文与标题位置；详情返回、动作对齐、字号 | 不在每页散落 CSS 覆盖 |
| `AdminResourceTableShell` / `AdminFilterToolbar` / `AdminTableViewControls` | 明确检索、选择、视图的可选位置，减少默认常驻控件 | 不新建表格引擎、不更换 Vuetify 数据表 |
| 具体资源页面 | 调整默认列、合并身份、动作文案和显示时机 | 不删除技术列能力、不伪造接口字段 |
| `AdminConfigSection` 与配置页面 | 分节、保存范围、dirty 提示收敛 | 不重写动态 schema 或 Secret 契约 |
| DESIGN / STYLE-LOCK / IA | 确认后一次同步新的层级和尺寸，删除冲突要求 | 本提案未确认前不擅改既有“已冻结”基线 |

保存视图沿用原 key。既有用户明确保存的技术列不强制清空；新默认列只影响无自定义偏好的初始视图。必要的旧列映射在现有偏好归一化逻辑内完成，不建第二套偏好服务。

## 7. 施工顺序与完成门槛

1. **样板切片：应用壳＋标签。** 落地导航和页头规则，收敛标签工具栏/列/编辑层级；用举报列表做对照，验证规则允许简单与复杂列表差异。验收通过后再扩大。
2. **资源列表切片：卡片、评论、用户、文件、角色、权限。** 迁移到同一位置规则，保留各自能力；核对搜索、分页、视图和深链，不只做截图对齐。
3. **任务与配置切片：举报/投递/审计详情、站点/主题/存储/渠道/验证、用户安全。** 统一上下文、信息先后、危险操作及保存位置；不改变状态机。
4. **收尾切片：工作台、运行状态、升级页面与全局复核。** 调整摘要优先级、状态文案和专业诊断；完成所有角色、窄屏、键盘和错误态检查。

首轮成功不是“组件都调用同一个壳”，而是标签和举报在同一规则下都自然好用。出现共同规则无法表达的真实任务差异，先保留合理例外，不继续加全局开关。

## 8. 可核验的验收清单

- 20 个现有唯一导航入口无遗漏、无重复；旧 URL、query、hash、详情父项选中均保持正确。
- 不出现“域 → 无页面的分区 → 列表”的三层目录；新会话只展开当前组。
- 每页一个 h1；默认列表无重复当前页面包屑；真实详情可返回父列表。
- 标签默认 4 个业务/操作列＋选择列；技术列仍可找回；未经支持的筛选与关联数量不出现。
- 未选择记录时不显示批量动作；选中后影响范围与权限正确，不能发生隐藏的跨页全选。
- 结果、搜索、分页、排序、命名视图恢复和管理员隔离不退化；恢复默认不误删已保存视图。
- 标签/卡片/用户/举报/文件/角色的主次操作位置一致，危险动作确认后才提交；检查操作成功、失败和结果不确定三种反馈。
- 配置明确保存范围，未保存离开提示覆盖原场景；Secret 不回显，测试不使用未保存值。
- 1440×900、1280×800、390px 窄屏及 200% 缩放验证；标签首屏目标为表头＋至少 6 条普通单行数据（数据足够、无异常横幅时），以真实截图验收，不靠缩小字号凑数。
- 键盘依次完成页面搜索、列表查询、打开/取消编辑、回到列表；焦点可见，弹窗无意外失焦，长名称不遮挡操作。
- 更新架构/导航契约断言，再执行 `npm run check`、`npm run build:admin` 与影响页面的隔离 E2E；角色/授权与视觉验收分开记录。
