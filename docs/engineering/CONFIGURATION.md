# 系统配置与共享基础设施

状态：2026-11-11 原子配置组、PHP Redis 读取超时与 Gateway 存活检查已进入工作树；替身行为测试通过，真实数据库并发、PhpRedis 黑洞与 dev 验收尚未完成。代码与最终验收结果以平台收敛实施账本为准。

## 所有权

Platform/Config 是系统配置唯一读写入口。Redis 是可选基础设施配置组，默认关闭；连接信息不启动进程，也不自动选择 ThinkPHP 缓存驱动。业务模块经 Config Public 读取配置，不直接修改 configs 表。

## 原子配置组

复用 configs 表，每组保留 `__revision` 元数据行。业务配置、字段 schema 和驱动配置不暴露该键；管理读取在组值对象中附带 `__revision`。管理提交回传读取时的版本，后端在事务中锁定版本行、校验 CAS、更新整组并递增版本。更新响应为本次事务捕获的确定脱敏快照，不在提交后重新读取另一管理员的结果。缺失版本拒绝写入，版本冲突要求重新加载。

密码继续使用 keep/replace/clear；脱敏标记不参与真实值写入。多个组一次提交时按组名排序取得锁并整体提交，任一冲突或校验失败全部回滚。现有管理响应从 204 调整为 200 组快照，SDK 契约与管理消费者同发行更新。

内部 set/setGroup/register/fillDefaults/deleteKey 使用同一版本锁与事务。register 创建组的版本行；已存在字段不覆盖。deleteGroup 删除业务字段但保留并推进隐藏版本，防止旧表单在同名组重建后误获写入资格。普通接口不能创建、删除或覆盖保留键。reload 不制造配置变更。

配置的权威读取与写入不依赖通用缓存，也不依赖被管理的 Redis；不在写入后调用受管理 Redis 使已提交结果被误报为失败。其他业务缓存保持原有明确部署选择。显式启用 Redis 缓存后，停用 Redis 前须先切换部署缓存策略，或通过受控数据库修复路径恢复；不自动回退 file。

## Redis 与 Gateway

PHP 明文和 TLS 连接均设置 250ms 连接、命令读取预算；这不是包括 DNS、OS 调度的硬实时上限。多命令操作仍受命令数量与调用方任务预算约束。TLS 验证证书链与名称，不提供静默明文回退。

Gateway 只在订阅确认后报告就绪；每 15 秒发送一次带标识 PING，5 秒内未收到匹配 PONG 时关闭订阅与 SSE，按既有策略重连。认证、选库、订阅握手整体受连接预算限制。正常空闲不能被误判离线，业务信号流量也不能替代匹配 PONG。Redis 配置版本变化仍关闭旧连接后重建。

干净安装在既有持久 `install.lock` 中生成 32 位部署 ID，不另建状态文件。旧格式安装锁从持久实例根路径确定性推导身份，因此同一旧站跨 Release 保持稳定；克隆旧站若共用相同绝对路径，部署方必须显式配置不同的 `LC_DEPLOYMENT_ID`。该环境变量也可覆盖新安装的锁内身份，取 16—64 位小写字母、数字、下划线或连字符组成的站点唯一稳定值，必须由 Web、cron、Worker 共用。身份不是密码，不随 Release、Redis 密码或数据库备份轮换。Config Public 从它派生 Redis Pub/Sub channel、ThinkPHP Redis 缓存前缀和定时消费者 MySQL 命名锁，Gateway 经认证的内部配置接口取得 channel。Redis database 号不能隔离 Pub/Sub。尚未安装且没有有效显式身份时，Redis 缓存与定时消费失败并报告原因，不借用共享默认通道或锁。迁移既有站点的身份时应先暂停消费并等待在途任务结算，随后同步更新 Web、cron、Worker 环境并重启相关进程；不能在后台热改该身份。

会话票据的最终实现与验收状态见平台收敛实施账本；本节只规定部署身份和 Redis 连接配置。

## 验证要求

必须覆盖整组无混合快照、并发版本冲突不落部分字段、元数据不可被业务接口写入、删除重建不复用旧版本、敏感值遮罩、缓存故障不阻止配置管理，以及 Gateway 半断开/正常 PONG/TLS 验证。真实 MySQL 和 PhpRedis 黑洞测试与进程内替身测试分开记录。
