# 管理端角色与权限矩阵（设计稿）

> 状态：角色模板、幂等安装/升级种子与 capability 映射已落地；模板不会自动分配给现有用户
>
> 本文件是角色模板和授权边界；前端按 grant 隐藏入口，后端 route/service 仍是最终授权边界。

## 1. 使用方式

角色不是页面开关。最终可见内容由以下交集决定：

```text
角色 grants
∩ 页面读取 capability
∩ 具体动作 capability
∩ 数据范围（global / resource / self）
```

前端导航只负责体验，后端 route/service 才是最终安全边界。

矩阵中的“读”表示可以读取页面和必要摘要；“管”表示可以执行该域的受控业务动作；“配”表示可以修改配置；“高危”表示必须额外确认、原因和审计。

## 2. 域级模板

内置管理模板使用稳定 slug，不使用固定数据库 ID。`root/admin/user/guest` 继续保留
`1/2/3/4` 锚点；以下模板的 ID 由安装现场分配，代码和前端不得依赖其数值：

| 中文名称 | 稳定 slug | 默认职责边界 |
| --- | --- | --- |
| 内容运营 | `content_operator` | 卡片与标签治理；不含审核、用户和系统权限 |
| 社区运营 | `community_operator` | 评论正文修正、卡片级评论置顶、举报与社区聚合；不含系统配置 |
| 审核员 | `moderator` | 卡片、评论与举报审核；不含正文编辑和删除 |
| 安全管理员 | `security_admin` | 用户安全、Session 撤销与审计读取；恢复接口权限保留供服务端兼容 |
| 运维管理员 | `operations_admin` | 基础设施配置、投递、升级迁移与恢复 |
| 审计员 | `auditor` | 获授权域的只读核对；不包含任何写操作 |

所有模板都只包含进入管理端与工作台所需的 `admin.access:global`、
`dashboard.read:global`，再叠加职责所需的最小 grants。代码事实源为
`SystemRolePolicy::administrationTemplates()`；升级迁移只补缺失角色和默认 grant，
不会删除超级管理员显式追加的 grant，也不会向 `user_roles` 写入任何分配。

| 角色 | 工作台 | 内容与社区 | 用户与安全 | 系统配置 | 运维与审计 | 访问控制 |
| --- | --- | --- | --- | --- | --- | --- |
| 超级管理员 | 读/管 | 读/管 | 读/管 | 读/配 | 读/管/高危 | 读/管/高危 |
| 管理员 | 读/管 | 读/管 | 读（受范围限制） | 读（非敏感） | 读（健康摘要） | 默认不显示 |
| 内容运营 | 读 | 读/管内容 | 不显示 | 不显示 | 不显示 | 不显示 |
| 社区运营 | 读 | 读/管社区 | 不显示 | 不显示 | 不显示 | 不显示 |
| 审核员 | 读 | 读/管审核动作 | 不显示 | 不显示 | 读处理历史 | 不显示 |
| 安全管理员 | 读 | 不显示 | 读/管安全 | 不显示 | 读安全审计 | 不显示 |
| 运维管理员 | 读 | 不显示 | 不显示 | 读/管基础设施 | 读/管/高危 | 不显示 |
| 审计员 | 读 | 只读授权范围 | 只读授权范围 | 只读摘要 | 只读 | 不显示 |

“不显示”是默认模板建议，不阻止以后由超级管理员授予额外 grant。

## 3. 动作级边界

### 内容与社区

| 资源 | 允许的动作类别 | 明确禁止/特殊规则 |
| --- | --- | --- |
| 卡片 | 查看、编辑（受授权）、隐藏、恢复、删除、标签治理 | 编辑表单区分可写字段和派生统计字段 |
| 评论 | 查看、编辑正文、审核、隐藏、恢复、删除、卡片级唯一置顶（分别受授权） | 正文编辑使用 `comments.update.all`；置顶使用 `comments.pin.all`，且所有变更强制审计原因 |
| 标签 | 查看、创建、改名、停用/恢复 | 删除前显示受影响卡片数量 |
| 举报 | 查看证据、状态转换、填写原因、查看历史 | 转换必须满足状态前置条件并写审计 |
| 社区洞察 | 读取聚合指标 | 不返回草稿、收藏、历史或私信正文 |

### 用户与安全

| 资源 | 允许的动作类别 | 明确边界 |
| --- | --- | --- |
| 用户 | 查询、查看公开/授权资料、冻结/恢复（受授权） | 敏感字段遮罩，不能把安全详情混入资料编辑 |
| 账号恢复 | 用户端自助找回；管理端通过审计日志追溯结果 | 不展示恢复凭证或独立挑战列表 |
| Session | 查看摘要、撤销单个/全部会话 | 撤销必须二次确认并填写原因；按钮消费服务端 `session_mutation_allowed`，接口再次授权 |

用户与角色管理还受垂直授权上限约束：非 root 管理员不能修改 root 或 grants 高于自己的目标，不能修改自己的角色，也不能分配自己不拥有的 grant。删除、禁用或降级 root 用户时必须在事务内保证仍有至少一名可登录的 root；前端隐藏动作不能替代这一后端规则。

### 系统配置与运维

| 资源 | 允许的动作类别 | 高风险规则 |
| --- | --- | --- |
| 站点规则 | 查看、编辑 | 显示影响范围和保存结果 |
| 外观/主题 | 查看、选择、配置 | 激活主题前确认；schema/驱动详情下沉三级 |
| 存储/消息/验证 | 查看、配置、测试 | 渠道 secret 默认遮罩；测试结果写审计 |
| 运行状态 | 查看、刷新 | 降级状态必须可见，不把缓存值称为实时 |
| 通知投递 | 查看、按允许状态重试 | 重试显示 attempts、原因和新状态 |
| 升级/迁移 | 查看、上传、单步推进、批准、恢复 | 每一步独立确认；Contract 批准和恢复分离 |
| 审计 | 查询、导出（受授权） | payload 按后端白名单脱敏 |

## 4. 导航契约字段

施工阶段的导航配置和后端 route metadata 必须能表达：

```ts
type AdminNavigationContract = {
  domain: string
  route: string
  requiredCapabilities: string[]
  actionCapabilities?: string[]
  dataScope?: 'global' | 'resource' | 'self'
  riskLevel?: 'normal' | 'sensitive' | 'high'
  parentRoute?: string
  legacyAliases?: string[]
}
```

前端据此决定入口、按钮和说明；服务端再次校验 capability、资源状态和数据范围。

## 5. 施工验收

- 普通管理员看不到未获授权的一级域、二级入口和危险按钮。
- 直接访问隐藏 URL 时得到明确的 403 页面，而不是空白或重定向到无关页面。
- 角色变更后，导航和工作台在刷新后与新 grants 一致。
- 每个动作失败时保留页面上下文，并显示是否已执行、是否可重试。
- 所有高风险动作可在审计日志中追溯操作者、资源、原因、前后状态和 correlation id。
- 角色矩阵中的每个动作都能在后端 route/service 和测试中找到对应实现；不存在只在前端显示的“幽灵权限”。
