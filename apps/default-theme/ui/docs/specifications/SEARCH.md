# LoveCards 聚合搜索设计基线

> 状态：实现基线 v1.1。适用于 `/search*`；页面身份与返回行为见 [`NAVIGATION.md`](./NAVIGATION.md)，卡片与动效遵守共享规范。

## 页面与地址

- `/search` 无词时是输入入口；`/search?q=<词>` 有词时是综合结果。范围页为 `/search/posts?q=<词>`、`/search/users?q=<词>`、`/search/topics?q=<词>`。范围是可分享的路径，不作为发现页筛选。
- 只在有词时显示“综合 / 内容 / 用户 / 话题”范围导航；各范围保留原词。完整范围的 `page` 从 2 开始显式写入 URL，综合页只展示各类预览，不分页。空词、未知范围、无效页码和旧 `/explore?q=` 用 `replace` 归一，保留不冲突的参数与 hash。
- 搜索框显示当前 `q` 并可直接编辑；Enter 和“搜索”提交当前输入。清空并提交回到 `/search`。桌面顶栏及手机搜索起始页在建议尚未返回时，Enter 也能进入 `/search?q=`；建议项仍可打开对应真实资源。

## 结果契约

- 综合页按“内容、用户、话题”分组，各组独立加载、空态、失败和重试；单组失败不覆盖其他组。内容组沿用共享 `FeedCollection` 和卡片预览，用户与话题逐条排列在页面底色上，不再套整组面板。
- 内容使用专用 `GET /cards/search-public`，接受必填 `search_value`、`sort=match|latest` 和有界分页。只收录已发布、公开、未删除且作者正常的卡片，双向屏蔽在计数与分页前生效，管理员身份也执行同一公开范围。现有 `cards/search` 继续服务发现与话题列表。
- 默认按“匹配程度”，正文开头、正文其他位置、仅关联公开话题依次排序，同档按发布时间和 ID 倒序。正文为空的历史卡片以已有字符串标题回退，与卡片显示一致。普通关键词同时匹配正文包含和关联话题精确名称，用 EXISTS 避免重复卡片。显式 `#话题` 只查关联公开话题，综合页优先展示话题组。
- 内容范围选择“最新发布”写入 `sort=latest`，切换排序回第一页。默认 `sort=match` 从地址省略，其他范围和综合页不保留排序参数。分页链接、刷新、分享、历史返回均保持排序。综合页内容预览使用默认匹配排序。
- 用户按完整 UID、用户名完整匹配、用户名开头依次排序，同档按用户名和 ID 升序。话题按完整名称、开头、包含依次排序，同档按名称和 ID 升序。用户主页隐私和卡片公开范围分别使用各自规则。
- 站内输入最多 100 个字符，普通内容关键词至少两个字符。单字符仍查询用户和话题，内容组显示“输入至少两个字搜索正文”。`#猫` 可以检索单字话题关联内容，单独 `#` 显示“请输入话题名称”，提示不算全部无结果。SQL 通配符按字面值匹配。
- 综合页每类只显示少量预览；范围页使用服务端分页与“上一页 / 下一页”。请求随词、范围、页码变化取消或忽略过期结果，不用前端重排已加载切片冒充完整搜索。
- 无词提示、加载骨架、零结果、单组失败和全组零结果在页面底色表达。设计预览模式显示“演示数据、操作不会保存”提示，不把样例用户或话题伪装成真实 API 数据。

## 响应与交互

- 桌面搜索位于侧栏右侧的内容区顶部，查询结果用可编辑的原词输入替换该位置的快捷搜索；手机从顶栏真实链接进入 `/search`，显示与设置共用的返回顶栏。起始、综合和范围使用同一个移动任务壳，底部只为页面间距和安全区留白。桌面顶栏与手机起始页复用 180ms 防抖与输入法组合处理，只联想用户与话题，每组最多两条，完整搜索入口始终可提交原词。搜索结果页仅保留一处可编辑查询框。
- 内容结果在桌面固定多列，手机使用共享的单列／多列偏好。结果卡片与加载骨架使用相同列数。用户和话题结果保持列表，手机范围导航可横向到达。
- 键盘可从输入、范围导航到结果逐项操作；输入法组合期间 Enter 不提交半成品。快速建议的无结果或接口错误不能伪装成可点击资源；原词提交始终通往真实结果页。
- 内容预览返回时恢复搜索路径、词、范围、页码、滚动和焦点；刷新或直接打开内容地址显示完整详情。减少动态效果时遵守共享动效规范。

## 验收

覆盖 320/390/768/1024/1440px、键盘与输入法、游客与登录、前进后退与刷新、内容预览返回、三类单独失败及全部为空、服务端分页、设计预览提示和快速搜索请求竞态。

公开范围另验管理员身份、仅关注者/仅自己可见内容、作者异常、隐藏话题、双向屏蔽，以及历史标题回退、短词和字面通配符。真实数据库验证同档跨页顺序和正文/话题同时命中的去重。

## 实现与运维

首版复用现有数据库、模块 Service、卡片 Resource 与 SDK 生成链。范围页每页 24 条并使用现有页码分页契约，取数和计数成本分别记录。站点使用固定检索规则与部署预算，无需管理员设置。查询请求量、延迟与错误通过现有运维观测提供，原始搜索词不进入新建统计记录。

P95 ≤ 500ms 是初始候选验收目标，须标明样本规模、并发及测量条件。实际正文扫描成为瓶颈时，再对相同语料验证数据库全文索引及中文命中质量。有异步索引同步和重建任务后，才添加对应后台运维入口。
