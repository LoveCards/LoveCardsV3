# 发布与评论交互规范

## 内容形态

发布页先由用户显式选择内容形态，再根据所选类型校验媒体：

- `随笔`：纯文字，隐藏媒体工作区，正文必填。
- `图文`：1–9 张 JPEG、PNG、WebP 或 GIF；一张写入 `image`，多张写入 `gallery`。
- `视频`：一个 MP4、WebM、MOV 或 M4V 文件，写入 `video`。

`image` 与 `gallery` 是“图文”这一用户类型的两种数据状态，不拆成两个发布入口。类型选择使用单选分段控件并支持方向键；没有文件上传权限时保留“随笔”，图文与视频明确禁用。

## 媒体上传

上传区是编辑器的一部分，不使用大面积空白拖放框。空状态显示加号与明确动作；选择后显示可排序的缩略图、顺序、移除操作和媒体数量。失败时保留已选文件，允许重新提交。

切换到与已选媒体不兼容的类型时，使用确认弹窗说明“正文和话题保留、媒体将移除”。没有媒体时立即切换，不额外打断。视频不生成图片封面字段；媒体 URL 与文件 ID 继续通过卡片媒体字段保持归属和顺序。

发布页不提供信息流实时预览。媒体区只显示本地上传缩略图，用于确认顺序、识别文件和移除媒体；它不是最终卡片模拟。发布后的正式呈现统一由信息流 `FeedStory` 和详情媒体组件负责，发布页不得维护第二套卡片表现。

## 草稿箱

草稿是发布页编辑状态的保存结果，不是独立的内容类型，也不是另一套编辑器。

- 只有发布页的“存入草稿箱”动作会创建草稿；打开发布页、输入内容或进入草稿箱都不会自动创建空草稿。
- 草稿不提供用户填写的标题。列表展示名由正文第一行派生；没有正文时显示内容类型，例如“视频草稿”。后端兼容字段 `title` 只保存这个派生值，不是可编辑产品字段。
- 草稿箱只展示未发布内容。点击列表项统一返回 `/compose?draft=<id>`，发布页恢复同一套类型、正文、话题和媒体字段。
- 新草稿使用“存入草稿箱”，已有草稿使用“更新草稿”；保存失败时保留当前页面输入，不清空本地文件或已恢复媒体。
- 保存媒体草稿时，媒体先上传并以有序引用写入草稿 payload；恢复发布时复用这些文件，不重复上传。用户移除媒体或删除草稿后清理仍未被正式内容引用的上传文件。
- 发布成功后删除草稿记录，保留正式卡片正在使用的媒体引用。

## 评论

评论采用单一连续讨论流：回复上下文紧贴输入框，输入框支持多行、字数计数、发送中禁用、失败保留草稿；评论行使用紧凑分隔，不为每条评论创建松散独立卡片。完整的线程、回复、失败和登录状态规则见 [`INTERACTIONS.md`](./INTERACTIONS.md)。

## 组件复用

施工时优先复用 Astryx 原生能力：`SegmentedControl` 负责发布类型，`MediaDropzone` 基于 `FileInput` 负责选择、拖放、类型和数量校验，`ChatComposer` / `ChatComposerInput` / `ChatSendButton` 负责评论输入与发送状态，`Typeahead` 负责话题建议，`Dialog` 只用于确认或异常恢复。LoveCards 只覆盖布局、Token 和状态样式，不复制底层行为组件。
