# LoveCards 反馈与状态系统

> 状态：v1.0。本文定义信息如何选择 FieldStatus、Banner、Toast、EmptyState、ResourceState、Dialog、Skeleton、Spinner 和 Progress。具体错误翻译见 [`ERROR-FEEDBACK.md`](./ERROR-FEEDBACK.md)。

## 1. 先判断范围、持续时间和下一步

反馈组件不能按“好不好看”选择。每次反馈先回答三个问题：

1. **范围**：影响字段、当前任务区、页面资源，还是整个应用会话？
2. **持续时间**：短暂确认、持续到用户看见，还是持续到问题被修复？
3. **下一步**：用户无需处理、可以重试、必须修改输入，还是必须做决策？

```text
字段值有问题 → FieldStatus
当前任务持续受阻 → scoped Banner
页面资源无法呈现 → ResourceState
没有数据且请求成功 → EmptyState
动作已完成且无需处理 → Toast
必须确认高影响后果 → AlertDialog
内容正在形成 → Skeleton / Progress / Spinner
```

**The Smallest Honest Surface Rule.** 使用能完整表达影响范围的最小反馈表面；既不把字段错误升级为页面 Banner，也不把页面失败缩成一条 Toast。

## 2. 反馈组件职责

| 组件 | 正确用途 | 持续规则 | 禁止 |
|---|---|---|---|
| `FieldStatus` | 单个字段、文件或自定义控件的 error/warning/success | 与控件值一起存在，修正后更新 | 网络故障、页面加载失败、全局公告 |
| `Banner` | 页面或 Section 顶部的持续更新、权限、任务失败和需要行动的说明 | error 在问题解决前保留；info/success 可关闭 | 短暂成功、字段格式错误、连续堆叠多个同类 Banner |
| `Toast` | 保存、复制、删除、状态切换等已经完成的短暂确认 | 自动消失；可逆操作提供撤销 | 表单校验、关键失败、需要阅读后行动的信息 |
| `EmptyState` | 成功加载后数据为零、首次使用、无搜索结果 | 数据出现后消失 | 404、403、网络失败、加载中 |
| `ResourceState` | 页面或数据区域的 loading/error/permission/deleted/restricted/offline | 与资源状态同步 | 普通字段错误或即时动作反馈 |
| `AlertDialog` | 删除、清空、屏蔽、放弃未保存修改等高影响确认 | 用户明确选择后关闭 | 单纯告知、成功提示、可内联完成的任务 |
| `Skeleton` | 页面和内容区域首次加载，几何与完成态一致 | 数据到达后替换，不独立播报每块骨架 | 不知道最终结构时使用万能灰卡 |
| `Spinner` | 小于约 1 秒、范围明确的未知等待；按钮或紧凑控件内 | 保留原尺寸和标签语义 | 替代整页骨架、让按钮宽度跳动 |
| `ProgressBar` | 上传、导入等能够提供可信进度的任务 | 只展示真实进度 | 用虚假百分比安抚用户 |
| `StatusDot` / `Badge` | 在线、未读、处理中、失败等短状态 | 必须配可读文本或可访问名称 | 日期、计数和普通元数据胶囊化 |

## 3. 状态等级

| 语义 | 适用 | 颜色与图标 | 默认动作 |
|---|---|---|---|
| info | 状态更新、说明、可选提示 | 中性或信息图标 | 了解、查看 |
| success | 已确认完成 | success + 对勾 | 无；可逆时撤销 |
| warning | 可以继续但存在风险或缺失 | warning + 明确风险 | 修改、检查 |
| error | 任务或请求没有完成 | danger + 错误图标 | 修正、重试、重新登录 |
| critical | 安全、账户或不可逆风险 | danger + 清楚后果 | 独立安全动作，不自动消失 |

颜色永远不是唯一信号。标题、正文和动作必须能在灰度下说明状态。

## 4. 文案结构

持续反馈采用三段式，但不要求视觉上占三行：

- **标题**：发生了什么，例如“图片格式不支持”。
- **原因/范围**：影响哪个对象，为什么无法继续。
- **动作**：用户能执行的下一步，例如“重新选择”“重新登录”“重试加载”。

不得写“参数错误”“操作失败”“未知错误”“请求异常”。不得把支持格式、失败原因、后端状态和恢复动作压成一条长句。

动作标签必须具体：“重新选择”“重试上传”“返回主页”，不用“确定”“处理”“知道了”代替真实动作。

## 5. 常见场景矩阵

| 场景 | 主反馈 | 补充行为 |
|---|---|---|
| 输入格式错误 | 控件 `FieldStatus` | 保留输入，聚焦首个无效字段 |
| 文件类型/大小/损坏 | `FileInput status` / `FieldStatus` | 保留任务，提供重新选择 |
| 上传中 | FileInput loading；有可信进度时 ProgressBar | 禁止重复选择和重复提交 |
| 上传网络失败 | 上传任务区的 scoped Banner | 文件可安全保留时提供重试 |
| 上传权限/登录失效 | scoped Banner | 提供登录或返回，不提供无效重试 |
| 保存成功 | Toast 或原位状态 | 不弹成功 Dialog |
| 复制链接成功 | Toast | 短文案，无 Banner |
| 列表首次加载 | 结构匹配 Skeleton | 保留容器尺寸 |
| 列表为空 | EmptyState | 解释原因并提供一个下一步 |
| 列表加载失败 | ResourceState | 重试只重载该区域 |
| 加载更多失败 | 列表尾部内联 Banner/Message | 保留已加载内容 |
| 资源删除/受限 | ResourceState 占位 | 禁止仍可点击的假入口 |
| 后台同步中断 | 当前区域非阻塞 Banner | 保留旧数据并允许刷新 |
| 删除/清空前 | AlertDialog | 描述后果和可恢复性 |
| 删除完成 | Toast；可恢复时“撤销” | 列表先更新，失败则回滚 |

## 6. 头像上传的标准流程

头像属于“直接触发的独立编辑任务”，不能把上传控件、帮助文本和错误临时塞进个人主页身份排版。

### 入口

- 本人主页点击头像直接打开“更换头像”任务 Dialog，不经过资料二级页。
- 头像上提供相机/编辑提示和可访问名称“更换头像”；键盘 Enter/Space 可打开。
- 他人主页和内容作者头像仍是用户身份入口，不能触发编辑。

### Dialog 内部

1. Header：标题“更换头像”，关闭按钮。
2. Body：当前头像/待上传预览、`FileInput`、常驻短说明“JPG、PNG、GIF 或 WebP，最大 10MB”。
3. Footer：取消和“保存头像”；未选择新文件时主动作禁用。

文件格式、体积和读取失败显示在 FileInput 的 `FieldStatus` 中；不额外创建 Banner。网络、服务端、权限或登录失败影响整个上传任务，显示在 Dialog Body 顶部的 scoped Banner。成功后关闭 Dialog、更新主页头像，并显示短暂 Toast“头像已更新”。

如果选择文件即自动上传，则失败时保留预览和可重试文件；如果浏览器无法安全复用文件，明确显示“重新选择”，不能展示无效“重试”。

### 6.1 单个媒体资料的复用范围

头像上传任务的 `FormDialog + FileInput + FieldStatus/scoped Banner + Toast` 是单个媒体资料编辑的统一模式。主页背景图、封面图等同样是“一次选择、一次提交”的单文件资料时，复用该上拉任务结构，只替换标题、限制和后端场景；不得在资料卡旁展开第二套上传表单。多文件发布、排序和批量移除仍使用 `MediaDropzone`。

## 7. 通知与反馈不是同一概念

站内通知是持久业务内容，例如点赞、评论、回复、关注、私信投影和系统通知；它属于通知列表 Pattern。消息中心把独立的私信页放在第一入口，通知二级只保留“互动消息”和“系统通知”：`/inbox` 使用服务端联合筛选 `engagement`，`/inbox/system` 使用 `system`。`message/social/interaction` 是返回项的真实分类，不再作为用户可见的二级筛选。Toast、Banner 和 FieldStatus 是当前交互会话中的界面反馈。前端不能为了提示用户而创建站内通知，也不能用通知列表项代替当前操作反馈。

## 8. 可访问性与时序

- 动态错误使用 `role="alert"` 或相应 Astryx live-region；状态更新使用 `role="status"`。
- 同一事件只播报一次，禁止 FieldStatus、Banner 和 Toast 同时重复播报相同错误。
- 错误出现不强制抢走正在输入的焦点；提交失败可聚焦错误摘要或首个无效字段。
- Toast 不接收初始焦点；包含“撤销”时必须可通过键盘到达，且停留时间足够。
- Banner 的关闭按钮和动作至少 44×44px；error 默认不可关闭，直到问题已解决或用户离开任务。
- 减少动态下取消 Toast 滑入、Skeleton 闪烁和状态缩放，保留即时显隐。

## 9. 骨架与最终内容契约

- Skeleton 与最终 Pattern 使用相同宽度、列数、媒体比例、头像尺寸和文字轨道。
- 页面级骨架保留稳定壳层、标题和 Tab；只替换会变化的数据区域。
- Tab 切换只在内容区显示骨架，不能把整个用户主页重新变灰。
- 加载结束时累计布局偏移应接近零；不得用统一三行灰卡模拟所有内容类型。

## 10. 验收

- 每个反馈都能说明范围、持续时间和下一步。
- 页面不存在同一错误被 Inline、Banner、Toast 重复显示。
- 头像错误不会改变用户主页身份头的高度和排版。
- 空状态只用于成功的零数据；403、404、网络和删除分别表达。
- 加载更多失败保留已有内容；写操作失败保留输入和可恢复上下文。
- 键盘、读屏、亮暗主题、320px 和减少动态全部可用。
