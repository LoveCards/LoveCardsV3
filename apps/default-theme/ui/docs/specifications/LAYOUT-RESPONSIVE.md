# LoveCards 布局与响应式规范

> 状态：v1.0。本文定义页面壳、容器、内容轴、信息流 gutter、响应式重排和 Skeleton 几何。视觉 Token 见 [`../../DESIGN.md`](../../DESIGN.md)。

## 1. 布局原则

- 响应式改变结构，不缩小任务。
- 页面宽度由内容类型决定，不用一个 `max-width` 处理信息流、阅读、设置和会话。
- 手机端“全宽页面”不等于内容贴屏：页面背景可以顶满，文字、卡片流和触控内容必须遵守 gutter 与 safe-area。
- 页面只拥有外部编排；Feed Card、AuthorIdentity、CommentThread 等 Pattern 内部布局不能被页面 CSS 穿透。
- 正常态、Skeleton、Empty、Error 和 Permission 使用同一容器与内容轴。

## 2. 全局断点与 gutter

| 容器宽度 | 页面 gutter | 结构能力 |
|---|---:|---|
| 320–359px | 12px；紧凑 Feed 可使用 8–9px | 单列安全回退，所有动作可达 |
| 360–760px | 12–16px；Compact Feed 固定 9px | 双列发现或单列任务，底部 safe-area |
| 761–1050px | 20px | 三列发现，辅助栏折叠 |
| 1051–1439px | 20–24px | 3–4 列发现或主轴 + 280px 上下文 |
| ≥1440px | 居中，最大 1240px | 不继续无限增加列宽 |

断点是结构变化门槛，不是设备型号。组件在容器不足时先换行、收起次级信息或切换 Pattern 密度，不能先缩小触控目标。

## 3. 容器 Profile

| Profile | 宽度 | 适用页面 |
|---|---:|---|
| `shell` | 最大 1240px | 全局导航下的大多数页面 |
| `discovery` | 1240px 内自适应列 | 首页推荐、发现、话题、用户内容网格 |
| `relationship` | 主轴 520–680px | 关注流、粉丝/关注列表、通知列表 |
| `reading` | 680–760px | 内容详情、长文、评论线程 |
| `editor` | 最大 860px | 发布、草稿、较长表单 |
| `settings` | 内容 640–760px + 可选导航 | 设置和隐私任务 |
| `auth` | 360–420px | 登录、注册、恢复 |
| `conversation` | 桌面双栏；会话轴 640–760px | 消息列表与私信 |

同一页面只能有一个主内容轴。右栏只承载上下文，不能复制主轴已有的标题、Tab、统计或资产入口。

## 4. IA depth × Mobile shell

IA depth 描述用户离一级目的地有多远，Mobile shell 描述手机页面使用哪套导航几何；两者必须分别登记。Shell 的路由与返回语义以 [`NAVIGATION.md`](./NAVIGATION.md) 为准。

| Shell | 顶部 | 底部 | 主滚动与安全区 |
|---|---|---|---|
| `standard` | 一级语境顶栏 | BottomNav + safe-area | 页面主内容扣除上下导航高度 |
| `task` | 56px 局部“返回 + 标题 + 可选动作” | 仅 safe-area | 单一任务滚动层，不预留 BottomNav 空白 |
| `immersive` | 56px 取消/返回与任务动作 | 固定任务栏（如发布）+ safe-area | 内容区避让软键盘和任务栏，不出现第二套底栏 |
| `gateway` | 认证流程自己的品牌/返回区域 | 仅 safe-area | 表单轴随软键盘滚动，主动作始终可达 |

- Shell 是稳定页面几何：loading、empty、error、permission 和完成态使用同一壳。
- 响应式只改变操作的排布和承载形式，不改变权限。桌面与手机必须共用同一登录/能力门禁，不得在某一断点提前渲染未授权的菜单项。
- `task` 与 `immersive` 在 320–760px 隐藏全局 TopNav/BottomNav；桌面是否保留产品 TopNav 由页面家族决定。
- `immersive` 同一时刻只能有一个固定底部任务栏；发布操作栏、Composer 与 BottomNav 不得叠放。
- Skeleton 必须从内容区开始，不能用 Skeleton 替代局部顶栏或造成返回按钮跳动。

## 5. 页面家族

### 首页、搜索、话题与用户主页

- Compact 内容统一使用同一自适应 Feed 容器和 `FeedStory` Pattern。
- 桌面 3–4 列，平板 3 列，360–760px 为双列，小于 360px 单列回退。
- 卡片列 gap 8–16px，外 gutter 不得为 0；手机用户中心、关注页面中的内容流与首页遵守同一外边距规则。
- 页面 Header、身份头和 Tab 可全宽占据页面画布，但卡片网格必须回到 Feed gutter。

### 关注、粉丝与关系列表

- 内容是连续身份行，不是每个人一张独立白卡。
- 桌面主轴 520–680px，可有一个轻量关系筛选区；手机为全宽列表，行内容保留 12–16px gutter。
- 本人和他人的关注/粉丝列表统一使用 `task` Shell：手机只有返回、标题和可选搜索，不显示 BottomNav；返回本人或对应公开主页。
- 头像/用户名入口、关系动作和进入会话是兄弟热区，不允许整行链接包裹按钮。

### 用户中心

- 本人和他人主页共享身份摘要、内容 Tab 和卡片流。
- 未登录访问本人主页时，桌面和手机均只显示登录边界；隐藏“完整资料 / 分享主页 / 设置”等本人操作。手机顶栏保留等宽占位，避免标题因菜单消失而偏移。
- 桌面不保留重复资产侧栏；本人私有内容由同页 Tab 切换。
- 手机页面背景可顶满视口，但身份信息、Tab 和 Feed 均有各自明确 gutter；“全宽”不等于卡片贴屏。
- Tab 切换只替换内容区域；身份头、Tab、高度和滚动语境保持稳定。

### 用户中心二级页

- `/me/following`、`/me/followers` 使用独立的 `relationship` 内容轴，不把列表折叠插回 `/me`；获赞只保留为资料卡里的只读统计，不创建内容轴。
- 桌面保留产品顶栏和返回主页链接；手机使用局部“返回 + 标题”顶栏，隐藏全局 BottomNav，底部只保留 safe-area 空间。
- 二级页的 loading、empty、error 与最终行/内容表面共用同一宽度、圆角和 gutter；加载更多错误只占据列表之后的局部区域。

### 详情与评论

- 详情主轴不超过 760px，正文 65–75ch。
- 手机媒体可以视觉贴边，作者、标题、正文、操作和评论仍回到 12–16px 阅读 gutter。
- 评论是连续线程，回复缩进不能把 320px 视口正文压到不可读。

### 消息与通知

- 桌面会话使用列表 + 内容双栏；列表宽约 300–360px，内容栏占剩余空间。
- 手机列表和会话是独立路由视图；不把两栏压缩并排。
- Composer 固定在当前会话底部并尊重键盘与 safe-area，消息区是唯一滚动层。
- 消息中心入口先进入私信；通知作为相邻一级任务，不把通知投影塞进会话双栏。
- 通知页只保留“互动消息 / 系统通知”两个二级视图。桌面可使用稳定侧栏或 Tab，手机使用可见的双项 Tab；切换分类只替换通知列表，不重建页面壳。

### 发布与草稿

- `/compose`、草稿恢复和已发布内容编辑在手机统一使用 `immersive` Shell；隐藏全局 TopNav/BottomNav，只保留取消/返回、任务标题、草稿入口和发布操作栏。
- 发布操作栏是唯一固定底栏并避让软键盘与 safe-area；正文滚动区不得被操作栏遮挡。
- `/drafts` 使用 `task` Shell，返回 `/compose`；恢复草稿后进入同一 `immersive` 编辑器，不创建第二套编辑页。
- 有未保存内容时返回、取消、系统返回和路由切换都使用同一离开确认语义。

### 设置与表单

- Section 通过标题、间距和 Divider 组织，不能把每个字段组做成浮卡。
- 桌面可使用侧导航 + 单一表单轴。
- 手机端整个 `/settings` 家族使用独立全屏 `task` Shell，不显示全局 TopNav 或 BottomNav。`/settings` 返回 `/me`，分类页返回 `/settings`；分类切换不得变成页内锚点。
- 设置总览与分类完成态、Skeleton、错误和权限状态共用同一局部顶栏与 12–16px 内容 gutter，不预留 64px BottomNav 空白。
- Dialog 的 Header、Body、Footer 三行结构不受页面布局影响。

## 6. Edge-to-edge 规则

允许贴视口边缘：

- 页面画布和主题背景；
- 手机顶部/底部导航；
- 详情主媒体、全屏 Lightbox；
- 明确定义的 Section Banner；
- 手机 Dialog/Sheet 的外表面。

必须保留 gutter：

- Feed 卡片网格；
- 头像、姓名、简介与关系统计；
- Tab 可读文字和横向滚动安全区；
- 列表行内容、错误动作与空状态；
- 评论正文和 Composer 内容。

任何贴边例外必须在对应 Blueprint 标注，不能由页面 CSS 偶然产生。

## 7. Grid 与 Stack

- 一维排列使用 Stack/Flex；二维卡片编排使用 Grid 或 Masonry。
- 普通自适应网格优先 `repeat(auto-fit, minmax(...))`；媒体高度差显著的 Feed 才使用 Masonry。
- 列宽由卡片 Profile 决定，Compact 理想宽度 180–280px；列数不应让卡片低于可读宽度。
- 长标题、中文/英文 handle、计数和按钮必须在 200% 缩放下保持可达，不依赖固定高度裁掉内容。

## 8. Skeleton 几何

| 页面 | 必须保留 | 只替换 |
|---|---|---|
| 首页 | 顶栏、频道、Feed 容器 | 卡片数据 |
| 用户主页 | 身份头几何、Tab、Feed gutter | 头像/文字数据与卡片 |
| Tab 切换 | 身份头、Tab、滚动位置 | 当前 Tab 内容区 |
| 详情 | 阅读轴、媒体比例、作者栏 | 内容与评论数据 |
| 消息 | 双栏/单栏结构、Composer 位置 | 会话和消息行 |
| 设置 | 局部顶栏、总览/字段宽度、返回层级 | 分类项、字段值和依赖数据 |

Skeleton 的媒体比例、头像尺寸、行数和卡片圆角必须对应当前 Pattern。不得用通用 Spinner 替代整页，也不得在数据到达后改变列数造成卡片横跳。

## 9. Overlay 与滚动

- 页面只保留一个主滚动容器；Dialog Body、会话消息区等任务表面才拥有局部滚动。
- Sticky 导航不得遮挡锚点、标题、焦点环或 Toast。
- Popover、菜单和 Tooltip 使用 Portal/top layer，不能被 Feed 卡片或媒体 `overflow` 裁切。
- 打开模态表面时锁定背景滚动并保存位置，关闭后恢复。

## 10. 验收视口

必须至少检查 320、390、768、1050、1440px，并补充：

- 200% 浏览器缩放；
- 手机浏览器动态工具栏与 safe-area；
- 超长用户名、无头像、四位数互动计数和长错误文案；
- 亮暗主题与 Portal 浮层；
- Skeleton 到最终内容的布局偏移。

验收标准：无横向滚动、无卡片裁切、无操作遮挡、Feed 外 gutter 一致、页面与状态使用同一内容轴。
