# LoveCards 错误翻译与恢复规范

> v1.1 · 本规范负责把 SDK/前端约束翻译为安全、具体、可恢复的用户文案。反馈组件与呈现层级由 [`FEEDBACK-AND-STATUS.md`](./FEEDBACK-AND-STATUS.md) 决定。

## 1. 基本原则

一条用户可见错误至少回答两个问题：发生了什么，以及下一步怎么处理。能够确定原因时同时说明原因。不得直接显示“参数错误”“未知错误”“服务器内部错误”“Request failed”或状态码等开发语言。

- 准确：只表达前后端能够确认的事实，不根据资源 ID、字段名或请求地址推测业务原因。
- 就近：字段和文件错误显示在对应控件附近；局部动作错误留在当前动作附近；整页加载失败才使用页面级错误状态。
- 可恢复：保留用户输入、所选文件和页面上下文；提供重试、重新选择或登录等明确动作。
- 一致：同一原因在头像、发布媒体、评论和消息中使用相同术语，不为追求文案变化而改写概念。
- 安全：不展示堆栈、内部路径、SQL、请求体或无法确认面向用户安全的详情。

## 2. 错误信息来源优先级

前端按下列顺序选择文案，命中后停止：

1. 前端已经确认的约束，例如文件类型、文件大小、字符数和必填项。
2. SDK `ApiError.details` 中通过安全白名单、且属于当前输入约束的具体原因。
3. 服务端返回的明确业务文案，例如“用户名已存在”“评论已删除”。
4. SDK `code` 或 HTTP `status` 对应的用户语义。
5. 当前操作的上下文兜底，例如“头像没有保存，请稍后重试”。

`details` 可以是字符串、字符串数组或字段对象。前端只把它作为分类证据；仅当首条短文本符合已知验证语义且不含路径、代码、堆栈或内部字段时才允许展示。不得把对象序列化后直接显示。若 `message` 只是通用包装（如“参数错误”），优先使用通过白名单的具体 `details`，否则使用当前表面的验证兜底。

## 3. 状态与文案映射

需要持续呈现的错误统一采用“状态标题 + 具体原因 + 下一步动作”的文案结构；视觉组件仍按影响范围选择 FieldStatus、scoped Banner 或 ResourceState，不要求机械拆成三行。

| 类别 | 用户可见结构 | 恢复动作 |
|---|---|---|
| 格式/字段验证 | `[对象]不符合要求。[明确格式或示例]` | 修改输入或重新选择 |
| 文件过大 | `[对象]超过大小限制。请选择不大于 [限制] 的文件。` | 重新选择 |
| 文件类型不支持 | `[对象]格式不支持。请选择 [格式集合]。` | 重新选择 |
| 文件损坏/不可读 | `无法读取这张图片。请重新导出或选择其他图片。` | 重新选择 |
| 未登录 | `登录后才能完成此操作。` | 去登录并保留返回位置 |
| 权限不足 | `当前账号不能[动作]。` | 返回或联系管理员；不展示无效重试 |
| 资源冲突 | 使用后端明确业务文案；没有时说明当前状态已变化 | 刷新状态或修改输入 |
| 请求过于频繁 | `操作太频繁，请稍等一会再试。` | 延迟重试 |
| 网络/超时 | `网络连接不稳定，请检查网络后重试。` | 重试并保留输入 |
| 服务端失败 | `[动作]暂时没有完成，请稍后重试。` | 重试；不归咎于输入 |

### 3.1 页面与列表加载状态

所有读取型页面使用同一套跨层分类。分类依据是用户能采取的恢复动作，不根据请求来自某个页面而改名，也不向用户暴露 SDK、端口或接口路径。

| 技术事实 | 页面标题 | 说明与动作 |
|---|---|---|
| SDK 网络错误、超时、HTTP status 0 | `无法连接到服务` | 检查连接并“重新连接” |
| HTTP 5xx | `服务暂时不可用` | 服务端未完成请求，允许“重新加载” |
| SDK 契约或返回数据结构不兼容 | `页面暂时无法读取数据` | 数据与当前页面不一致，允许“重新加载” |
| 401 | `登录状态已失效` | 引导重新登录，不伪装成网络问题 |
| 403 | `当前内容不可访问` | 说明权限边界，不提供无效重试 |
| 404 | `没有找到相关内容` | 说明删除或链接失效，不显示空列表 |
| 429 | `请求过于频繁` | 展示等待说明，稍后重试 |
| HTTP 200 且集合为空 | 业务空状态 | 说明内容如何产生；这不是错误 |

错误边界的优先级高于空状态。请求失败时，即使页面当前没有任何列表项，也必须显示对应错误，不能降级为“还没有内容”。已有内容的增量加载失败不得清空列表，只在列表尾部显示局部错误和重试。

可安全替代的数据源允许降级展示，例如推荐流不可用时展示最新公开内容；此时页面保持可用，并在内容上方用 scoped Banner 明确说明“原数据源不可用、当前显示什么”。不得把降级结果伪装成原算法结果，也不得显示整页空状态。

## 4. 文件上传

选择文件之前必须在控件附近写清支持格式和大小。浏览器 `accept`、前端校验、文案、测试与后端当前契约必须一致。

头像当前按默认存储策略支持 JPG、PNG、GIF、WebP，最大 10MB。若后端以后提供可查询的场景化上传策略，前端应改为读取策略，不继续硬编码渠道配置；页面不得显示内部 `scene`、MIME 或存储用途。

头像文件错误文案：

- 格式：标题 `图片格式不支持`；说明 `请选择 JPG、PNG、GIF 或 WebP。`
- 大小：标题 `图片太大`；说明 `请选择不超过 10MB 的图片。`
- 无法读取：标题 `图片无法读取`；说明 `请重新导出或选择其他图片。`

头像入口和上传控件不在同一表面：点击本人主页头像打开“更换头像”任务 Dialog。格式、大小和损坏错误作为 FileInput/FieldStatus 显示；网络、登录、权限和服务端失败作为 Dialog 内 scoped Banner 显示；成功关闭 Dialog 并 Toast“头像已更新”。不得把任何上传反馈插入用户主页身份头。完整状态和文案见 [`FORMS-AND-UPLOADS.md`](./FORMS-AND-UPLOADS.md)。

## 5. 呈现位置

### 5.1 认证边界

- 未登录不是业务空状态。私有入口应在导航层重定向登录，不在目标页面重复渲染“登录后查看……”内容。
- 认证初始化失败与未登录必须分开：前者使用服务/网络错误语义并提供重试，后者进入登录流程。
- 登录跳转应保留来源页面和必要的动作上下文；只允许站内单斜杠路径，登录成功后返回来源页面。
- 公开页面上的私有动作使用统一登录提示；同一动作不得同时播报 Toast、页面空状态和对话框三种提示。

- 输入框、FileInput 和媒体项目：值本身的错误使用关联的 FieldStatus；错误不能只靠红色区分。
- 点赞、收藏、关注等即时动作：成功可用 Toast；失败根据影响范围使用动作附近的恢复反馈，不能一律 Toast。
- 删除完成可用 Toast；删除前的高影响确认使用 AlertDialog，失败不得提前显示成功。
- 评论、私信和发布：错误紧邻编辑器，保留正文和附件；重新提交前不清空错误之外的状态。
- 列表和页面加载：使用 ResourceState，标题说明哪个区域失败，提供“重试加载”动作。
- 后台同步和加载更多：不得覆盖已显示内容；在对应区域使用 scoped Banner/Message 和局部重试。

动态错误使用 `role="alert"`；保存中、上传中和成功反馈使用 `role="status"`。错误出现后不得强制把焦点移离用户当前输入，提交型表单可在失败后把焦点移到首个无效字段。

## 6. 实现边界

默认主题通过统一错误翻译函数消费 SDK 的 `code`、`status`、`message` 和 `details`。页面必须提供与动作相关的 fallback；统一函数只负责识别通用错误类别，不猜测卡片、评论、用户或私信路由。

后端仍负责返回稳定业务错误码和可公开的验证详情。前端校验用于提前反馈，不能替代服务端验证，也不能通过解析中文文案决定业务流程；中文关键词只允许用于把旧版文件验证详情降级为更明确的上传说明。

## 7. 验收

- 任何已知文件格式或大小错误都显示具体限制，不出现“参数错误”。
- 400/422 且含验证详情时显示具体详情；详情缺失时显示当前表面的验证兜底。
- 401、403、413、415、429、网络错误和 5xx 均有不同、可执行的反馈。
- 网络、5xx、SDK 数据不兼容与成功空列表使用不同标题；同类错误在首页、发现、个人主页、消息和设置中保持相同语义。
- 失败请求不会因为数据数组为空而显示业务空状态。
- 错误后输入与文件选择不会被意外清空，重试不会重复提交。
- 错误可被读屏识别，键盘用户能完成修正与重试。
- 单元测试覆盖验证详情、通用参数错误、文件格式、文件大小、网络和服务端错误。
- 同一错误不会被 FieldStatus、Banner 和 Toast 重复播报。
- 头像上传失败不会改变主页身份头高度或挤压姓名、Tab 与 Feed。
