# LoveCards 交互表面规范

> v1.3 · 设计先行冻结。本文约束评论线程、搜索和移动壳层；Dialog、Modal、Alert 和移动 Sheet 的共享结构、焦点与滚动规则见 [`DIALOGS.md`](./DIALOGS.md)。运行实现必须映射到 Astryx 原生组件，不在页面里复制一套“看起来像组件”的 CSS。

## 1. 统一命题

交互要让用户感觉“内容在前，系统随手可用”：信息流保持安静，动作在需要时出现，状态反馈精确而短。评论不是一组松散的白色卡片，而是一条有层级的讨论轨道；搜索不是一条孤立输入框，而是从输入到结果的连续表面；手机端顶部和底部各自承担不同职责，不能重复放置同一入口。

视觉策略为 Restrained：冷中性画布、白色不透明内容面、Deep Rose 只用于当前状态和主要动作。玻璃材质只允许用于媒体上的临时控制，评论、搜索和导航不得默认玻璃化。

## 2. 移动壳层

### 2.1 结构

| 区域 | 规则 | 禁止 |
|---|---|---|
| 顶栏 | 56px；左侧品牌，右侧一个 44px 搜索触发器；滚动时保持稳定 | 顶栏头像与底栏“我的”重复 |
| 搜索面 | 点击触发器打开全屏 Search Dialog；输入框自动聚焦，结果在同一层更新 | 把桌面宽搜索框硬缩到手机 |
| 底栏 | 64px + safe-area；首页、发现、发布、消息、我的五个固定槽位 | 用大悬浮球遮住信息流、把“我的”再放到顶栏 |
| 发布 | 居中主动作但不遮挡文字；44px 命中区 | 只显示图标而没有可读名称/辅助文本 |

消息入口显示真实未读数；加载、空、错误和登录边界都在当前页面内表达。用户中心的唯一稳定入口是底栏“我的”，头像只在内容作者身份中出现。

### 2.2 桌面壳层

桌面顶栏为 68px：品牌 → 一级导航 → 内联 Typeahead 搜索 → 发布/主题/账号动作。账号动作保留在桌面，手机端不重复。搜索结果层使用 Portal 逃离滚动容器，宽度与输入轴对齐，最多 8 项。

### 2.3 消息与通知

- 收件箱需要登录；检查会话失败显示可重试的错误状态，未登录显示登录动作，不渲染假数据。
- 通知列表使用 SDK 返回的 `items`、`next_cursor` 和 `has_more`；未读行显示真实未读标记，打开单条或执行全部已读后更新未读数。
- 通知流优先解析 SDK 返回的单次 SSE 快照；解析失败或服务端不可用时降级为定时刷新，并保留手动刷新和错误提示。
- 会话列表、会话详情和发送都使用真实消息数据。会话地址无效、消息加载失败、空会话、收件人缺失和发送失败分别表达，不把权限或配置错误显示成“发送成功”。
- 私信发送中禁用重复提交；失败保留正文和客户端稳定 ID，允许安全重试。未登录用户只能看到登录边界。

## 3. 信息流卡片动作

- Compact 卡片的底部元数据栏固定为“作者 + 被动喜欢数 + 评论数 + 三点更多”。喜欢数和评论数只提供判断价值，不是按钮。
- 信息流不得直接显示喜欢或收藏按钮。喜欢只在内容详情页执行；收藏、取消收藏、复制链接和举报进入三点菜单。
- 举报自己的内容不显示。服务端没有提供的“不感兴趣”“减少推荐”等能力不得做成看似成功的菜单项。
- 游客可以浏览和复制公开链接；只有在触发收藏或举报时才引导登录，并保留当前返回地址。
- 设计预览和静态蓝图使用同一菜单位置与尺寸，但所有写操作禁用，不得发起 SDK 请求。发布页不渲染信息流卡片预览。
- 菜单触发器与每个菜单项的移动端命中区不小于 44px，支持键盘打开、方向键移动、Esc 关闭和焦点回归。

## 4. 搜索表面

### 4.1 Astryx 映射

- 桌面和移动均使用 `@astryxdesign/core/Typeahead`，不使用手写输入 + 手写下拉。
- 结果项使用 `TypeaheadItem`；图标只表达类型：内容、话题、状态。
- 移动包装为 Astryx `Dialog variant="fullscreen" purpose="info"`，关闭后焦点回到搜索触发器。

### 4.2 状态与时序

1. 空查询：展示最近内容/热门话题；若没有历史，展示“从话题开始探索”。
2. 输入：150–250ms 防抖；中文 IME composition 期间不发请求；新请求取消旧请求。
3. 加载：只在结果层显示局部 Skeleton，不让整页跳动。
4. 有结果：类型 → 标题 → 作者/话题上下文；Enter 打开高亮项，方向键移动，Esc 关闭。
5. 无结果：保留输入，提示“换个关键词试试”，提供进入完整搜索页的动作。
6. 错误：结果层内联显示重试；不把错误变成空白页。

### 4.3 页面搜索与顶栏搜索

顶栏搜索是快速进入内容/话题的入口；发现页搜索是可持续编辑的查询表面。二者共享同一 `SearchSource` 和结果语义，但发现页保留 URL `q`、范围 Tabs 和完整结果流。不得出现两个不同的结果排序或不同的“搜索中”文案。

## 5. 评论线程与回复

### 5.1 信息结构

评论区是一条 `CommentThread`：

```text
讨论标题 / 数量
└─ RootComment
   ├─ ReplyComment
   └─ ReplyComment
└─ RootComment
Composer（新评论或回复）
```

- Root 评论与回复使用同一行语法，不使用每条评论一张卡片。
- Root 行：头像 32px、作者/时间、正文、轻量动作；回复缩进 20px，左侧只用 1px 分隔线，不做彩色粗侧条。
- 只有存在回复时才显示“2 条回复”；默认展示首层和最多 3 条回复，更多回复进入同页展开，不跳到黑色中转页。
- 删除评论保留“原评论已删除”的关系占位，避免回复失去上下文。

### 5.2 Composer

- 使用 Astryx `ChatComposer` + `ChatComposerInput` + `ChatSendButton`，`elevation="none"`，内容面与详情同源。
- 新评论 placeholder：“写下你的回复”；回复状态显示 `回复 @用户名` 和 44px 取消按钮。
- Enter 发送，Shift+Enter 换行；IME 组合期间 Enter 不发送；发送中保留内容并禁用重复提交。
- 错误显示在 composer 下方，输入内容不清空；成功后清空并把焦点留在 composer。
- 右侧显示“已回复 / 140”计数，达到限制时仅禁用发送，不截断用户文本；与当前后端评论校验保持一致。

### 5.3 SDK 边界

当前 SDK 已有 `comments.cardList`、`comments.create(parent_id)`、编辑和删除，因此回复可真实接入。`parent_id` 必须属于当前卡片；若后端未验证，前端仍只发送当前卡片内已读到的 ID，并在后端契约中列为必须补齐的归属校验。

## 6. 当前互动范围

当前产品只登记普通评论线程，不提供投票卡片、单选规则或基于评论 marker 的兼容协议。`discussion` 是普通内容类型：信息流展示标题与正文，详情页使用同一 `CommentThread` 承载根评论和回复。

- 历史或未知互动声明不能生成操作控件，也不能改变卡片类型、权限或资源归属。
- 评论必须按普通正文显示、编辑和删除；前端不再把任何评论解释为协议事件。
- 若未来重新评估结构化互动，必须先完成独立产品决策、后端资源契约、SDK 能力和新的设计验收，不能复用当前评论正文作为事件存储。

## 7. 交互验收矩阵

| 表面 | 桌面 | 手机 | 键盘/读屏 | 无 API |
|---|---|---|---|---|
| 搜索 | 原位 Typeahead | 全屏 Dialog | 方向键、Enter、Esc、焦点回归 | 显示配置错误，不显示假结果 |
| 评论 | 单列线程 + 内联 composer | 同结构，空间不足时转 Sheet | Tab、Enter/Shift+Enter、IME | 登录提示，保留正文 |
| 移动壳 | 不适用 | 顶部搜索、底部我的唯一入口 | 每项 44px | 真实未读、空、错误、登录状态 |
