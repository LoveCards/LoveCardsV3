# LoveCards 导航、Tab 与选择规范

> 状态：v1.9。本文区分路由导航、同页视图切换、值选择、筛选和动作，并定义内容预览层与情境登录的 URL、历史与返回。表面选择见 [`DIALOGS.md`](./DIALOGS.md)，动效轨迹见 [`MOTION.md`](./MOTION.md)。

## 1. 语义选择

| 用户意图 | 组件 | URL 行为 |
|---|---|---|
| 前往另一页面/资源 | Link、TopNav、BottomNav、Breadcrumbs | 路由变化，支持打开新窗口和历史记录 |
| 同一页面切换相关视图 | TabList | 页面壳不变；必要时同步 query/path |
| 选择一个值或模式 | SegmentedControl、RadioList、Selector | 表单值变化，不产生页面导航语义 |
| 筛选当前数据 | Chip/ToggleButton/MultiSelector | 保留页面结构，URL 可同步筛选条件 |
| 执行动作 | Button/IconButton/Menu item | 不伪装成链接或 Tab |
| 展开/收起内容 | Collapsible | 不创建无意义路由 |

视觉相似不能覆盖语义。Tab 不能提交表单，SegmentedControl 不能替代路由，按钮不能用来伪装普通链接。

### URL 规范地址

| 用户任务 | 规范地址 | 地址语义 |
|---|---|---|
| 浏览推荐 | `/` | 默认公开内容流 |
| 浏览动态 | `/activity` | 受保护的关注更新、全局一级入口 |
| 主动发现 | `/explore` | 公开内容流，默认最新发布，`sort` 可切换排序 |
| 开始搜索 / 查看结果 | `/search`、`/search?q=<词>`、`/search/{posts|users|topics}?q=<词>` | 空查询是入口；综合与范围结果由 path 区分，关键词由 `q` 表示 |

URL 层数不决定 IA 深度或 Mobile shell。`/activity` 是一级全局入口，不由公开 Feed 的过滤参数实现。`/me?tab=…`、`/compose?draft=…`、`/compose?edit=…` 与 `/media/:id?index=…` 的 query 分别表示同页视图、编辑任务和媒体位置。后端 `/me/feed/following` 是 API 地址，不随前台路由改动。

`/feed/following`、`/?feed=following`、`/?channel=following` 是动态旧链接；`/feed/latest`、`/?channel=latest` 是发现旧链接。进入时以 `replace` 跳到 `/activity` 或 `/explore`，移除旧 `feed/channel` 键并保留其他有效 query、hash 和路由 state；两个旧键冲突时 `following` 优先于 `latest`。`/?channel=recommended` 与未知值归一到 `/`。规范化先于登录守卫，使登录返回目标、导航选中态与 Card Preview 来源均使用规范地址。前进、后退和刷新不得重新出现旧地址或多出历史项。旧入口由前端路由负责人维护；确认外部旧链接不再使用且回归门禁覆盖替换入口后才移除兼容重定向。

`/search?q=…` 是综合结果；`/search/{posts|users|topics}?q=…` 是完整范围。内容范围默认按匹配程度，选择最新发布写入 `sort=latest` 并回第一页；翻页、刷新和预览返回保留排序。其他范围及综合页移除排序参数。无词的范围地址回到 `/search`；未知范围有词时回到综合结果，无词时回到搜索入口。无效 `page`、`sort` 和重复参数按搜索契约归一，保留有效的 `q`、其他无冲突参数与 hash。清除关键词回到 `/search`。完整行为见 [`SEARCH.md`](./SEARCH.md)。

## 2. IA 深度与移动壳

页面的业务层级与移动端外壳是两条独立轴，不能仅凭 URL 层数或是否出现在全局入口中决定是否显示 BottomNav。

### IA depth

| 深度 | 定义 | 典型入口 |
|---|---|---|
| 一级主页面 | 可在全局导航间稳定切换的长期目的地 | 首页、动态、消息中心、我的 |
| 二级任务页 | 从一级页面进入、完成一类明确任务后返回上级 | 关注/粉丝、草稿箱、设置总览、会话 |
| 三级深层任务 | 在二级任务内继续完成单一高专注操作 | 设置分类、密码/邮箱任务、账号恢复步骤 |

### Mobile shell

| Shell | 全局顶栏 | BottomNav | 局部顶栏 | 适用场景 |
|---|---|---|---|---|
| `standard` | 使用当前一级语境 | 显示 | 标题/搜索/当前页动作 | 首页、动态、发现频道、消息中心、我的 |
| `task` | 隐藏 | 隐藏 | 返回 + 标题 + 必要动作 | 关系页、草稿箱、设置栈、私信会话 |
| `immersive` | 隐藏 | 隐藏 | 取消/返回 + 任务状态或主动作 | 发布/编辑、媒体查看、长输入任务 |
| `gateway` | 隐藏 | 隐藏 | 品牌/返回入口按认证流程决定 | 登录、注册、账号恢复 |

- 同一 IA 深度可以使用不同 Shell；例如 `/compose` 是全局发布入口，但手机编辑器仍使用 `immersive`。
- `task` 和 `immersive` 只保留系统 safe-area，不预留 BottomNav 高度，也不能渲染不可见的全局导航占位。
- 页面从 Skeleton、Empty、Error、Permission 切换到完成态时，Shell 不得变化。
- 浏览器/系统返回优先恢复真实历史；无有效站内历史时使用下表的固定上级。
- 路由模块加载与身份检查期间，手机任务壳立即显示该任务的标题和返回入口。受保护内容等待身份检查。
- 手机搜索入口、综合与范围结果使用同一个搜索任务壳。局部返回退出整个搜索任务；浏览器返回逐步恢复关键词、范围、排序和页码。从搜索或发现打开话题时，局部返回恢复准确来源。
- 从卡片预览进入完整详情时，继承可信站内来源与卡片焦点。返回恢复频道、查询、排序、页码与原滚动位置。独立访问完整详情时回到首页。

| 路由 | IA depth | Mobile shell | 固定上级 |
|---|---|---|---|
| `/me`（本人主页或游客视图）及本人资产 Tab | 一级 | `standard` | — |
| `/me/following`、`/me/followers` | 二级 | `task` | `/me` |
| `/user/:uid/following`、`/user/:uid/followers` | 二级 | `task` | `/user/:uid` |
| `/messages`、`/inbox`、`/inbox/system` | 一级 | `standard` | — |
| `/messages/:conversationId` | 二级 | `task` | `/messages` |
| `/search`、`/search/:scope` | 二级浏览任务 | `task` | 来源页；直达返回首页 |
| `/topic/:slug` | 二级浏览任务 | `task` | 来源页；直达返回发现 |
| `/post/:id` 完整详情及评论深链 | 二级阅读任务 | `task` | 来源信息流；直达返回首页 |
| `/compose`、`/compose?draft=*`、`/compose?edit=*` | 一级入口 / 深度任务 | `immersive` | 来源页；缺失时 `/` |
| `/drafts` | 二级 | `task` | `/compose` |
| `/settings` | 二级 | `task` | `/me` |
| `/settings/*` | 三级 | `task` | `/settings` |
| `/auth/*` | 认证流程 | `gateway` | 来源页；缺失时 `/` |

## 3. 全局导航

### 登录边界

- 手机公开页的全局账号入口统一为底栏“我的”。游客可从“我的”登录正式账号或结束游客会话。
- 无会话时普通点击“动态、我的、消息、发布”等私有一级入口，在当前页面打开共享登录 Dialog / 手机 Sheet；登录成功后进入原目标路径，取消则留在原页面。新标签、修饰键激活及直达私有网址仍由路由守卫进入 `/auth/login`，原目标路径（含 query 与 hash）通过路由 state 保留。游客会话可进入精确的 `/me` 游客视图和 `/settings/session`，其他私有入口仍走登录边界。
- `/activity` 由共享登录守卫保护；推荐 `/` 与发现 `/explore` 保持公开。桌面侧栏将发现列在推荐之后，再显示动态。手机动态保留在底栏，发现位于浏览顶栏。发现默认按最新发布排序。发现内容与排序契约以 [`DISCOVERY.md`](./DISCOVERY.md) 为准。
- 私有深链（例如会话、草稿、设置分类）由共享 `ProtectedRoute` 兜底：认证检查中只显示中性的认证 Skeleton，未登录重定向登录，认证服务失败显示统一错误状态。
- 公开页面仍可访问；点赞、收藏、评论、关注、私信等需要账号的动作使用可直接完成登录的共享情境登录表面。来源页面没有模态层时桌面为紧凑 Dialog、手机为上拉 Sheet；CardPreviewSurface 内按弹窗规范在当前阅读区展开。当前 URL 不变，成功后仍留在来源资源，更新会话并恢复触发器焦点。当前输入或评论草稿由原组件保留，登录本身不自动重放写操作。登录表面始终提供 `/auth/login` 的完整页面入口。
- 评论区权限提示中的“去登录”是显式导航链接：进入独立 `/auth/login` 页面，并以路由 state 的 `from` 保留当前内容路径、query 与 hash。登录成功后回到该内容；在 Content Preview 中点击此链接也离开预览层，不在评论区插入登录表单。评论的回复、喜欢等动作仍按上一条使用情境登录。
- `/auth/login`、`/auth/register` 和 `/auth/recovery` 始终是可直接访问、刷新和分享的独立页面。未登录用户普通点击“我的”或其他受保护一级入口时，在当前页面打开情境 Dialog/Sheet，并提供完整登录页入口。直达受保护路由及独立打开登录地址时进入 `/auth/login`。登录成功后进入已验证的站内 `from`，缺失时按认证页默认目标处理。注册和账号恢复使用各自的独立页面。
- 情境登录不改变资源 URL，打开时也不增加历史项；Escape 或明确关闭恢复触发器。浏览器 Back 按真实历史返回，并同时清理登录表面；不拦截浏览器历史来制造同 URL 项。CardPreviewSurface 内的登录表单属于当前阅读层的局部状态；取消回到原动作，浏览器 Back 仍按 Card 的历史返回来源列表。
- 路由守卫是主门禁，页面内部保留 SDK 401/403 防御性处理，但不得把未登录误报为空列表或网络错误。
- `from` 只接受单斜杠开头且不以 `//` 开头的站内路径，禁止开放重定向。

### 桌面

- 主导航位于左侧栏，依次为站点标识、推荐、发现、动态、消息、发布、我的。推荐指向 `/`，发现指向 `/explore`，搜索位于内容区上方。侧栏底部放主题切换和版权。按钮显示当前偏好，点击按浅色 → 深色 → 自动循环切换，立即生效并记住选择。自动模式跟随系统；外观与无障碍页面仍提供主题和减动设置。
- 当前项使用浅玫瑰色胶囊和较重字重，发布动作使用柔和的强调色。话题归发现，私信与通知归消息。搜索有自己的搜索工具，侧栏主页入口不高亮。入口使用真实站内链接。
- “我的”是桌面唯一的全局账号入口。正式登录后显示本人头像，缺失或加载失败时使用头像组件的替代标记。匿名用户沿用情境登录，成功后进入本人主页。游客进入游客主页，可注册、正式登录或结束游客会话。正式账号退出位于个人设置的会话页。

### 手机

- `standard` Shell 的 BottomNav 保留 4–5 个稳定入口并尊重 safe-area；`task`、`immersive`、`gateway` 不显示 BottomNav。
- 游客点击 BottomNav“我的”进入 `/me` 游客视图，显示当前身份、正式账号入口、设置与结束游客会话；不展示本人资料、关系统计或私有内容。结束会话后以 replace 返回公开首页，服务器退出未确认时显示跨路由可见的会话提示。
- 推荐和发现的顶栏左侧显示品牌图标，中间显示“推荐 / 发现”，右侧为搜索。两页共用底栏“首页”语境。搜索等独立任务使用各自的返回栏。
- 发布入口不能使用遮挡内容的大悬浮球；视觉强调不改变 44px 触控和可读名称。
- 桌面侧栏“发布”是指向 `/compose` 的真实 Link；普通站内点击带来源历史状态打开宽发布 Dialog，新标签、直达、刷新进入独立页。手机底栏“发布”直接切换到 `/compose` 独立任务页；信息流不重复放置“写随笔”入口。所有表面使用同一编辑轴和发布状态。弹窗浏览器返回关闭并恢复来源；有未保存内容时先确认，取消确认维持当前表面。
- 未读数使用 Badge，但必须有可访问文本，例如“消息，3 条未读”。

### 消息中心

- 私信和通知及其子页面使用消息中心的局部顶栏，省略顶部全站搜索。桌面保留产品侧栏，私信保留会话筛选入口。
- 桌面 TopNav 与手机 BottomNav 的“消息”主入口都进入 `/messages`；第一层先展示私信，并通过 `messages.conversations/list/send` 完成会话任务。
- 消息中心始终只有一个页面标题“消息中心”和一组一级 Tab（“私信 / 通知”）。桌面私信使用“会话列表 + 当前会话”双栏工作区；手机先展示会话列表，进入会话后使用 `/messages/:conversationId` 独立任务壳，不显示全局 BottomNav。列表摘要和身份链接是兄弟热区，身份进入用户主页，摘要负责打开会话。
- 消息中心一级在“私信 / 通知”之间导航；通知页内部只保留“互动消息 / 系统通知”两个相关视图。默认 `/inbox` 对应 `engagement`，`/inbox/system` 对应 `system`。
- `/messages/search` 是手机的会话筛选任务页，`?q=` 用于刷新及前进/后退后恢复关键词；桌面 `/messages` 的即时筛选可留在页面局部状态。两处只筛选已加载的会话列表，不宣称搜索全部消息正文或服务端历史。空词使用 `/messages/search`，清除词时移除 `q`。
- `/inbox/message`、`/inbox/social`、`/inbox/interaction` 是历史深链，统一重定向到 `/inbox`。重定向后不保留旧筛选状态，也不触发旧分类请求。
- `type=message` 只表示私信产生的通知投影；进入私信列表、读取会话与发送消息仍由 `/messages*` 承担，不能把通知列表设计成第二套私信页。

### 设置栈

- 手机端整个 `/settings` 家族使用独立 `task` Shell，不显示全局顶栏或 BottomNav。
- `/settings` 是设置总览，返回目标为 `/me`；`/settings/security|privacy|appearance|session|notifications` 返回 `/settings`。
- 设置分类之间通过总览或明确的同栈导航切换，不能返回后落入不同的页面壳，也不能把设置总览伪装成“我的”Tab 内容。
- 桌面保留产品侧栏与顶部搜索，设置分类使用自己的局部导航；移动端的独立全屏栈不改变真实子路由语义。

## 4. 用户主页 Tab

- `/me` 的本人视图显示“内容 / 喜欢 / 收藏 / 历史”。
- 点击 Tab 只替换卡片数据与对应状态，身份头、关系统计、Tab 和 Feed 容器保持不变。
- `/me` 是本人“内容”的唯一默认 URL；内容总数直接写在“内容”Tab 标签中。喜欢、收藏、历史使用 `/me?tab=likes|saved|history`，浏览器前进/后退恢复 Tab。旧的 `?tab=content` 仍兼容但不作为新入口。
- 无效 `tab` 值以 `replace` 回到 `/me`，保留其他有效 query 与 hash；不得显示默认内容却留下错误 Tab 地址。
- 资料卡不再显示“动态”统计。关注和粉丝是两条明确的统计 Link，分别进入 `/me/following`、`/me/followers`；获赞只显示服务端聚合数字，不提供明细入口。不得使用折叠面板或把当前页卡片点赞数当作收到的互动总数；历史 `/me/likes-and-saves` 深链重定向回 `/me`。
- 旧 `/me/library/{likes|saved|history}` 只作为兼容入口，最终渲染同一主页壳；不得维护第二套列表页面。
- `/user/:uid` 显示一个“内容”Tab 作为结构锚点，不暴露私有资产。
- 评论只在内容详情和讨论线程中展示；用户中心不提供评论记录入口或独立页面。

主页统计进入的关系二级页使用独立任务壳：桌面保留产品侧栏、顶部搜索和返回主页链接；移动端使用“返回 + 标题”的局部顶栏，不显示全局 BottomNav。二级页拥有自己的 loading、empty、error 和分页状态，不把列表插回主页身份头下。获赞是只读统计，不创建二级任务壳。

Tab 切换期间只在内容区显示与 Feed 完成态对应的 Skeleton。空、404、403、网络失败也在同一内容区表达。

## 5. 内容与身份导航

- 有效 UID 的头像和用户名共同组成一个 `AuthorIdentity` 链接，进入 `/user/{uid}`。
- UID 是公开身份的稳定展示值；展示昵称、`@username`、内部数字 id、注销状态或空 UID 不能推导主页地址。
- 卡片作者、卡片正文、更多菜单、喜欢/收藏/评论是兄弟热区，不允许嵌套 `<a>`。
- 点击作者不能触发卡片详情；点击卡片正文不能触发作者链接或动作。
- 评论、会话、关系列表和通知 actor 遵守相同身份规则，但排版使用对应变体。

### 5.1 Card 预览与完整详情

- Card 的唯一标准地址仍是 `/post/:id`。在首页、发现/搜索、话题、本人或他人主页、收藏和历史等保持挂载的列表中，以普通左键或触屏激活卡片主表面时，先保存来源 location（含 query）、滚动位置和触发器身份，再把历史 push 到 `/post/:id`，在保留的来源页上呈现 Content Preview。预览资格只在当前 SPA 会话内有效；新文档启动时即使浏览器恢复旧 history state，也渲染完整详情。直接访问、刷新、站外打开、缺少可恢复来源或来源已卸载时同样渲染完整详情页。
- 卡片主表面仍是可复制地址的真实 Link。Ctrl/Cmd/Shift 点击、中键、右键“在新标签页打开”以及键盘要求新上下文的操作保持浏览器原生行为；新标签页以完整详情页打开。作者、话题、更多菜单、互动按钮是兄弟热区，不触发内容预览。
- 预览层的关闭按钮和 Escape 返回来源 location，恢复原筛选与滚动位置，焦点回到触发卡；来源卡已经消失时焦点回到列表标题。浏览器 Back 等价于关闭；Forward 可重新打开同一资源预览。不得用额外历史项实现“完整详情”，也不能让关闭按钮无条件 `navigate(-1)` 跳到站外；来源失效时关闭使用该来源页面的安全路由，无法确定时回到 `/`。
- “查看完整详情”保持当前 `/post/:id` URL，以 `replace` 更新当前历史项的内部呈现状态并退出模态层；之后 Back 返回来源列表，Forward 仍进入完整详情。完整详情的分享地址始终是 `/post/:id`，不能在 URL 里塞入仅用于动画的 `from`、滚动坐标或 modal 标记。来源页重新挂载时按保存的筛选与滚动恢复。
- 预览层内切换另一条 Card、打开评论深链 `/post/:id/thread/:commentId` 或媒体任务时，必须显式定义历史与最上层表面；第一阶段不在预览层内提供下一条/上一条 Card 导航。评论深链进入完整详情并定位评论；媒体查看器关闭回到原 Card 阅读位置。与完整详情相同，预览层中登录/权限/404/删除态不能产生第二条虚假历史。

## 6. 返回与层级

- 浏览器/系统返回优先恢复真实历史；没有站内历史时回到明确上级路由。
- 返回按钮的 fallback 必须来自本规范的路由矩阵；不能统一写死为首页，也不能依赖 `navigate(-1)` 产生站外或循环返回。
- 详情页来自 Feed 时尽量恢复原滚动位置和筛选状态。
- Breadcrumbs 只用于设置、深层管理或清楚的资源层级；移动端使用返回按钮与标题，不横向挤入完整面包屑。
- 关闭 Dialog 恢复触发器焦点；关闭 Lightbox 恢复原媒体。手机搜索的返回按路由任务规则处理。

## 7. Tabs 键盘行为

- TabList 是一个键盘导航组：Tab 进入，方向键移动，Enter/Space 激活，Home/End 到首尾。
- 当前 Tab 使用 `aria-selected`，面板通过 `aria-controls`/`aria-labelledby` 关联。
- 上述 TabList 语义用于同页视图切换，例如本人主页资产分类。消息中心“私信 / 通知”跨 `/messages` 与 `/inbox` 路由，保留真实 Link 和 `aria-current="page"`；不为视觉外观强加 TabList 角色或指向未挂载面板的 `aria-controls`。
- 横向溢出允许滚动，但当前项必须滚入可见区，首尾保留 gutter。
- 标签栏可横向滚动不代表内容区支持左右滑动切 Tab；当前不启用内容区横滑手势，也不强制平滑滚动标签栏。
- 内容数量和未读 Badge 不改变 Tab 的可访问语义；数量应作为标签的次级文本，不得挤压其他 Tab 的最小触控宽度。

## 8. 筛选与分页

- 2–5 个简单互斥筛选可使用 SegmentedControl；内容分类视图使用 TabList。
- 复杂筛选使用 Popover/Sheet 内表单，不把一排胶囊无限横向堆叠。
- Cursor 列表使用“加载更多”或连续加载状态，不伪造页码；真正 page-based 数据才使用 Pagination。
- 通知的 `next_cursor` 是不透明复合游标，只能原样回传当前分类请求；URL 不保存、不暴露也不构造 cursor。
- 切换筛选时取消旧请求，清楚区分首次加载和加载更多；URL 只保存可分享、可恢复的筛选。

## 9. 禁止

- 禁止点击 Tab 后进入不同页面模板。
- 禁止为同一入口同时保留顶栏和底栏副本。
- 禁止用整卡链接包裹内部按钮或作者链接。
- 禁止使用没有可读名称的图标导航。
- 禁止把 Button 写成只有 `onClick(navigate)` 的假链接；语义导航必须可复制地址、打开新窗口和被读屏识别。
- 禁止把服务端 `action_url` 之外的信息拼成通知路由。
- 禁止在 `task`、`immersive` 或 `gateway` Shell 底部保留 BottomNav 的高度占位。

## 10. 验收

- 鼠标、Tab、方向键、Enter、Space、浏览器前进/后退得到一致结果。
- 用户主页切 Tab 不重建页面壳、不跳顶、不改变 Feed gutter。
- 所有作者链接使用真实 username，缺失时诚实降级。
- 320px 下 Tab 可滚动、当前项可见、操作不重叠。
- 焦点在导航、Overlay 和路由切换后都有合理落点。
