# LoveCards 表单与文件上传规范

> 状态：v1.0。本文覆盖字段结构、校验时机、异步提交、文件上传和头像编辑。反馈组件选择见 [`FEEDBACK-AND-STATUS.md`](./FEEDBACK-AND-STATUS.md)，Dialog 结构见 [`DIALOGS.md`](./DIALOGS.md)。

## 1. 表单原则

- 一个表面只服务一个清楚任务；主动作每个 Footer 最多一个。
- Label 永久存在，Placeholder 只提供输入示例。
- 帮助信息在输入前解释限制，错误在输入后解释失败，二者不能合成一条长句。
- 提交失败保留用户输入、选择、滚动位置和任务上下文。
- 前端校验用于提前帮助，后端仍是权限和业务规则的真源。
- 标准 Astryx 输入已经提供 Label、Description 和 Status 时，不在外面重复包一套 Field。

## 2. 字段结构

```text
Field
├─ Label + required/optional
├─ Description（稳定规则或示例）
├─ Control
└─ FieldStatus（仅在存在反馈时）
```

### 布局

- 单列任务默认使用纵向 Label，字段间距 16–20px。
- 桌面设置页只有在标签稳定、字段短且宽度足够时使用横向标签；手机统一转纵向。
- 相关字段使用 `FormLayout` 和 Section 分组，不为每组再套一张 Card。
- 字段宽度由预期内容决定：验证码、时间和数量不占满长行；用户名、链接和正文使用可读宽度。

## 3. 校验时机

| 校验 | 时机 | 规则 |
|---|---|---|
| 必填 | 离开字段或提交 | 用户尚未交互时不提前标红 |
| 格式/范围 | 有足够输入后或离开字段 | 中文输入法组合期间不校验最终值 |
| 服务端唯一性 | 停止输入并防抖，或提交 | 请求可取消，旧结果不能覆盖新值 |
| 跨字段 | 提交或相关字段都完成后 | 错误附着在能修正问题的位置 |
| 文件限制 | 选择/拖入后立即 | 使用与后端一致的 accept、size、count |

错误清除以问题确实修正为准，不能在用户一输入新字符就假装成功。Success FieldStatus 只在确有价值时使用，例如用户名可用；普通字段不逐项显示绿色对勾。

## 4. 提交状态

- `idle`：主动作按有效性决定是否可用。
- `submitting`：保留按钮宽度，文案改为具体进行时，例如“保存中”；设置 `aria-busy`，禁止重复提交。
- `field-error`：聚焦或定位首个无效字段，保留其他值。
- `task-error`：使用表单顶部或 Footer 上方的 scoped Banner，不把未知服务端错误绑到某个字段。
- `success`：更新原页面状态；短确认使用 Toast，不显示成功 Dialog。

离开有未保存修改的表面时才使用确认。保存中是否允许关闭由任务风险决定；文件正在传输时默认阻止误关闭并说明状态。

## 5. 选择控件

- `CheckboxInput`：单个需要提交的布尔选择。
- `Switch`：切换后立即生效的设置。
- `RadioList`：少量选项单选且需要同时比较。
- `Selector`：中等数量、无需搜索的单选。
- `Typeahead`：较大或异步数据集的单选。
- `MultiSelector` / `Tokenizer`：多选；前者适合有限列表，后者适合搜索并累积选择。
- `SegmentedControl`：2–5 个互斥值或模式，不承担页面导航。
- `TabList`：同一页面相关视图切换，不改变页面结构。

## 6. 文件上传选择

| 场景 | 形态 | 理由 |
|---|---|---|
| 头像、单个附件 | compact `FileInput` 或小型 dropzone | 任务集中，不占据页面主体 |
| 发布图片/视频 | `FileInput mode="dropzone"` + 缩略图队列 | 支持拖放、排序、数量和移除 |
| 移动端 | 点击选择为主，拖放为增强 | 不用“拖到这里”作为唯一说明 |
| 立即上传 | `changeAction`/受控异步状态 | 选择后立即显示预览与进度 |
| 提交时上传 | 本地预览 + 提交队列 | 明确文件尚未上传，失败可单项重试 |

上传前必须声明 `accept`、最大体积和最大数量。说明使用人类可读格式，不显示 MIME、字节数或内部 scene 名。

## 7. 文件状态模型

```text
empty → selected → validating → ready → uploading → uploaded
                    ↘ invalid
                               ↘ upload-error → retrying
```

- `selected/validating`：显示文件名或预览，不提前显示成功。
- `invalid`：文件未进入上传队列；FieldStatus 说明具体限制。
- `uploading`：显示 Spinner 或真实 ProgressBar，移除和关闭策略明确。
- `uploaded`：显示预览与替换/移除动作。
- `upload-error`：文件级错误留在对应项目；任务级错误使用 scoped Banner。

多文件上传每个文件拥有独立状态。一个文件失败不能把全部成功文件清空；主动作应说明是否允许部分成功，默认发布要求所有必需文件成功。

## 8. 头像编辑蓝图

### 触发与表面

本人主页头像是一个 44px 以上的编辑按钮。点击后打开 `FormDialog`，桌面宽度约 480px，手机使用全宽任务表面；这不是资料二级页，也不改变主页身份头。

### 默认态

- 96px 当前头像预览。
- 标题“更换头像”。
- Description：“选择清晰的正方形图片，发布后会用于主页、评论和消息。”
- FileInput：“选择图片”；辅助说明“JPG、PNG、GIF 或 WebP，最大 10MB”。
- Footer：“取消”与“保存头像”；未选择时保存禁用。

### 文件错误

| 原因 | 标题 | 说明 | 动作 |
|---|---|---|---|
| 类型 | 图片格式不支持 | 请选择 JPG、PNG、GIF 或 WebP | 重新选择 |
| 大小 | 图片太大 | 请选择不超过 10MB 的图片 | 重新选择 |
| 损坏 | 图片无法读取 | 请重新导出或选择其他图片 | 重新选择 |

这些内容属于 FileInput 的 `status`，不创建 Banner，也不插入主页身份区域。

### 任务错误

| 原因 | Banner 文案 | 动作 |
|---|---|---|
| 网络 | 网络连接不稳定，头像还没有上传 | 重试上传 |
| 登录失效 | 登录状态已失效，重新登录后可以继续 | 重新登录 |
| 权限 | 当前账号不能更换头像 | 返回 |
| 服务端 | 头像暂时没有保存，已保留你选择的图片 | 重试上传 |

任务错误 Banner 位于 Dialog Body 顶部、预览之前。错误与预览同属一个内容轴，不覆盖 Header、Footer 或文件控件。

### 成功

保存成功后关闭 Dialog、恢复头像触发器焦点、更新所有当前用户头像缓存，并显示 Toast“头像已更新”。如果后续资料写入失败，不能提前替换为永久成功状态。

## 9. 无障碍与移动端

- FileInput 必须有可访问 Label；格式说明通过 Description 关联。
- 状态通过 Astryx FieldStatus/`aria-describedby` 关联到控件，error 同时设置 `aria-invalid`。
- 文件移除、重新选择和重试均可键盘操作；图标按钮有上下文名称。
- 手机软键盘和系统文件选择器返回后，Dialog 保留状态和滚动位置。
- 预览图片有描述当前状态的 alt；装饰性裁剪遮罩不进入无障碍树。
- 触控目标至少 44×44px，错误文案在 320px 下换行而不挤压动作。

## 10. 验收

- Label、Description、Control、Status 的语义和视觉顺序一致。
- 头像默认、格式错误、大小错误、损坏、上传中、网络失败、权限、成功均有设计状态。
- 错误不会改变用户主页身份头高度，也不会与姓名、Tab 或卡片流重叠。
- 选择失败保留任务上下文；可重试场景保留文件，不可重试场景明确要求重新选择。
- 键盘、读屏、320/390px、亮暗主题和减少动态通过。
