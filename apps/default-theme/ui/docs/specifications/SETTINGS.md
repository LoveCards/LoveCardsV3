# LoveCards 设置体系规范

> 状态：v1.2。本文定义 `/settings*` 的信息架构、扩展方式、桌面与移动布局以及 SettingsGroup 的状态边界。用户能力是否属于设置以及当前 SDK 覆盖，以 [`USER-SELF-SERVICE-MATRIX.md`](../implementation/USER-SELF-SERVICE-MATRIX.md) 为准。字段与提交规则继续遵循 [`FORMS-AND-UPLOADS.md`](./FORMS-AND-UPLOADS.md)，反馈组件选择遵循 [`FEEDBACK-AND-STATUS.md`](./FEEDBACK-AND-STATUS.md)。

## 1. 信息架构

- 设置按用户任务分为稳定分类，不按当前接口或数据库表拆分。
- 桌面使用“分类导航 + 单一设置工作区”；右侧只能有一个主任务轴。
- 分类入口必须对应真实子路由；尚未实现的能力不能伪装成可点击入口。
- `/settings` 是真实的设置总览，不再固定跳到外观页。总览只显示真实分类、能力范围和当前位置，不复制各分类的表单。
- 每个分类使用稳定子路由，分类导航不混用 hash 定位和页面跳转。
- 新增分类只修改共享导航登记和对应页面，不复制一套侧栏、标题或移动导航。
- 用户主页提供头像、姓名等快捷编辑；设置页保留独立“个人资料”任务页，用于完整资料、账号编号和低频字段管理。
- 内容、收藏、喜欢、历史和草稿仍由个人中心及对应任务页管理；“用户可操作”不是把它搬进设置的理由。

当前真实分类：

| 分类 | 入口 | 范围 |
|---|---|---|
| 账号与安全 | `/settings/security` | 密码、邮箱与权限状态 |
| 隐私 | `/settings/privacy` | 主页可见性、私信权限、关系展示与黑名单列表 |
| 外观与无障碍 | `/settings/appearance` | 主题、减少动态等仅此设备偏好 |
| 登录与会话 | `/settings/session` | 当前会话、其他会话撤销与退出 |

设置总览提供“个人资料”分类，指向 `/settings/profile`；主页快捷编辑与完整资料页共享生成 SDK，不创建两套保存契约。

## 2. 桌面布局

```text
SettingsPage
├─ 返回与页面标题
├─ SettingsLayout
│  ├─ SettingsNavigation（216px，可 sticky）
│  └─ SettingsPanel（640–760px 主任务轴）
│     ├─ OverviewList（仅 `/settings`）
│     └─ SettingsGroup（分类页）
```

- 页面最大宽度约 1024px，侧栏与主轴间距 24px。
- 侧栏和主工作区各自只使用一层 `--lc-surface`；SettingsGroup 之间以 Divider 分隔。
- 禁止把每个字段组再做成独立浮卡，也禁止在主工作区内部继续套 Dashboard 栅格。
- 侧栏激活项使用完整浅玫瑰背景与文字色，不使用粗侧边色条、渐变或阴影。
- Sticky 侧栏不能遮挡锚点、焦点环或产品顶栏。

## 3. 移动与中间宽度

- 760px 及以下进入手机任务栈并隐藏桌面侧栏；不能把四个完整页面压进一个长页面后再用锚点定位。
- 手机端整个 `/settings` 家族是从 `/me` 进入的独立二级全屏设置栈，统一使用 `task` Shell，不显示全局 TopNav 或 BottomNav。
- `/settings` 是栈内总览，局部顶栏返回目标为 `/me`；`/settings/security|privacy|appearance|session` 的局部顶栏返回目标为 `/settings`。
- 浏览器/系统返回优先使用真实历史；无有效站内历史时必须使用上述固定上级，不能把所有设置页都写成 `navigate(-1)` 或统一退回首页。
- 分类列表和设置行的命中区域至少 44px，当前值、说明和 chevron 必须在同一阅读轴内。
- 桌面横向字段在手机转为纵向；验证码动作转为全宽，不能挤压输入框。
- 设置总览和分类任务页底部都只保留 `env(safe-area-inset-bottom)`；不得残留 64px BottomNav 占位。
- 320px 下不得出现横向滚动，说明、错误和动作均允许自然换行。

## 4. SettingsGroup 与设置行

SettingsGroup 负责标题、稳定说明、Section 状态和相邻 Divider。其内部只使用以下语法：

| 类型 | 结构 | 用途 |
|---|---|---|
| 即时偏好行 | 标题/说明 + Selector 或 Switch | 修改后立即生效的设备偏好 |
| 表单任务 | 任务说明 + FormLayout + 单一主动作 | 密码、邮箱等显式保存任务 |
| 进入项 | 整行 Link + 当前状态 + chevron | 进入真实的深层设置页面 |
| 归属说明项 | 标题/说明 + 真实页面链接 | 解释头像、姓名、历史等为什么在对应任务页管理 |
| 会话项 | 后果说明 + 次级按钮 | 登录、退出和设备会话 |
| 危险区 | 后果说明 + destructive 动作 + AlertDialog | 停用、删除等不可逆操作 |

- 退出登录不是删除或停用账号，不进入危险区，也不使用红色外框。
- Switch 只用于切换后立即生效的设置；需要保存的布尔值使用表单控件。
- 密码和邮箱变更若会撤销其他会话，必须在提交动作前说明后果；保存成功后进入重新登录流程，不只显示 Toast 后留在失效页面。
- 隐私三项在服务端支持安全 partial merge 前必须作为一个完整表单提交，不能拆成三个即时保存开关。
- 页面 CSS 不得穿透 Astryx 控件内部重新实现交互，只能编排其外部行和宽度。

## 5. 状态与权限

- 页面标题、分类导航和工作区几何在 loading、empty、error、permission 状态下保持稳定。
- 手机所有状态必须保留同一局部设置顶栏：总览返回 `/me`，分类返回 `/settings`；错误或 Skeleton 不得重新显示产品 BottomNav。
- 字段格式错误使用 FieldStatus；网络、权限和未知服务端失败使用当前任务顶部的 scoped Banner。
- 成功确认使用 Toast，不显示成功 Dialog。
- 游客仍可修改设备外观；账号与隐私区域显示明确登录入口。
- 无写权限时保留可用的其他分类，并在账号组内显示只读说明。
- 只有服务端确实支持的能力才显示当前值、数量或管理入口，不能用设计预览数据填充正式页面。
- 黑名单、会话和通知偏好必须连接生成 SDK；加载、空、失败和保存反馈均为真实状态，不得出现假开关或假数量。

## 6. 扩展门槛

新增设置项必须同时完成：

1. 先按用户自助矩阵判断它究竟属于设置、就地操作、个人内容管理还是契约待补；不能因为接口位于 `/me` 就自动加入设置。
2. 确认真实 SDK 能力、权限、loading/error/empty 状态和保存语义。
3. 在共享设置导航登记真实入口，并为桌面侧栏、手机总览和局部顶栏提供同一名称与键盘焦点。
4. 补充完成态与 Skeleton 几何、320/390/768/1050/1440px、亮暗主题和减少动态检查。
5. 不复制 SettingsLayout、SettingsNavigation 或 SettingsGroup 的视觉实现。

旧 `/settings#settings-appearance`、`#settings-account` 和 `#settings-session` 仅作为迁移入口，分别重定向到真实子路由；新代码不得继续生成 hash 分类链接。未知 `/settings/:section` 应进入标准 404，不能伪装成“功能暂未开放”。
