# LoveCards 发现页面设计基线

> 状态：设计基线 v1.2，适用于 `/explore`。导航与旧链接归一化以 [`NAVIGATION.md`](./NAVIGATION.md) 为准；搜索、卡片和动效沿用各自共享规范。页面视觉蓝图状态以 [`BLUEPRINTS.md`](../registries/BLUEPRINTS.md) 为准。

## 1. 页面职责

发现聚合公开内容，也是原“最新”内容流的归并入口。`/explore` 默认展示按发布时间降序排列的公开内容。动态 `/activity` 是登录后的关注更新，消息由消息中心承担。

搜索 `/search*` 用于已有关键词的查找，话题 `/topic/*` 用于浏览单个话题。三者共享卡片和查询能力，但各自保持清楚的页面身份。游客可浏览发现，互动动作沿用共享登录规则。

## 2. 页面结构与响应式

桌面侧栏和手机顶栏提供“推荐 / 发现”导航。桌面内容工具行提供排序，手机在同一工具行提供排序和单列／多列。手机从品牌图标、频道和搜索的顶栏进入，各操作的触控高度至少 44px。页面保留单一读屏标题“发现”。

工具栏下方直接显示共享信息流。内容、错误和空态均位于页面底色。话题通过搜索结果和内容上的话题链接进入。

桌面在内容区顶部使用全局搜索。手机沿用 `standard` Shell 与频道导航，320px 时排序和首张卡片均可到达。卡片使用共享 `FeedStory` 与 Content Preview。

手机的话题详情 `/topic/:slug` 使用独立任务页。站内进入时返回原搜索结果或发现排序，直达时返回 `/explore`。

搜索综合与范围页遵守 [`SEARCH.md`](./SEARCH.md)。内容结果复用 `FeedCollection` 和卡片表面，状态反馈直接位于页面底色。内容结果、推荐和话题在桌面显示两至五列，手机共用已保存的单列／多列选择。用户、话题结果保留逐条列表语义。

## 3. 排序与地址契约

| 展示选项 | 规范 URL | 服务端排序 | 含义 |
|---|---|---|---|
| 最新发布 | `/explore` | `created_at DESC, id DESC` | 默认，全量公开卡片按发布时间 |
| 最多喜欢 | `/explore?sort=liked` | `goods DESC, id DESC` | 全时累计喜欢数 |
| 讨论最多 | `/explore?sort=discussed` | `comments DESC, id DESC` | 全时累计评论数 |

排序是同一列表的单值选择，首期使用紧凑的原生 `select` 打开平台单选菜单，不赋予 Tab 语义，也不增加自定义菜单状态。选择后 URL、可访问名称和列表数据一起更新；`sort=latest`、空值和未知值以 `replace` 归一到默认地址，保留不冲突的 query 与 hash。浏览器前进、后退和刷新应恢复选项。排序只在服务端完成，先排序再分页；不能只重排已加载的 30 条，也不能使用非分页的 `cards.hot()` 冒充完整列表。前台仅发送 SDK 已声明的 `order_key`，具体映射为 `created_at`、`goods`、`comments`。互动计数变化可能使跨页相对顺序改变；切换排序时重新从第一页加载，不混用不同排序的页。

首期不命名“热门”或“趋势”：这些词需要时间窗、指标和更新时间契约。若服务端没有总数，不显示“共 N 条”。`/explore?q=` 的旧关键词入口归一到 `/search?q=`，避免在发现页维护第二套搜索结果身份。

## 4. 状态与交互

- 发现只请求卡片列表，话题资料在进入话题详情时加载。权限或配置错误使用明确的状态提示。
- 首次加载使用共享信息流 Skeleton；加载更多保留已有卡片，增量失败只影响末尾区域。结束时不再显示加载入口。
- 排序切换取消或忽略过期请求，清空旧排序页；切换期间保留明确的进度反馈，避免旧结果被新响应覆盖。
- 卡片点击、预览开关、路由切换、图片加载与减少动态效果遵守 [`MOTION.md`](./MOTION.md)；卡片打开需立即出现可见反馈。
- 搜索、话题和卡片深链都使用真实链接；预览返回恢复来源 URL（含排序）、滚动位置与焦点。

## 5. 验收

至少核对 320/390/768/1024/1440px、亮暗主题、200% 缩放、键盘、游客与已登录、减少动态效果。覆盖三种排序的服务端次序及分页、切换中的过期响应、首次与增量错误、空态、前进后退和旧链接。验证首屏从工具栏直接进入信息流，并能从搜索和内容链接访问话题详情。
