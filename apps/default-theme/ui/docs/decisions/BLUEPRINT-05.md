# Blueprint 05 · 用户主页与个人中心

## 统一决策（2026-08-22）

用户中心不是一组互相跳转的资产页面，而是一个稳定的主页壳。身份摘要、关系动作、选项卡和卡片流在切换时保持不变；选项卡只替换内容数据，不改变页面结构。只有关系明细这类需要独立数据轴的内容，才进入明确的二级任务页；获赞只作为资料卡里的只读聚合统计，评论只在详情页和讨论线程中出现。

### 页面结构

1. 身份摘要：本人和公开主页共用 `ProfileIdentitySurface`，页面模式只改变权限与动作。手机端顺序固定为封面 → 头像/用户名/UID 身份组 → 简介 → 所在地/性别/年龄 → 主动作 → 统计；桌面端改为头像、资料正文与右侧动作的横向构图，简介和元信息收进中间资料列，不能机械放大手机纵向结构。
   本人主页的头像和用户名是直接编辑触发器，不再要求先进入资料二级页。姓名可原位编辑；头像点击后进入稳定的更换任务 Dialog/移动 Sheet，上传反馈不插入身份头。头像状态见 [`../../blueprints/blueprint-06-avatar-edit.html`](../../blueprints/blueprint-06-avatar-edit.html)。
2. 内容选项卡：本人显示“内容 / 喜欢 / 收藏 / 历史”；他人只显示“内容”。
3. 统一卡片流：四个本人选项卡与公开主页都使用 `ProfileCardFeed`，卡片进入详情、作者身份进入 `/user/{uid}`，两条交互路径互不嵌套。
4. 二级入口：关注和粉丝分别使用 `/me/following`、`/me/followers`。
   本人资料卡不再出现“动态”统计；“内容”及其总数只放在下方 Tab。关注和粉丝统计是明确的 Link，获赞统计是不可交互的只读数字，评论记录不再提供入口。不使用折叠器或插入式面板；二级页保留返回主页和必要的同类切换，移动端不显示产品 BottomNav。

### 同页选项卡契约

- `/me` 是本人“内容”的唯一默认状态；内容总数显示在“内容” Tab 标签中。喜欢、收藏、历史使用 `/me?tab=likes|saved|history`。旧的 `/me?tab=content` 与 `/me/library/{likes|saved|history}` 仅作为兼容入口并渲染同一主页壳。
- 关注和粉丝统计使用真实 Link，获赞只在资料卡显示服务端聚合数字，不提供明细路由。统计数字缺失时显示 `—`，不能用当前页卡片数量或点赞数推算。
- 点击选项卡不得进入另一种页面模板，不得显示重复的“我的空间/资产”侧栏。
- 切换期间保留身份头、选项卡和卡片网格；只将当前卡片流替换为对应骨架、空态、错误态或数据。
- 喜欢、收藏、历史的记录若指向已删除/不可访问卡片，保留不可用占位，不伪造另一套列表卡。

### 关系与互动二级页

- `/me/following` 与 `/me/followers` 使用 Cursor 列表、统一 `AuthorIdentity` 行、首次加载/空态/错误/加载更多状态；桌面保留产品顶栏，手机只保留返回标题栏，不显示 BottomNav。
- 获赞没有独立二级页；只消费 `users.me().stats.received_likes` 作为资料卡只读聚合。不得用 `likes.list()`、`library.list()` 或当前页卡片点赞求和冒充“收到的获赞”。历史 `/me/likes-and-saves` 深链重定向回 `/me`。
- 二级页不复用主页内容 Tab，也不在主页身份头下插入可收起面板。

### 他人主页

- `/user/:uid` 只展示该用户的公开卡片和一个“内容”选项卡；不显示喜欢、收藏、历史或评论入口。
- 关系页 `/user/:uid/followers|following` 是独立关系数据页，可返回主页；关系页不复用内容选项卡。
- 关注与私信动作位于身份摘要，不能阻塞卡片详情或作者链接。
- 本人身份编辑只覆盖头像和当前后端支持的用户名；简介和所在地在完整资料页维护，主页仅作为信息展示；封面保留为统一视觉槽位，拥有正式写入契约后再接入自定义背景。
- 公开主页仅保留“关注 / 发私信”两个主动作；分享、举报、拉黑与解除拉黑统一进入右上角三点菜单。本人主页只保留一个“编辑资料”主按钮，分享与设置进入三点菜单；头像、姓名和简介均可快速编辑。
- 公开身份元信息不展示 IP 地址。IP 属于账号安全与会话管理数据，不能进入公开主页；用户若未开放性别、年龄或所在地，前端直接省略对应项。
- 简介默认最多展示四行，仅在内容确实溢出时显示“展开”；展开后提供“收起”，按钮必须可聚焦并暴露 `aria-expanded`。
- 本人和他人资料为空时，都在简介与元信息各自的位置保留克制的未设置提示，确保两类主页结构不跳变；本人简介提示可点击编辑，他人提示只读。年龄由服务端生日字段计算展示，不能显示完整生日或虚构年龄。
- 头像文件错误使用 FileStatus，网络/权限/登录错误使用任务内 scoped Banner，成功关闭任务并 Toast；主页身份头高度始终稳定。
- `/me` 保留头像、姓名等高频就地编辑；完整资料使用独立的 `/settings/profile` 任务页，历史 `/me/edit` 链接重定向至该页面。移动端仍通过统一设置任务页进入，避免在主页堆叠低频字段。

### 响应式与骨架

- 桌面使用单一内容画布，不保留用户中心右侧栏；卡片流使用与首页相同的 Compact 网格。
- 手机端页面、身份头、选项卡和卡片网格全宽贴合画布；网格保留内边距和安全区，不产生横向滚动或卡片裁切。
- `ProfileSkeleton` 与 `PublicProfileSkeleton` 必须包含身份、选项卡和与主页 `FeedSkeleton` 同源的卡片骨架；媒体、图集、文字/讨论卡按最终 Pattern 保持对应比例，加载完成时不跳高。
- 选项卡切换的 loading、empty、404、403、network error 均在原卡片流位置呈现，不能用与最终页面无关的全屏 spinner 替代。
- 信息流卡片不展示话题标签；话题只在详情页作为上下文入口出现。

### 数据边界

公开卡片首期只通过 SDK `cards.listPublicByUser(uid, { page, list_rows })` 读取，前端使用 `CardResource` 与 `normalizeSdkCard`；不以 `user_id` 拼接主页，不用 number 或展示昵称替代真实 UID。
