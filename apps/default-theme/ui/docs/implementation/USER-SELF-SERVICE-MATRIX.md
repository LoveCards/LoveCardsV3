# 用户自助能力与设置归属矩阵

> 状态：2026-08-25 审计基线。本文是默认主题判断“某项能力是否应进入设置”的事实表；接口事实以生成 SDK 为准，页面结构以 [`SETTINGS.md`](../specifications/SETTINGS.md) 与 Blueprint 08 为准。

## 1. 判定边界

用户能够执行的动作不等于设置项。默认主题按任务归属分为四类：

1. **设置**：持续生效的账号、隐私、会话或设备偏好，进入 `/settings*`。
2. **就地身份与关系操作**：只有在当前对象上下文中才有意义，留在本人或他人主页。
3. **个人内容与数据管理**：收藏、历史、草稿、上传和内容编辑，留在对应内容页面。
4. **契约待补**：产品方向成立，但当前普通用户 SDK 不支持；只保留设计边界，不进入正式导航，也不显示假开关、假数量或假成功。

## 2. 当前真实覆盖

| 用户能力 | 数据来源 | 当前用户端入口 | 设计归属 | 结论 |
|---|---|---|---|---|
| 用户名、头像 | `users.me/updateMe`、`files.upload` | `/me` 头像与姓名就地编辑 | 个人资料 | 已完成；设置总览只说明入口，不复制编辑表单 |
| 密码 | `users.updatePassword` | `/settings/security` | 账号与安全 | 已完成；必须说明更新后其他会话失效并需要重新登录 |
| 邮箱与验证码 | `users.emailCaptcha/updateEmail` | `/settings/security` | 账号与安全 | 已接入；SDK 仍需把验证码响应和必填字段强类型化 |
| 主页可见范围 | `safety.preferences/preferences_update` | `/settings/privacy` | 隐私 | 已完成 |
| 私信接收范围 | 同上 | `/settings/privacy` | 隐私 | 已完成 |
| 关注与粉丝列表展示 | 同上 | `/settings/privacy` | 隐私 | 已完成 |
| 主题模式 | 本机 `localStorage` | `/settings/appearance`、顶栏快捷动作 | 外观与无障碍 | 已完成；明确“仅此设备” |
| 减少动态效果 | 本机 `localStorage` | `/settings/appearance` | 外观与无障碍 | 已完成；明确“仅此设备” |
| 退出当前账号 | `session.logout` | `/settings/session` | 登录与会话 | 已完成；不能描述成多设备管理 |
| 拉黑/解除拉黑 | `safety.block/unblock` | `/user/:handle` | 用户关系安全操作 | 动作已完成；缺少设置内的黑名单列表闭环 |
| 账号恢复 | `session.recovery_request/recovery_reset` | `/auth/recovery` | 登录恢复流程 | 已完成；不重复放入已登录设置表单 |
| 清空浏览历史 | `library.history/history_clear` | `/me?tab=history` | 个人数据管理 | 已完成；设置总览可以说明归属，但不复制危险动作 |
| 收藏、喜欢、草稿、内容与媒体管理 | `library/likes/drafts/cards/files/tags` | `/me`、`/drafts`、详情与发布页 | 个人内容管理 | 不属于设置；不得为了“设置齐全”搬入设置侧栏 |
| 通知已读状态 | `notifications.read/readAll` | `/inbox*` | 通知列表状态 | 不是通知偏好 |

## 3. 已确认的契约缺口

| 规划能力 | 当前缺口 | 进入正式设置的门槛 | 优先级 |
|---|---|---|---|
| 黑名单列表 | 已有生成 SDK | `/settings/privacy` 使用 `safety.listBlocked` 不透明游标、搜索和 `unblock` | 已接入 |
| 个人简介、所在地 | 已有生成 SDK | `/me` 就地编辑，分别限制 160/64 Unicode 码点，空值保存为 null | 已接入 |
| 登录设备与其他会话 | 已有生成 SDK | `/settings/session` 展示真实会话并支持撤销 | 已接入 |
| 通知偏好 | 已有生成 SDK | `/settings/notifications` 使用真实通知类型，system.* 锁定 | 已接入 |
| 账号停用/注销、数据导出 | 没有普通用户契约 | 专用自助接口、再次验证、冷静期/撤销、内容归属和审计语义；不得复用管理员删除 | P2 |
| 跨设备外观、字号、语言、时区 | 当前只有本地主题与减少动态 | 用户偏好读取/更新契约；未提供前保持“仅此设备” | P3 |
| 手机号、2FA、Passkey、恢复代码 | 普通用户无对应接口与领域能力 | 完整认证策略、验证流程和恢复语义 | Future |
| 会话静音、归档、消息请求偏好 | 消息 SDK 没有对应操作 | 先定义消息请求和会话偏好契约 | Future |

## 4. 禁止误导

- Blueprint 和正式页面不得把手机号、双重验证、Passkey、恢复代码、通知渠道、个性化推荐、文字大小、账号停用或黑名单数量画成当前可操作能力。
- 管理端 API 不得被当成普通用户端能力；尤其不能复用管理员会话撤销、用户删除或主题配置接口。
- `notifications.read/readAll` 只代表已读状态，不代表用户选择接收哪些通知。
- `theme.publicConfig` 是站点主题配置，不是个人外观偏好。
- 无列表接口时不得通过本地记忆、当前页关系或逐用户请求拼出黑名单。
- 隐私更新当前必须完整提交三个字段，直到服务端支持安全的 partial merge；否则单字段保存可能把其他设置恢复默认值。

## 5. 新能力进入设置的门槛

任何新增设置必须同时具备：用户任务归属、普通用户 SDK 强类型契约、读取/保存/失败语义、权限和隐私边界、桌面与移动入口、加载/空/错误/保存状态，以及与现有页面不重复的明确理由。未满足时只登记在本矩阵，不进入导航。
