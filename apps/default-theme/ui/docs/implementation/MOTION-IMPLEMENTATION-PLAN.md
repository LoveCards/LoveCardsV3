# 默认主题动效开发方案

> 状态：第 2–8 节记录 2026-11-18 的 v1 施工及验收快照；第 9 节是 2026-11-19 冻结的下一阶段方案，实施状态见第 10 节。设计依据为 [`MOTION.md`](../specifications/MOTION.md)、[`DIALOGS.md`](../specifications/DIALOGS.md) 与 [`NAVIGATION.md`](../specifications/NAVIGATION.md)。本文记录实现顺序、影响范围和验收门槛，历史快照不覆盖新规范。

## 1. 基线与边界

| 当前行为 | 代码入口 | 施工判断 |
|---|---|---|
| Astryx Dialog 使用约 550ms 定向位移 + 缩放入场；`isOpen=false` 时立即 `close()` | `@astryxdesign/core@0.3.0` 的 `Dialog`、`AlertDialog` | 必须通过现有组件的 `ref`、受控 `isOpen` 和 LoveCards 样式处理；不复制原生模态、焦点陷阱或滚动锁 |
| `FormDialog`、`ConfirmActionDialog`、`AuthPromptDialog` 是共享入口 | `src/ui/interaction.jsx` | 在这三个入口复用一个关闭期状态机；移动 Sheet 由 FormDialog 的响应式形态决定 |
| 搜索和媒体查看器直接使用全屏 Astryx Dialog | `src/components/HeaderSearch.jsx`、`src/features/media/MediaGallery.jsx` | 关闭其通用位移/缩放入场；不纳入标准 Dialog 退场状态机 |
| 路由使用 `Routes` + 顶层 `Suspense` | `src/app/router.jsx` | 普通路由保持即时切换；处理懒加载时回退内容可能替换页面壳的问题 |
| 个人主页四个 Tab 在同一 `/me` 路由用 query 切内容 | `src/pages/profile/ProfileContentTabs.jsx`、`ProfilePage.jsx` | 仅此处实现可移动指示器与真正的同页 Tab 键盘语义；内容保持原位 |
| 消息中心两项跨 `/messages`、`/inbox` 路由 | `src/pages/community/MessageCenterTabs.jsx` | 保留 Link 与 `aria-current`，选中标记即时落位；不为动效重建路由壳 |

施工不修改 SDK、后端契约、业务请求或主题发布格式。共享 `motion` Token 映射后删除被替代的局部动效声明；不引入 Framer Motion 等新运行依赖。

## 2. 切片 A：Token 与减少动态效果

1. 在 `src/styles/tokens.css` 映射设计 frontmatter 的 `press/state/control/matchedExpand/dialogLift/sheetLift`；复用已有 `--lc-ease`，不出现第二套缓动值。
2. 在 `src/main.jsx` 的 React 渲染前同步读取已保存的站内减少动态效果设置，使首帧使用正确的 `data-reduce-motion`；`AppProviders` 继续拥有设置状态和后续变更。系统偏好仍交给 CSS `prefers-reduced-motion`。
3. 共享 CSS 仅对本次迁移的 Dialog、Tab 和路由反馈使用新 Token。其他组件的零散时长按后续实际改动逐步迁移，避免纯格式化式全站替换。

**退出条件：**亮/暗主题、首次加载和设置切换都取到同一 Token；站内或系统减动任一开启时首帧无位移、缩放和 Skeleton 闪烁。

## 3. 切片 B：共享 Dialog 进出场

### B1. 验证 Astryx 开放边界

先用一页最小浏览器样例确认 `Dialog` 和 `AlertDialog` 的 `ref` 确实指向原生 `<dialog>`，产品类选择器可覆盖其 StyleX 入场 keyframe，`::backdrop` 可单独淡化；记录 320/390px Sheet、桌面 Dialog 的 `getComputedStyle()` 与实际焦点/滚动锁。若 CSS 覆盖不稳定，停止此切片并调整共享适配方案，不在页面加 `!important` 补丁。

### B2. 一个关闭期状态机

在 `src/ui/` 增加只负责动效时序的共享 hook，由现有三个 Dialog adapter 使用。它维护 `closed/opening/open/closing` 与本次动画的代号：

- 打开时把 `isOpen=true` 传给 Astryx，保持其 `showModal()`、初始焦点、Escape、Backdrop 规则和滚动锁。
- 用户请求关闭时立即且仅一次向外部 `onOpenChange(false)` 提交请求；以父组件确认后的 `isOpen=false` 作为进入 `closing` 的依据，不能在父组件拒绝关闭时自行隐藏。Surface 退场完成前仍向 Astryx 传 `isOpen=true`；完成后才传 `false`，让 Astryx 执行 `close()`、释放滚动锁和焦点恢复。关闭期阻止重复提交与重复关闭。
- 父组件直接把 `isOpen` 改为 `false` 时，若 adapter 仍挂载，也进入同一退场。关闭期锁定最后一次完整的标题、说明、Body 和 Footer，避免调用方先清空状态造成文案跳变；下一次打开必须使用新内容。
- 以原生动画完成/取消事件和当前动画代号收口，不用任意延时计时器。反向打开时取消旧退场；组件卸载、路由离开或减动生效时立即结束对应阶段并清理。
- 保存中原有关闭限制优先。表单操作成功后若立即导航，遵守规范直接清理，不为了退场延迟业务导航。

在 `src/styles/interactions.css` 对共享 adapter 的 Dialog 类定义入场、退场和 Backdrop 轨迹；桌面位移取 `dialogLift`，移动 Form Sheet 取 `sheetLift`，均只用 `transform` 与 `opacity`。覆盖 Astryx 默认缩放和长时入场，并移除默认 Backdrop 的静态模糊，使遮罩保持中性。全屏搜索和媒体查看器仅关闭 Astryx 的通用入场动画。

### B3. 调用方收口

逐个处理“关闭时立即卸载”与“关闭时清空内容”的入口：`ProfilePage` 的清空历史确认、`DetailPage` 的举报弹窗、`useHumanVerification` 的图片验证，以及关闭时清空 `authPromptAction`、`pendingPublishType`、上传文件和举报表单的调用方。能保持 adapter 挂载的入口使用受控 `isOpen`；路由立即离开或任务对象本身消失时走明确的即时清理路径。不得为了动画保留已失效的可提交业务对象。

**退出条件：**关闭期间原生模态仍阻断背景、焦点不提前回到页面；连点、快速反向、Escape、软键盘、路由离开和减动切换后无残留 Backdrop、滚动锁或旧文案。如果现有 Astryx 版本无法稳定提供这些条件，按规范即时关闭该路径，并记录该路径与原因；不得伪造退场。

## 4. 切片 C：个人主页 Tab

1. 在 `ProfileContentTabs.jsx` 的本人四项中保留真实 URL，增加 `tablist/tab/tabpanel` 关联、`aria-selected` 和 roving `tabIndex`。方向键与 Home/End 只移动焦点，Enter/Space 激活；Ctrl/Cmd/中键打开新标签页仍遵守链接行为。公开主页的单一“内容”结构锚点不启用四项交互。
2. 在 `ProfilePage.jsx` 给现有 Feed 内容区稳定的面板 ID 与名称；切换 query 后只替换内容，不重建身份头、Tab 栏或 Feed gutter。加载、空、错误、权限继续占用同一区域。
3. 用一个 `aria-hidden` 指示器替换每项独立伪元素。仅在当前 Tab 栏内测量位置和宽度；通过 `transform` 平移/缩放，不动画布局宽度。字体、容器尺寸与数量变化时重新定位，首次渲染直接落位；标签栏滚动仍使用 `behavior:'auto'`。
4. 不实现内容区左右滑动手势或整屏滑入。内容默认即时替换；若浏览器实测数据就绪时短淡化有清楚收益，再在 Feed 区局部启用 `motion.state`，且减动时关闭。

消息中心保持现有 Link 结构和即时选中标记，只统一颜色状态 Token；不为跨路由“移动下划线”抽出常驻父布局。

**退出条件：**点击、键盘、前进后退和窄屏横向滚动一致；指示器可中断且不漂移；内容横滑不误切 Tab，媒体手势与浏览器返回不被拦截。

## 5. 切片 D：普通路由与卡片详情

普通路由不增加转场组件。检查 `router.jsx` 的顶层 `Suspense`：懒加载期间应使用与目标路由一致的页面壳和局部 Loading，不能短暂丢失顶栏、BottomNav 或任务页模式。只调整 fallback 与路由模式映射，不重构全部页面壳所有权。浏览器返回继续按既有导航规范恢复 URL、焦点与滚动。

卡片到详情的 `matchedExpand` 单独评估：只有来源卡片仍在 DOM、媒体与详情可稳定识别同一资源、且浏览器支持可靠转换时，才做 300ms 的渐进增强。只给同一媒体/作者建立匹配标识；修改点击拦截时保留修饰键、新窗口和正常历史。来源不存在、数据加载、返回目标变化或减动时立即切换。该评估不阻塞 Dialog 与 Tab 切片交付。

**退出条件：**普通导航无整屏飞入、双层页面、空白帧或错误 Shell；匹配转换失败时有即时且可用的回退，不影响深链直达。

## 6. 切片 E：其余共享组件核对

按 `MOTION.md` 的 Press、State、Control 语义，核对现有 Button/Like/Save、菜单/Popover、Toast、媒体控制和 Skeleton 的实际计算样式。仅把不符合规范的共享规则收敛到 Token；保留 Astryx 已正确处理的焦点、状态与减动行为。Astryx Toast 容器当前过渡 `grid-template-rows` 与 `padding`，属于布局属性，需在浏览器中确认影响后于共享层取消该过渡或选择不动画容器，Toast 本体仍可按 Token 淡入淡出。不得为各页面各造一个 Toast 或 Popover 动效。

**退出条件：**本次涉及的共享组件没有无名时长、布局属性转场或减动遗漏；Skeleton 停止闪烁后仍可识别为加载状态。

## 9. 下一阶段：阅读预览层与整站动效基线（设计已冻结，代码未实施）

参考观察：2026-11-19 在[小红书 Web 信息流](https://www.xiaohongshu.com/explore)看到卡片打开后 URL 指向内容，原列表仍留在页面，桌面覆盖层和窄屏全屏阅读层承接内容；未量测其动画时长或轨迹。LoveCards 的“卡片匹配放大”是本项目的设计选择，不宣称为小红书原样实现。模态语义依据 [W3C Dialog 模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)；减动依据 [W3C 动画交互说明](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions)；匹配转场的唯一命名、焦点和回退约束参考 [Chrome 同文档转场指南](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/same-document-transitions)。

### 9.1 现状差距

| 普通路由 | URL 与 Shell 切换已稳定，内容整体即时替换 | 仅新内容区短淡入/微位移，返回已有视图及减动时跳过 |
| 菜单与即时动作 | 目前依赖各自组件默认反馈，未统一审阅 | 共享锚定浮层与 Like/Save/Follow 状态轨迹、失败回滚和减动 |
| 浏览器与移动验收 | v1 主要覆盖 Dialog、Tab 的部分场景 | 加入 Card 预览、历史、深链、视频、软键盘、离屏来源和快速反向 |
| 登录入口 | `AuthPromptDialog` 只提示前往 `/auth/login`；完整表单仅在 `AuthPage` | 公开内容里的账号专属动作可在同一模态层完成登录；完整登录、注册和恢复页面保留 |
| 发布入口 | `ComposePage` 已覆盖随笔/媒体、草稿、编辑、验证与脏状态 | 保留唯一 `/compose` 工作区；信息流“写随笔”只增加指向该路由的入口，新建默认随笔 |

### 9.2 实施切片与所有权

1. **内容复用。** 从现有 `DetailPage` 提取可嵌入的 Card 阅读内容和评论线程；保留一个数据/权限状态源。独立页面与预览层仅各自负责外壳、滚动容器、页面标题和关闭/返回。`FeedStory` 继续提供真实 Link，不把整卡包成链接，也不复制详情业务组件。
2. **路由背景状态。** 在 `router.jsx` 的 `/post/:id` 路由边界保存已挂载的来源 location、筛选、滚动与触发器身份；普通激活 push 到 Card URL 并呈现预览层。直接深链、刷新与新标签走独立详情。关闭、Back、Forward 和“查看完整详情”按导航规范处理；仅内部历史状态可承载来源，URL 不新增动画参数。先验证路由库在返回/前进时可恢复相同表面，再迁移所有 Card 入口。
3. **共享阅读表面。** 增加一个 `CardPreviewSurface` Pattern，复用现有模态语义或其薄适配，统一背景 inert、滚动锁、Escape、焦点与最上层管理。桌面媒体/阅读布局和手机全屏阅读布局分别验收；不直接套短 FormDialog Footer。搜索、个人主页、收藏、历史、话题与通知 Card 入口逐个接入，非 Card 资源仍用原表面。
4. **连续展开。** 在唯一共享层实现当前 Card 的匹配名与动画生命周期，复用 `motion.matchedExpand`、`motion.state` 和 `motion.contentLift`。先实现无匹配时可靠淡入，再增加同文档 View Transition；图片、文字、图集封面、视频海报分别验证。动画准备不得等待网络；资源变化、来源离屏、快速反向和减少动态效果必须安全取消。
5. **其余状态。** 对普通路由内容区、共享 Menu/Popover、Like/Save/Follow、搜索建议、通知列表和 Skeleton 完成态逐项收敛到现有 Token；仅新增 `contentLift` 这一复用位移 Token。保留 v1 Toast 退出依赖的已知限制，不用页面级覆盖掩盖。不要为每个页面添加 keyframe 或新的动画依赖。
6. **情境登录。** 从 `AuthPage` 中只抽出账号密码登录所需的字段、校验与提交状态，页面、情境 Dialog/Sheet 与预览层内联表单复用；注册、恢复、游客和私有路由守卫保持原页面流程。现有 `AuthPromptDialog` 升级为可提交的 Form Dialog / Sheet，不创建第二个认证 service。预览层触发登录时只在阅读区展开同一表单，不再创建模态层或滚动锁。登录成功更新会话并恢复原位置，不自动重放写操作。路由离开直接清理，不制造同 URL 历史项。
7. **发布入口。** 保留 `/compose` 作为唯一编辑任务。若增加信息流“写随笔”，只加真实 Link，沿用已有随笔默认值，不复制字段、发布请求、草稿、脏状态和验证。该入口与全局发布、手机发布、草稿恢复共同验收。快捷发布弹窗不进入本阶段。

每个切片须在 dev 工作树以独立、可回退的变更交付。先完成内容/历史语义与无动画回退，再启用匹配增强；缺少稳定来源身份时保持完整详情可用。设计蓝图需要补一页覆盖桌面媒体/文字、手机、加载/错误、展开与减动状态；注册表的 `CardPreviewSurface` 在蓝图和浏览器验收完成前保持 `needs-blueprint`。

### 9.4 功能收益与代码熵复审结论

| 方案 | 用户收益 | 新增状态与耦合 | 结论 |
|---|---|---|---|
| Card 内容预览层 + 完整详情 | 浏览列表时阅读、互动后可回原位置；直达仍有稳定页面 | 需要一个路由背景状态、阅读外壳与共享详情内容；历史/焦点测试较重 | **保留**；先保证无动画正确，再启用匹配展开 |
| 情境账号密码登录 + 独立认证页 | 公开内容中的互动不必离开原语境 | 抽一个共享登录字段/提交模型；普通 Dialog/Sheet 复用现有适配层；预览层内联表单不增加模态 | **保留并收窄**；注册、恢复、游客、守卫仍在独立页 |
| 桌面快捷随笔弹窗 + 完整发布页 | 少一次页面切换 | 需再维护输入、脏状态、草稿交接、人机验证、权限和失败恢复；`ComposePage` 已覆盖完整任务 | **不纳入当前基线**；局部“写随笔”链接到 `/compose` |
| 所有路由统一整屏转场 | 视觉变化明显 | 跨 Shell、异步资源和浏览器历史均需额外状态 | **不采用**；只让目标内容区入场 |
| 每个列表卡滚动入场/弹跳 | 短时装饰感 | 长列表需要逐项可见性状态，滚动性能和减动分支增多 | **不采用**；只动画被激活的资源与局部状态 |

施工门槛是“新增一个共享抽象必须消除已存在的重复或危险耦合”。第一阶段只实现 Card 预览的语义/历史和现有登录提示的表单化；动效再作为共享层的渐进增强。若路由背景状态不能在 Back/Forward、刷新和来源卸载条件下保持一致，先回退该入口到独立详情，不以页面级补丁掩盖。若登录表单抽取迫使注册、恢复或人机验证复制状态机，则缩小复用边界到账号密码字段和提交用例。快捷发布弹窗只有在真实使用证据证明它显著优于完整页，且无需新增草稿协议和第二套提交状态机时，才重新进入设计评估。
